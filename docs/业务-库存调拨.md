# 业务说明 — 库存调拨

> 面向业务人员。技术口径与契约见 docs/M3拆解-库存与成本.md（§1.6.5 调拨成本守恒）与代码（领域 `domain/transfer`）。
> 任务编号 M3-T04。

## 1. 调拨解决什么问题

企业常有多个仓库（如总仓、门店仓、车间线边仓）。同一批货物常常需要**从一个仓搬到另一个仓**，比如：

- 总仓向门店仓补货；
- 把车间用不完的余料退回原料仓；
- 仓库整合、库位调整时把货物集中。

调拨单就是记录「**哪些商品、多少数量，从哪个仓调到哪个仓**」的业务单据。它保证：货物离开调出仓、进入调入仓这两件事**要么都发生、要么都不发生**（同一笔事务原子完成），账面永远对得上实物。

## 2. 调拨单的生命周期

调拨单和系统里其他单据一样走统一状态机：

```
草稿(DRAFT) → 审核(APPROVED) → 执行中(EXECUTING) → 完成(COMPLETED)
   ↓
作废(CANCELLED，仅草稿可作废)
```

- **草稿**：录入调出仓、调入仓、调拨商品与数量。此时还没动任何库存，可以改、可以作废。
- **审核**：确认调拨内容无误，业务内容自此锁定。
- **过账（一步推进到完成）**：系统真正移动库存——调出仓扣减、调入仓增加，并生成两笔库存流水。完成后不可修改，只能**冲销**（开一张反向调拨单纠正，红字调拨单统一在后续版本落地）。

> 单据号自动生成，格式 `TR-年月-序号`，如 `TR-202606-0001`。

### 关键规则

- **调出仓与调入仓不能相同**：同仓调拨没有意义（货物没真正移动），系统直接拒绝。
- **调拨数量必须大于 0**。
- **调出仓库存不足时拒绝过账**（默认禁止负库存）：账面有多少才能调多少。
- 调出仓、调入仓、商品必须都是**启用状态**的档案。

## 3. 为什么成本必须守恒

这是调拨在财务上最重要的一点。

库存不只有「数量」，还有「金额」（这批货值多少钱，按移动加权成本核算）。调拨**只是把货物从一个仓搬到另一个仓，并没有创造或消灭任何价值**。所以：

> **调出仓减少的金额，必须严格等于调入仓增加的金额。**

系统的做法（每行调拨拆成「调出腿 + 调入腿」两笔流水，同一笔事务完成）：

1. **调出腿**：从调出仓按该仓**当前的移动加权成本**出库，算出这批货带走多少钱；
2. **调入腿**：进入调入仓时，**直接用调出腿带走的那笔金额入账**，而不是重新估价。

这样整个企业的库存总价值在调拨前后**分毫不差**，不会因为搬一次货就凭空多出或少掉库存价值。

### 小例子

总仓现有某商品 100 个、账面金额 1000.00 元（加权单价 10.00 元/个）；门店仓现有 50 个、金额 400.00 元（加权单价 8.00 元/个）。

现在从总仓调 **70 个**到门店仓：

| | 调拨前 | 调拨后 | 变动 |
|---|---|---|---|
| 总仓数量 | 100 | 30 | −70 |
| 总仓金额 | 1000.00 | 300.00 | **−700.00** |
| 门店仓数量 | 50 | 120 | +70 |
| 门店仓金额 | 400.00 | 1100.00 | **+700.00** |

- 调出腿：70 个 × 总仓加权单价 10.00 = **700.00 元**离开总仓；
- 调入腿：这 **700.00 元**原样进入门店仓（**不是**按门店仓原来的 8.00 元，也不是重新估价）；
- 守恒检验：总仓减少 700.00 == 门店仓增加 700.00 ✓。

> 注意：调拨后门店仓的加权单价会从 8.00 变成 1100.00 ÷ 120 ≈ 9.166667 元/个——这是把两批不同成本的货物混在一起后的正常加权结果，不是错误。

## 4. 与库存台账的关系

调拨单本身不直接写库存表。过账时，它通过库存的**唯一写入口**生成两笔库存流水：

- 调出仓一笔 `调拨出（TRANSFER_OUT）`（数量为负）；
- 调入仓一笔 `调拨入（TRANSFER_IN）`（数量为正）。

这两笔流水进入库存台账，和采购入库、销售出库、盘点盈亏等流水一样，受同一套对账恒等式约束：

> 每个仓每个商品：所有流水的数量之和 = 当前结存数量；所有流水的金额之和 = 当前结存金额。

调拨流水可以在库存流水查询（按仓库 × 商品）里看到，每笔都带来源单据号（调拨单号），全程可追溯（CLAUDE.md 原则 3 可审计）。

## 5. 典型流程

1. 仓管在系统里新建调拨单：选调出仓、调入仓，加几行商品和数量 → 保存为草稿（`TR-` 单据号自动生成）。
2. 核对无误后**审核**。
3. **过账**：系统校验调出仓库存够不够，够则一次性完成「调出扣减 + 调入增加」，单据变为完成。
4. 之后在库存余额/流水里能看到两个仓的变化，金额守恒、对账平。

也可以通过聊天让 Agent 协助：

- 「把一号仓的不锈钢板调 100 个到二号仓」→ Agent 调 `create_transfer` 工具（高风险，系统会弹确认卡片，确认后建为草稿，再走审核过账）；
- 「TR-202606-0001 这张调拨单到哪一步了」→ Agent 调 `query_transfer` 查询。

> 权限：调拨相关操作需要 `inventory:transfer` 权限点（授予 ADMIN / BOSS / 仓管 WAREHOUSE 角色）。
