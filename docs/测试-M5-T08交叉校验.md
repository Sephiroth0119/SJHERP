## 2. 新增规则（12–16）口径与严重度
| 规则 | ConsistencyCheckType | 严重度 | 比对口径 |
|---|---|---|---|
| 12 | `MATERIAL_ISSUE_COST` | ERROR | COMPLETED 领料行 issued_cost = −Σ PRODUCTION_ISSUE.total_cost（src_doc_no=MI 单号, src_line_no=行号）；COMPLETED 退料行 returned_cost = Σ PRODUCTION_RETURN.total_cost（src_doc_no=MR 单号, src_line_no=行号）；缺流水(null)亦 ERROR |
| 13 | `PRODUCTION_INBOUND_COST` | ERROR | COMPLETED 报工 inbound_cost = Σ PRODUCTION_IN.total_cost（src_doc_no=PR 单号）；缺流水 ERROR |
| 14 | `WORK_ORDER_MATERIAL_CONSERVATION` | ERROR/WARN | 每工单 Σinbound_cost vs Σissued_net(=Σissued−Σreturned，退料经 MR→MI→WO 归属)：diff=Σinbound−Σissued_net **>0.01（1 分容差）→ERROR**（料虚增 R1 破）；0<diff≤0.01 入库 round2×qty 舍入残差不报；<0→WARN（在产 WIP 料）；=0→不报。容差仅加 ERROR 侧（评审 P2-2，防舍入残差误报阻塞关账）|
| 15 | `WORK_ORDER_COMPLETED_QTY` | ERROR | work_order.completed_qty = Σ COMPLETED 报工 completed_qty |
| 16 | `COST_SETTLEMENT_ADJUST` | ERROR | max(completed_cost−material_cost−already_transferred, 0) = Σ COST_ADJUST.total_cost（src_doc_no=PC 单号, src_line_no=结转行号） |

## 3. 单测清单（ConsistencyCheckServiceTest，22 例）
- 规则12 领料：相符不报 / 金额不符 ERROR / 缺流水(null) ERROR（含标度差 800↔800.00 视相等）。
- 规则12 退料：相符 / 不符 ERROR / 缺流水 ERROR。
- 规则13：相符 / 不符 ERROR / 缺流水 ERROR。
- 规则14：相等不报 / Σinbound>Σissued_net → ERROR（料虚增）/ Σinbound<Σissued_net → WARN（在产）/ 标度差视相等 / **超额恰 1 分舍入残差不报（修复2 P2-2）/ 超额 2 分超容差 ERROR / 差额恰 0 守恒不报**。
- 规则15：相符 / 不符 ERROR / 均 0 不报。
- 规则16：相符 / 不符 ERROR / 增量≤0 截 0 且无流水不报 / 增量截 0 却有 COST_ADJUST 流水 ERROR。
> 比对方法均为 `static` 纯函数（入参 DAO 聚合行 record），无 IO。`check()` 编排测试（全平 / 含多类 break）已**显式 stub 规则 8–16 全部 DAO 方法**（修复5 P3-2，不再依赖 Mockito 空集默认）；含多类 break 用例经规则14 注入一条生产链 ERROR 验证新规则接线生效（3 ERROR + 1 WARN）。

## 4. 端到端集成测试（ProductionFullChainConsistencyIntegrationTest，@Tag("integration-db")，CI 跑）
链路：PURCHASE_IN 预置子件库存 → 建工单 → 下达 → 开工 → 领料过账 → 报工完工过账 → 月末成本结转过账。断言：
1. **`ConsistencyCheckService.check()` 返回 0 ERROR break**（核心里程碑出口硬条件，含本批规则 12–16）；
2. 规则12：领料 issuedCost = −Σ PRODUCTION_ISSUE（`isEqualByComparingTo`）；
3. 规则13：报工 inboundCost = Σ PRODUCTION_IN；
4. 规则14：Σ完工入库料 = Σ净领料（无退料时相等，守恒）；
5. 规则15：工单 completed_qty = Σ报工 completed_qty；
6. 规则16：工费增量 = Σ COST_ADJUST（>0）。
> 不重蹈 M5-T05 P0 教训（只断数量不断金额）——逐条 DB 旁证断到金额相等。
> **病态路径用例（@Order(2)，修复4 P2-1）**：建工单 → 领料过账 → 报工**全部完工入库**（料 100% 结转）→ **退料过账**（退料-after-完工）→ `check()` 应含 **1 条 `WORK_ORDER_MATERIAL_CONSERVATION` ERROR**（key=工单号），验证修复1 净额无法回溯抵减已入库时规则14 纵深防御生效。`@TestMethodOrder` 保证干净链路用例（@Order(1) 断全库 0 ERROR）先跑，本病态 ERROR 不污染其全库断言（共享容器跨测试不清库）。

## 8. 交叉校验发现与裁定（详见设计文档 §6.3）
- **P2-A（R1 缺陷）→【用户裁定 2026-06-28：方案① 改净额，已修】**：退料不冲减完工料基 → 报工后退料致 Σinbound>Σissued_net 违 R1。本批将 `ProductionReportService.sumIssuedCostForWorkOrder` 重命名为 **`sumNetIssuedCostForWorkOrder`** 并改为 **Σ领料 issuedCost − Σ退料 returnedCost**（净额，新注入 `MaterialReturnRepository`，退料经 `material_issue_doc_no`→领料单→工单归属反查），补「报工前退料净额减退料 / 报工后退料致增量≤0 拒过账 / 无退料净额==毛额回归」三单测使 R1 恒成立；规则14 ERROR 保留为纵深防御（事后探测 + 阻塞关账，「全部完工后再退料」无法回溯抵减已入库，由集成测病态用例验证）。
- **P2-B（科目错配）→【用户裁定 2026-06-28：登记 ADR 后续修】**：生产料归集贷 1403、M3 采购入库借 1405 → 1403 长期负余额、存货科目分类失真（总额仍 tie-out）。本批**不改科目口径**（触及 M3 采购凭证模板，超出 T08 范围），起 `docs/ADR-003-存货科目口径统一.md` 草案 + 登记技术债 R-T08-2；规则17 账证勾稽随此裁定一并延后（避免科目错配未修前持续误报）。
- P3：双锚点口径（R-T06-8）、生产单据红冲缺口（M5 后续）。
