# ADR：生产成本核算规则（M5-T06）

## 2026-07-12 存货分类与净领料补充决策（优先于下文旧口径）

本补充决策落实 [ADR-003](ADR-003-存货科目口径统一.md)，是生产成本相关科目与材料成本的最新单一真源：

1. 材料成本口径改为已过账领料减已过账退料；成本结算行分别冻结原材料净额、商品类材料净额及其总额。
2. 原材料净额：借 5001、贷 1403；商品类材料净额：借 5001、贷 1405；完工结转仍为借 1405、贷 5001。
3. 商品分类由档案固定维护：`RAW_MATERIAL` 对应 1403，其余三类对应 1405。存在库存流水后不得修改分类。
4. 规则17将 `PRODUCTION_IN + COST_ADJUST` 与生产成本结算凭证 1405 净借方按工单勾稽；差额超过 0.01 元为 ERROR。

历史章节中“所有材料固定贷 1403”或“材料等于领料毛额”的描述，仅适用于 ADR-003 落地前的历史背景，不再作为现行实现依据。

> 状态：已采纳（2026-06-23）。本文是 SJHERP 生产成本核算的**会计政策单一真源**，约束 M5-T06 及后续成本相关开发。实现拆解见 docs/M5拆解-生产成本归集.md。
> 决策人：用户（WIP 计价法拍板"约当产量法"）；其余 D1–D9 由方案推荐、本 ADR 采纳。

## 1. 背景与约束
- 业务范围含生产模块，工单维度归集**料（直接材料）+ 工（直接人工）+ 费（制造费用）**，完工结转产成品成本，月末在产品（WIP）计价，与财务模块（GL）勾稽。
- 不可妥协红线：数据模型完整性、借贷平衡、移动加权一致、金额 BigDecimal、财务只可冲销不可物删/改、期间不可随意重开、可审计。
- 现实约束（v1.0 已证实的缺口）：**无工资模块、无制造费用归集单据、产品档案无标准成本**。故工/费的"钱"必须有务实来源（见 §6 D1）。

## 2. 核心决策：月末在产品（WIP）按【约当产量法】计价
对每个工单，月末时点：
```
期末在产约当量 = 期末在产数量 × 完工程度%
总约当产量    = 完工入库累计量 + 期末在产约当量
单位成本      = 工单累计成本 / 总约当产量
完工应负担    = 完工量 × 单位成本
在产应负担    = 在产约当量 × 单位成本
```

### 2.1 小企业从简口径（采纳）
- **料按数量比例、完工程度 100%**：BOM 投产时一次性投入，在产料完工度=100%。**料不单独算约当量**——料随领料即进 5001、随完工入库结转出 5001，由 M5-T05 增量模型已锁死守恒（Σ完工入库料金额 ≡ Σ领料出库金额，R1）。
- **工费按统一完工程度百分比**：工/费随加工进度累积。期末在产工费约当量 = 在产数量 × `wip_completion_pct`。
- **完工程度来源**：月末成本结转单上对每个未完工工单录入单一 `wip_completion_pct`（0–100），不逐工序拆（从简）。

> 一句话定调：**料按数量(100%投入)、工费按统一完工程度百分比；WIP 体现为 5001 生产成本科目的借方余额，不设独立在产品库存 SKU。**

## 3. 成本三要素的数据来源
| 要素 | 来源 | 算法 |
|---|---|---|
| 料 | 该工单 COMPLETED 领料单 issuedCost | `Σ issuedCost`（复用 T05 同口径），已由 T05 入产成品料成本，T06 **读不改** |
| 工 | 报工行工时 × 工序费率 | `Σ(ProductionReportLine.reportedHours × RoutingOperation.costRate)`；工序无 rate 用工单级/系统级**默认人工费率参数**兜底 |
| 费 | 制造费用按工时单一标准分摊 | `本期归集工时 × 制造费用率`（制造费用率为**配置参数**，元/工时，单一标准） |

## 4. 完工结转与产成品成本（不破坏 T05 守恒）
- T05 已把**料成本**随完工入库（PRODUCTION_IN）计入产成品库存（inboundCost），T06 **不动 inboundCost**。
- T06 仅把**完工应负担的"工+费"增量**通过 `CostAdjustCommand`（InventoryTxnType.COST_ADJUST，NEUTRAL：数量不变、只增金额）经库存唯一写入口追加到产成品库存：
  - 产成品移动加权单价上调，不稀释、不破坏 T05 料成本（加法叠加），库存恒等式（Σquantity/Σcost）不破。
  - 增量模型防重复入账：本期追加 = 工单完工总量应负担工费 − 该工单前期结转单已结转工费（`already_transferred` 锚点，照 T05 P0 教训）。
- **R1 守恒契约延伸**：T05 入料（≡领料出库），T06 用 COST_ADJUST 单独追加工费，来源单据不同、互不覆写；T06 只动增量，绝不改写 T05 已入料成本。

## 5. GL 凭证与科目（T06 出凭证）
科目全部已预置于 V19（无需新增）：`5001 生产成本`、`5101 制造费用`、`2211 应付职工薪酬`、`1405 库存商品`、`1403 原材料`。

T06 月末结转单过账时，对每个工单出分录（金额来自结转单行）：
1. **料归集**（T04/T05 未出 GL，料的 GL 归 T06）：`借 5001 生产成本 / 贷 1403 原材料`，金额=本期领料 issuedCost。
2. **工费归集**：`借 5001 生产成本 / 贷 2211 应付职工薪酬`（工）；制造费用**两段式**——平时归集 5101，月末 `借 5001 / 贷 5101`（5101 月末归零）。
3. **完工结转**：`借 1405 库存商品 / 贷 5001 生产成本`，金额=本期完工成本（料+工+费完工部分）。
4. **月末 WIP**：无凭证。5001 借方余额 = 在产料 + 在产工费 = 期末 WIP，进资产负债表"存货/在产品"。

凭证生成走新建 `ProductionCostVoucherService`（照 AutoVoucherService 范式：金额≤0 跳过、findBySourceDocNo 幂等、ensurePeriodExists、createFromSource+post），不塞进 AutoVoucherService（后者是一单一组借贷的即时模板，T06 是月末多工单批量多组分录）。

## 6. 关键裁定清单（D1–D9）
| # | 裁定 | 采纳 |
|---|---|---|
| **D1** 工费/制造费的"钱"来源 | 工费率=Routing.cost_rate（无则默认人工费率参数）；制造费用率=**配置参数**（元/工时单一标准），**非**期间费用池÷总工时（无费用归集来源）。登记 R-T06-1。 |
| D2 料的 GL 归属 | **全归 T06**（T04/T05 不出 GL）：补料归集 借5001/贷1403 + 完工结转 借1405/贷5001 |
| D3 约当量口径 | 料 100%(数量)、工费统一完工程度% |
| D4 制造费用 | **两段式**（5101 月末归零，与关账协调） |
| D5 结转单粒度 | **一张月末结转单管该期所有工单**（多行），照 PeriodClose 月末批处理 |
| D6 加工费机制 | **复用 CostAdjustCommand**（语义对口、恒等式不破、无除不尽残差） |
| D7 WIP 记账 | **5001 借方余额**，不设在产品 SKU |
| D8 权限 | `production:cost` 授 ADMIN/BOSS/ACCOUNTANT（成本结转是会计动作） |
| D9 一致性勾稽 | ConsistencyCheckService 加"已完工工单工费已结转"规则，**WARN 非阻塞**（避免误卡关账） |

## 7. 期间/关账顺序（硬约束）
`报工完工(T05) → 月末成本结转(T06 ProductionCostSettlement.post) → 损益结转关账(M4-T05 PeriodCloseService.close)`。
- T06 结转单过账校验目标账期 OPEN（撞 CLOSED 抛 PeriodClosedException 回滚，复用现有守卫）。
- 关账时 5001 留借方余额（WIP）属预期：COST 类不参与损益结转、不被试算平衡断言卡（断言只查 PROFIT_LOSS 净额=0）；5101 两段式已归零。

## 8. 遗留登记（R-T06-x）
- R-T06-1：制造费用率为静态配置参数（非真实费用池÷总工时），无费用归集单据；待费用/工资模块改实际分摊。
- R-T06-2：工费率依赖 Routing.cost_rate 录入，工序无 rate 兜底默认费率，可能失真。
- R-T06-3：完工程度为工单级单一百分比（非逐工序），约当量精度有限。
- R-T06-4：报废（scrapQty）成本本批不单独分摊，归入完工/在产，留后续。
- R-T06-5：约当量除不尽舍入尾差并入完工部分（同出空清零思路）。
- R-T06-6：T06 完工结转无冲销（同 T05 R6），结转单 REVERSED 留后续。
- R-T06-7：分批跨月完工工费增量用 already_transferred 锚点防重复，测试须断言多期 Σ守恒。
- **R-T06-8（评审 P2-1，技术债）**：双锚点跨「建单→过账」时间窗口口径不一致——库存 COST_ADJUST 增量用**建单时冻结**的 `alreadyTransferred`（行存值），GL 完工结转增量用**过账时实时** `priorCumulativeByWorkOrder`。正常顺序过账两者等价（已测）；但同一工单存在两张 APPROVED 未过账结转单且乱序过账时，库存 1405 子账与 GL 1405 完工累加口径可能偏移。D5（一张单管全期所有工单）使命中概率低。**修复方向**：GL 增量改用行上冻结值（与库存同源同时点），或 post 入口对同工单互斥校验（同时至多一张在途结转单）；并补**多期真库集成测**（评审 P3-3：同工单跨两账期各结转，断言库存 COST_ADJUST Σ = GL 1405 完工累加 + 一致性 0 ERROR）。
- R-T06-9（评审 P3-4，前瞻提示）：当前 WIP 留 5001 借方余额（D7）规避了 WIP 重复确认；若后续 T07/费用模块引入「在产品独立 SKU」或 WIP 凭证，必须同样套用 prior 锚点增量逻辑，否则 WIP 部分会按累计值重复确认。
