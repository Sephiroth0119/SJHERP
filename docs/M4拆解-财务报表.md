# M4-T06 财务报表（资产负债表 + 利润表）拆解与实现方案

> 路线图 §6 M4-T06（M 级）。本文是 T06 的单一设计真源，实现严格据此。
> 范围：**资产负债表**（时点，Assets = Liabilities + Equity）+ **利润表**（期间 + 本年累计，Revenue − Expense = Net Profit），均按小企业会计准则模板映射科目。
> 验收：与手工对账案例一致（真库整月业务→关账→报表数值与手算吻合、资产负债表平衡、利润表净利润=结转净利润=毛利）。
> **不做**（登记延后）：现金流量表（路线图标 P2，留后续）；维护型 `account_period_balance` 期末冻结表（见 §0 决策，本批仍不建表）。

## 0. 关键裁定：账期余额由凭证累计派生，不建 account_period_balance 冻结表

T05 文档曾记「account_period_balance 随 T06 协同落地」。**本批修正为：不建表，两报表均由 voucher/voucher_line 累计派生。** 工程理由：
1. **正确性不需要**：已关账期禁止过账（VoucherService.post 守卫），其派生余额天然稳定不变；冻结表只是把"每次重算"换成"读快照"，是**纯性能优化**，不影响任何数值正确性。
2. **避免在最高风险路径加写逻辑**：关账（PeriodCloseService.close）已是全系统最高风险的原子事务，为一个性能优化在其中追加"冻结全科目余额"写步骤，反而增加关账路径的故障面与回滚复杂度，得不偿失。
3. **小企业数据量**：v0.5 beta 种子用户凭证量小，累计聚合（WHERE period ≤ P，命中 idx_voucher_period + idx_voucher_line_account）足够快。
4. **期初建账**：GL 期初余额本就缺失（T02 OPENING 凭证延后），冻结表此刻也无期初可冻；待 OPENING 凭证补齐后，期初自然进入累计派生。

**登记（路线图 §0.5 技术债）**：当凭证量增大或资产负债表查询变慢时，引入 `account_period_balance` 期末冻结表（关账时冻结 + 期初结转），作为性能优化；届时派生口径必须与本批一致（回归对账）。

## 1. 数据派生口径（新建只读 DAO `com.sjherp.app.finance.FinancialStatementDao`，@Repository，参照 AgingReportDao）

CLAUDE.md 铁律「写操作只能经领域服务，报表/校验只读除外」——本类只有 SELECT/聚合，零写。金额一律 DECIMAL，跨行合计用 DECIMAL 精确 SQL 聚合，`nz()` 收敛 NULL→0。account_code 为 CHAR/yyyyMM 字符串，period 比较用字符串 `<=`（定长 yyyyMM 字典序=时序）。tenant_id 恒 0。

### 1.1 资产负债表派生：科目累计净额（截至账期 P 末，时点）
```sql
SELECT vl.account_code,
       SUM(vl.debit)  AS total_debit,
       SUM(vl.credit) AS total_credit
FROM voucher_line vl
JOIN voucher v ON vl.voucher_id = v.id
WHERE v.tenant_id = 0 AND v.status = 'APPROVED' AND v.period <= ?   -- 截至 P 末累计（含 P）
GROUP BY vl.account_code
```
返回 `List<AccountNetRow(accountCode, totalDebit, totalCredit)>`；净额（借方向）`net = totalDebit − totalCredit`。**含结转损益凭证**（4103 本年利润因此承接累计净利润；损益类经结转后累计净额=0，正确不进资产负债表）。service 侧用 `AccountService.listAll()` 取每个 code 的 type/balanceDir/name 做分类与映射。

### 1.2 利润表派生：损益类本期/本年累计发生额（**排除结转凭证**）
```sql
SELECT vl.account_code,
       SUM(vl.debit)  AS total_debit,
       SUM(vl.credit) AS total_credit
FROM voucher_line vl
JOIN voucher v ON vl.voucher_id = v.id
WHERE v.tenant_id = 0 AND v.status = 'APPROVED'
  AND v.period BETWEEN ? AND ?                         -- 本期=[P,P]；本年累计=[当年1月,P]
  AND (v.source_doc_type IS NULL OR v.source_doc_type <> 'PERIOD_CLOSING')   -- 排除结转损益凭证
GROUP BY vl.account_code
```
**为何排除 PERIOD_CLOSING**：利润表反映**经营活动**的收入/费用；结转损益凭证是内部期末结转（把损益类冲入 4103），若计入则损益类发生额自相抵消归零、利润表全为 0。排除后，损益类发生额=经营真实发生额，且 `净利润（利润表）== 结转净利润 == 4103 本期变动`（集成测试交叉验证）。本年累计区间 `[yyyy01, P]`（同年 1 月至 P），本期区间 `[P, P]`。

## 2. 报表科目映射（小企业会计准则；service 侧静态映射，仅末级科目出现在凭证行）

### 2.1 资产负债表（service 按 code 归集到报表行；contra 科目余额方向 CREDIT 作减项）
**资产**：货币资金=1001+1002+1012｜短期投资=1101｜应收账款=1122｜预付账款=1123｜其他应收款=1221｜存货=1401+1403+1405+1407+1411−1471(存货跌价准备 contra)｜固定资产=1601−1602(累计折旧 contra)｜无形资产=1701｜长期待摊费用=1801。**资产总计**=各行（按借方向净额，contra 减）。
**负债**：短期借款=2001｜应付账款=220201+220202｜预收账款=2203｜应付职工薪酬=2211｜应交税费=222101+222102｜其他应付款=2241｜长期借款=2501。**负债合计**=各行（按贷方向净额=−net）。
**所有者权益**：实收资本=4001｜资本公积=4002｜盈余公积=4101｜未分配利润=4103本年利润+4104利润分配 **+ 本期未结转损益**｜**权益合计**=各行（贷方向）。
**本期未结转损益**（动态本年利润，保证开账期/未关账也平衡）= `−Σ(PROFIT_LOSS net) − Σ(COST net)`（损益类借方净额为正=费用、贷方为负=收入；该式=收入−费用−成本=尚未结转的当期利润）。关账后损益类累计净额=0，此项=0，未分配利润=4103+4104。

**平衡不变式**（验收核心）：`资产总计 == 负债合计 + 权益合计`。由复式记账 Σ全部借=Σ全部贷 + 未结转损益折入权益，**恒成立**。service 计算 `balanced` 布尔（两侧 compareTo==0）；集成测试断言 true。**不可分类的科目余额必须暴露**（财务报表红线）：若某有余额 leaf code 不在映射表，归入"其他"行并使 balanced 仍可校验（宁可显示也不静默丢）——预置科目表固定，正常不应触发。

### 2.2 利润表（小企业会计准则，本期 + 本年累计两列）
①营业收入=6001+6051 ②减:营业成本=6401+6402 ③减:税金及附加=6403 ④减:销售费用=6601 ⑤减:管理费用=6602 ⑥减:财务费用=6603 ⑦加:投资收益=6111 → **⑧营业利润**=①−②−③−④−⑤−⑥+⑦ ⑨加:营业外收入=6301 ⑩减:营业外支出=6711 → **⑪利润总额**=⑧+⑨−⑩ ⑫减:所得税费用=6801 → **⑬净利润**=⑪−⑫。
每行金额=该科目自然方向净额（收入类 CREDIT：credit−debit；费用类 DEBIT：debit−credit），取自 §1.2 排除结转后的发生额。**交叉校验**：⑬净利润 == 同期 PeriodCloseService 结转的 netProfit（集成测试断言）。

## 3. 应用层
- **FinancialStatementService**（@Service）：注入 FinancialStatementDao + AccountService；`balanceSheet(String period)` → BalanceSheet、`incomeStatement(String period)` → IncomeStatement（内部算本期+本年累计）。映射逻辑、平衡校验、净利润计算在此。
- **DTO**（com.sjherp.app.finance.FinancialStatementDtos，record，金额一律 toPlainString 字符串）：
  - `BalanceSheetLine(String name, String amount)`；`BalanceSheet(String period, List<BalanceSheetLine> assetLines, String totalAssets, List<BalanceSheetLine> liabilityLines, String totalLiabilities, List<BalanceSheetLine> equityLines, String totalEquity, boolean balanced)`。
  - `IncomeStatementLine(String name, String currentPeriod, String yearToDate)`；`IncomeStatement(String period, List<IncomeStatementLine> lines, String netProfitCurrent, String netProfitYtd)`。
- **REST**（GlFinancialReportController 或并入既有 /api/reports，**类级 @PreAuthorize("@perm.has('finance:report')")**）：
  - `GET /api/reports/balance-sheet?period=yyyyMM` → BalanceSheet（period 必填，格式校验，缺/错→400）。
  - `GET /api/reports/income-statement?period=yyyyMM` → IncomeStatement。
  - 参数不合法 → 400 {"error":...}（@ExceptionHandler，口径同 AgingReportController）。
- **装配**：FinancialStatementDao @Repository、FinancialStatementService @Service 组件扫描（同 AgingReportDao/账龄链，无需改 Config）。

## 4. 权限（Permission + RolePermissions + docs/权限矩阵.md 三处同步）
**新增 `FINANCE_REPORT("finance:report","会计报表")`**：资产负债表/利润表暴露全盘财务状况（敏感），须本权限点。授 ADMIN（allOf 自动）+ BOSS + ACCOUNTANT（与 finance:voucher 同档，报表是会计日常产出）。同步 RolePermissionsTest（BOSS/ACCOUNTANT 期望集合 +finance:report、授予/拒绝断言）。**本任务不加 Agent 工具**（财务 Agent 工具——查利润/账龄留 T08，届时复用 finance:report）；HighRiskToolPermissionTest 基线不受影响。

## 5. 测试计划（质量闸门不降档）
- **service 单测（mock DAO + AccountService）**：

  - 利润表：各行映射、营业利润/利润总额/净利润计算、收入贷方向·费用借方向净额；本期 vs 本年累计区间不同；净利润=收入−成本−费用−税。
- **控制器（MockMvc + mock Service）**：balance-sheet/income-statement → 200（金额字符串、balanced 字段）；period 缺失/格式错→400；无 finance:report→403（专项 @WebMvcTest 或既有权限测范式）。
- **集成（@Tag("integration-db") 真库，照 PeriodCloseFlowIntegrationTest/PurchaseToSalesFlowIntegrationTest 装配整栈）——验收主测**：
  1. Flyway 迁移→开账期 P→模拟整月业务（采购入库/发票/付款 + 销售出库 COGS/发票/收款，T02 自动凭证）。
  2. **关账前** income-statement(P)：营业收入=销售额、营业成本=COGS、净利润=毛利（排除结转，此时尚无结转凭证）。
  3. **关账前** balance-sheet(P)：balanced=true（未结转损益折入未分配利润）；应收=1122 余额、存货=1405 余额、应付=2202 余额对账。
  4. close(P) 关账 → 生成结转凭证。
  5. **关账后** income-statement(P)：数值不变（结转被排除，经营发生额恒定）；净利润 == close 返回的 netProfit。
  6. **关账后** balance-sheet(P)：balanced=true；未分配利润含 4103=毛利；损益类各行已归零不影响。
  7. 与手工对账案例（设计/业务文档给定数字）逐行吻合。

## 6. 风险与决策
1. **不建 account_period_balance**（见 §0），登记为未来性能优化。
2. **利润表排除 PERIOD_CLOSING**（见 §1.2），否则损益自相抵消归零——这是 T06 最易错点，单测+集成双重覆盖。
3. **资产负债表恒平衡**靠"未结转损益折入权益"——对开账期/未关账期同样平衡；若不平（balanced=false）说明有未分类科目或数据异常，必须暴露不静默。
4. **本年累计区间** [当年1月, P]；跨年由 period 字符串 BETWEEN 'yyyy01' AND 'yyyyMM' 控制（同年）。
5. 现金流量表 P2 延后（小企业可后补，需现金流量项目映射，工作量独立）。
6. **COST 类（5001 生产成本/5101 制造费用）期末借方余额（在制品 WIP）当前折入资产负债表"未分配利润"作减项**（unsettledProfit 含 −Σ COST net），而非作为存货（在制品）列示于资产侧——账面仍平衡，但 WIP 是资产、列报不符会计准则；且此时「资产负债表未分配利润 ≠ 利润表净利润 ≠ 结转 netProfit」（后二者仅含 PROFIT_LOSS）。**当前 M3 链路不产生 COST 余额（生产模块在 M5），无活跃缺陷**。登记：M5 生产成本结转落地时，将 5001/5101 借方余额改列为存货（在制品）资产行（评审 P2）。
7. **利润表"其他损益（未分类）"兜底行**（评审 P2）：利润表行按硬编码 12 个损益 code 归集，资产负债表 unsettledProfit 按 AccountType 动态遍历——为防未来迁移新增损益科目时利润表静默漏列、破坏「净利润==结转 netProfit」不变式，利润表对未被任一行映射的 PROFIT_LOSS 科目发生额折入"其他损益（未分类）"行（与资产负债表"其他"行同源原则，暴露不丢）。
6. 全程 BigDecimal/DECIMAL(18,2)、tenant_id=0、UTC、金额字符串承载；主表/JOIN 不静默丢行。
