# M4-T07 统一冲销机制 拆解与实现方案

> 路线图 §6 M4-T07（标 M，实为 L，照 M3/M4-T04 先例拆 a/b/c）。本文是 T07 单一设计真源。
> 目标：**所有已过账单据只可冲销（红字单据 + 红字凭证），物理删除在领域层不存在**。验收：尝试删除已过账单据的所有路径都被拒。
> 设计输入：M4-T07 冲销 landscape 侦察报告（已读全仓 9 个 reverse() 桩、各过账下游副作用、reversal_of_id 预留、核销/库存/凭证反向缺口）。

## 0. 已就绪框架钩子（侦察确认，勿重复造）
- `BusinessDocument.reverse(operator, reversalDocNo)`：原单 →REVERSED + 回填 reversedById；`markAsReversalOf(originalDocNo)`：红字单 DRAFT 时回填 reversalOfId；`isReversalDocument()`。
- `DocumentStatus` 流转表已含 `COMPLETED→REVERSED`、`APPROVED→REVERSED`、`EXECUTING→REVERSED`，REVERSED 为终态。
- 全部 9 单据表 + voucher 表已预留 `reversal_of_id`/`reversed_by_id` 列（V11-V19/V23/V24）。
- 9 个 `reverse()` 桩均 `throw UnsupportedOperationException("...统一在 M4-T07 落地")`。
- 业务单据表零 DELETE（仅 catalog 的 unit/category 可物删，非财务记录）；聚合/服务无 delete 方法。

## 1. 跨切面裁定（a/b/c 共同遵守）

1. **红字凭证 = 借贷对调（反向分录），不用负额**。`VoucherLine.create` 强制「恰一方>0、非负、2 位」——负额非法。故冲销凭证把原凭证每行 `debit↔credit` 对调、金额不变；科目净额与原凭证抵消归零，Σ借==Σ贷 守恒、总额>0、行数≥2 不变式全满足。
2. **冲销凭证在原凭证账期过账，该账期须 OPEN**，否则抛 `PeriodClosedException`（关账后不得在该期再过账；闭月更正需先重开账期——与 T05 重开后重结同源，由人工高敏 reopen 后再冲销）。冲销凭证 `voucherDate` = 原凭证 `voucherDate`。
3. **冲销凭证来源防 uk 冲突**：新增 `VoucherSourceType.VOUCHER_REVERSAL`，`source_doc_type=VOUCHER_REVERSAL`、`source_doc_no=原凭证号`。uk_voucher_source=(tenant, source_doc_type, source_doc_no)，与原凭证（其自身 source_type 或 null）天然不撞；每张原凭证至多一张红冲凭证（物理唯一兜底幂等）。
4. **红字业务单据编号**：复用各单 DocumentNumberRule 生成**新单号**（如红字采购入库单仍 PR-yyyyMM-序号，靠 reversalOfId 关联原单，不靠号段后缀），避免与原单号撞唯一键、且红字单本身是合法单据可追溯。
5. **核销反向（unsettle）= 只追加反向核销记录**（原则 2/3 只追加不改不删）。settlement_record 加 `reversal_of_id`（指向被冲销的原核销记录 id）+ amount 仍>0 但语义为冲回；子账 `settled_amount` rollup 改为 `Σ正向 − Σ反向`。AccountsReceivable/Payable 加 `unsettle(amount)`（settledAmount 减、状态回退 SETTLED→PARTIAL→OPEN，下溢<0 抛异常）。一致性勾稽（T04c）rollup 口径同步为含反向。
6. **COGS 反向按原值**：销售出库冲销时，库存反向入库的成本=出库行已固化的 `cogs_amount`（不重算移动加权——期间可能已进新货，重算会失真）。用 `COST_ADJUST` 或反向 `SALES_OUT`（quantity>0,totalCost=原COGS）经库存唯一写入口，幂等键=`<原单>:REVERSAL:行号`。
7. **AP/AR 反向生成**：`AccountsPayable.open`/`AccountsReceivable.open` 校验 amount>0。冲销发票时不能建负额子账——改为：①原子账若**未核销**则整笔冲回（追加红字子账或将原子账标记 REVERSED 状态[子账加状态]）②已部分核销则先 unsettle 再冲。**裁定：发票冲销前置校验「原子账无核销」**（已核销的发票须先冲销对应收付款单），简化为不处理"带核销的发票冲销"递归级联——保数据模型不破碎，复杂级联留显式前置拒绝 + 清晰报错。
8. **子账量回滚**：冲销时回滚 receivedQty/invoicedQty/deliveredQty（侦察登记的 D-8a 遗留），由各单 reverse 同事务内调既有回写服务传负量（或新增 reverseReceipt/reverseInvoiced 方法，守门不下溢<0）。
9. **物理删除红线**：本任务不新增任何 DELETE 路径；新增**架构守卫测试**断言全业务聚合/服务/仓储无 delete、DocumentStatus COMPLETED 只可 →REVERSED。
10. **红字法「已过账集」= APPROVED + REVERSED（凭证派生口径，T07a P0 修复）**：红字法保留原凭证 + 追加借贷对调红字凭证，二者**必须都计入**科目余额汇总才能相互抵消归零。原凭证冲销后转 REVERSED，其经济发生额已真实入账、由红字凭证（APPROVED）抵消——若仅统计 APPROVED，原凭证被整笔剔除、仅红字计入，科目余额被写成真实业务的**反方向**（错账，且 Σ借==Σ贷 仍成立而静默）。故**所有凭证行派生口径**统一改为 `status IN ('APPROVED','REVERSED')`：①`JdbcVoucherRepository.aggregateBalances`（试算平衡/科目余额，T01/T05）②`FinancialStatementDao.cumulativeBalances`（资产负债表，T06）③`FinancialStatementDao.profitLossMovements`（利润表，T06——被冲销发票的原+红字都计入→该笔损益净额归零，正确剔除已冲销业务）。DRAFT/CANCELLED 未过账仍不计入。此为红冲正确性的财务红线，三处必须一致。

## 2. 子任务拆分

### T07a（本批）：凭证红冲基元 + 统一防删验收
- `VoucherService.reverse(docNo, operator)` 实现：装载原凭证（须 APPROVED，非 APPROVED[草稿/已冲销]抛 IllegalState）→ 账期 OPEN 校验 → 构造借贷对调红字凭证（VOUCHER_REVERSAL 来源回填）→ 过账 → 原凭证 `reverse(operator, 红字号)`（APPROVED→REVERSED + 双向 linkage）→ 幂等（原凭证已 REVERSED 或已有红冲则拒）。
- `VoucherSourceType.VOUCHER_REVERSAL`（label「凭证冲销」）。
- REST `POST /api/gl/vouchers/{docNo}/reverse` → 红字凭证（finance:voucher）。
- Agent 工具 `reverse_voucher`（HIGH HITL，finance:voucher，常驻 52→53）。
- **统一防删验收**：`NoPhysicalDeleteArchitectureTest`（反射/约定测试）——遍历 9 业务聚合 + 凭证：①无 public delete/remove 方法②对应领域服务无 delete③DocumentStatus 流转表 COMPLETED 仅 →REVERSED；满足路线图验收「尝试删除已过账单据的所有路径都被拒」。
- 测试：domain（对调红字数学/状态/幂等/账期 CLOSED 拒/原单非 APPROVED 拒）、controller、真库集成（建平衡凭证→过账→reverse→试算 6001/1001 净额归零、原 REVERSED+红字 APPROVED 双向 linkage、再 reverse 拒、关账期 reverse 拒回滚、审计 voucher.reverse）。

### T07b（后续）：业务单据红冲（采购入库/发票 + 销售出库/发票）
各 `reverse()` 实现：同事务内 ①生成红字业务单（reversalOf 关联）②反向下游（库存反向 PURCHASE_IN/SALES_OUT 按原值 + 子账量回滚 + AP/AR 冲回[前置校验无核销]）③反向自动凭证（复用 T07a 红冲基元或对调分录）④原单 →REVERSED。invoicedQty/receivedQty/deliveredQty 回滚收口（还 D-8a）。

### T07c（后续）：收付款红冲 + 核销反向 + 调拨/盘点红冲
- 核销反向引擎：settlement_record +reversal_of_id、AR/AP.unsettle、rollup 含反向、一致性勾稽口径同步。
- 收/付款单 reverse：按 paymentDocNo 反查核销记录 → 追加反向核销记录 unsettle → 反向现金侧凭证 → 原单 REVERSED。
- 调拨单（两腿反向）、盘点单（COUNT_GAIN/LOSS 反向）reverse。

## 3. T07a 实现细节（com.sjherp.domain.gl + app.gl）

### VoucherService.reverse
```
reverse(docNo, operator):
  原 = get(docNo)
  原.status==APPROVED 否则 throw IllegalStateException("仅已过账凭证可冲销，当前=...")
  原已被冲销(reversedById!=null) → throw IllegalStateException("凭证已冲销，红字号=...")  // 幂等
  红冲已存在 findBySourceDocNo(docNo) 含 VOUCHER_REVERSAL → throw（物理兜底前的应用层幂等）
  账期 OPEN 校验（accountingPeriodService.isOpen(原.period)）否则 PeriodClosedException
  红字行 = 原.lines 每行 new VoucherLineInput(accountCode, 原.credit, 原.debit, "冲销:"+原摘要)  // 借贷对调
  红字号 = numberGenerator.generate(VCH, YearMonth.from(原.voucherDate))
  createFromSource(红字号, 原.period, 原.voucherDate, "冲销 "+docNo, VOUCHER_REVERSAL, docNo, 红字行, operator)
  post(红字号, operator)
  原.reverse(operator, 红字号)   // APPROVED→REVERSED + reversedById
  红字.markAsReversalOf? —— 红字聚合 reversalOfId 经 createFromSource 落不进；T07a 在 reverse 内对红字聚合 markAsReversalOf(docNo) 后 save（或 createFromSource 增 reversalOf 入参）
  repository.save(原)
  return 红字
```
注意：红字凭证的 `reversalOfId` 回填——`createFromSource` 当前不带 reversalOf 参数。T07a 给红字凭证落 reversalOfId：在 post 后、save 时经聚合 `markAsReversalOf(docNo)`（DRAFT 时标记，但凭证 post 后已 APPROVED——故需在 create 后、post 前 markAsReversalOf）。调整顺序：create→markAsReversalOf→save→post。或给 JdbcVoucherRepository 落 reversal_of_id 列（V19 已有列）。实现时择一，保证红字凭证 reversal_of_id=原号、原凭证 reversed_by_id=红字号 双向可查。

## 4. 风险与决策
1. 红冲=借贷对调（非负额），不变式全满足（§1.1）。
2. 闭月冲销须先 reopen（§1.2），不自动重开（高敏，原则 2）。
3. 带核销的发票冲销 T07b 前置拒绝（§1.7），递归级联不做——保模型不破碎，清晰报错引导先冲收付款单。
4. 核销反向只追加（§1.5），settled_amount rollup 与一致性勾稽口径 T07c 同步改。
5. COGS 反向按固化原值（§1.6），不重算加权。
6. 全程 BigDecimal、tenant_id=0、UTC、@Audited、同事务原子、幂等。
