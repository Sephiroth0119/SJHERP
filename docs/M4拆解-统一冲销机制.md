# M4-T07 统一冲销机制 拆解与实现方案

> 路线图 §6 M4-T07（标 M，实为 L，照 M3/M4-T04 先例拆 a/b/c）。本文是 T07 单一设计真源。
> 目标：**所有已过账单据只可冲销（红字单据 + 红字凭证），物理删除在领域层不存在**。验收：尝试删除已过账单据的所有路径都被拒。
> 设计输入：M4-T07 冲销 landscape 侦察报告（已读全仓 9 个 reverse() 桩、各过账下游副作用、reversal_of_id 预留、核销/库存/凭证反向缺口）。

## 0. 已就绪框架钩子（侦察确认，勿重复造）
- `BusinessDocument.reverse(operator, reversalDocNo)`：原单 →REVERSED + 回填 reversedById；`markAsReversalOf(originalDocNo)`：红字单 DRAFT 时回填 reversalOfId；`isReversalDocument()`。
- `DocumentStatus` 流转表已含 `COMPLETED→REVERSED`、`APPROVED→REVERSED`、`EXECUTING→REVERSED`，REVERSED 为终态。
- 全部 9 单据表 + voucher 表已预留 `reversal_of_id`/`reversed_by_id` 列（V11-V19/V23/V24）。
- 9 个 `reverse()` 桩均 `throw UnsupportedOperationException("...统一在 M4-T07 落地")`。
- 业务单据表零 DELETE（仅 catalog 的 unit/category 可物删，非财务记录）；聚合/服务无 delete 方法。

## 1. 跨切面裁定（a/b/c 共同遵守）

1. **红字凭证 = 借贷对调（反向分录），不用负额**。`VoucherLine.create` 强制「恰一方>0、非负、2 位」——负额非法。故冲销凭证把原凭证每行 `debit↔credit` 对调、金额不变；科目净额与原凭证抵消归零，Σ借==Σ贷 守恒、总额>0、行数≥2 不变式全满足。
2. **冲销凭证在原凭证账期过账，该账期须 OPEN**，否则抛 `PeriodClosedException`（关账后不得在该期再过账；闭月更正需先重开账期——与 T05 重开后重结同源，由人工高敏 reopen 后再冲销）。冲销凭证 `voucherDate` = 原凭证 `voucherDate`。
3. **冲销凭证来源防 uk 冲突**：新增 `VoucherSourceType.VOUCHER_REVERSAL`，`source_doc_type=VOUCHER_REVERSAL`、`source_doc_no=原凭证号`。uk_voucher_source=(tenant, source_doc_type, source_doc_no)，与原凭证（其自身 source_type 或 null）天然不撞；每张原凭证至多一张红冲凭证（物理唯一兜底幂等）。
4. **红字业务单据编号**：复用各单 DocumentNumberRule 生成**新单号**（如红字采购入库单仍 PR-yyyyMM-序号，靠 reversalOfId 关联原单，不靠号段后缀），避免与原单号撞唯一键、且红字单本身是合法单据可追溯。
5. **核销反向（unsettle）= 只追加反向核销记录**（原则 2/3 只追加不改不删）。settlement_record 加 `reversal_of_id`（指向被冲销的原核销记录 id）+ amount 仍>0 但语义为冲回；子账 `settled_amount` rollup 改为 `Σ正向 − Σ反向`。AccountsReceivable/Payable 加 `unsettle(amount)`（settledAmount 减、状态回退 SETTLED→PARTIAL→OPEN，下溢<0 抛异常）。一致性勾稽（T04c）rollup 口径同步为含反向。
6. **COGS 反向按原值**：销售出库冲销时，库存反向入库的成本=出库行已固化的 `cogs_amount`（不重算移动加权——期间可能已进新货，重算会失真）。用 `COST_ADJUST` 或反向 `SALES_OUT`（quantity>0,totalCost=原COGS）经库存唯一写入口，幂等键=`<原单>:REVERSAL:行号`。
7. **AP/AR 反向生成**：`AccountsPayable.open`/`AccountsReceivable.open` 校验 amount>0。冲销发票时不能建负额子账——改为：①原子账若**未核销**则整笔冲回（追加红字子账或将原子账标记 REVERSED 状态[子账加状态]）②已部分核销则先 unsettle 再冲。**裁定：发票冲销前置校验「原子账无核销」**（已核销的发票须先冲销对应收付款单），简化为不处理"带核销的发票冲销"递归级联——保数据模型不破碎，复杂级联留显式前置拒绝 + 清晰报错。
8. **子账量回滚**：冲销时回滚 receivedQty/invoicedQty/deliveredQty（侦察登记的 D-8a 遗留），由各单 reverse 同事务内调既有回写服务传负量（或新增 reverseReceipt/reverseInvoiced 方法，守门不下溢<0）。
9. **物理删除红线**：本任务不新增任何 DELETE 路径；新增**架构守卫测试**断言全业务聚合/服务/仓储无 delete、DocumentStatus COMPLETED 只可 →REVERSED。
10. **红字法「已过账集」= APPROVED + REVERSED（凭证派生口径，T07a P0 修复）**：红字法保留原凭证 + 追加借贷对调红字凭证，二者**必须都计入**科目余额汇总才能相互抵消归零。原凭证冲销后转 REVERSED，其经济发生额已真实入账、由红字凭证（APPROVED）抵消——若仅统计 APPROVED，原凭证被整笔剔除、仅红字计入，科目余额被写成真实业务的**反方向**（错账，且 Σ借==Σ贷 仍成立而静默）。故**所有凭证行派生口径**统一改为 `status IN ('APPROVED','REVERSED')`：①`JdbcVoucherRepository.aggregateBalances`（试算平衡/科目余额，T01/T05）②`FinancialStatementDao.cumulativeBalances`（资产负债表，T06）③`FinancialStatementDao.profitLossMovements`（利润表，T06——被冲销发票的原+红字都计入→该笔损益净额归零，正确剔除已冲销业务）。DRAFT/CANCELLED 未过账仍不计入。此为红冲正确性的财务红线，三处必须一致。

### T07b（后续）：业务单据红冲（采购入库/发票 + 销售出库/发票）
各 `reverse()` 实现：同事务内 ①生成红字业务单（reversalOf 关联）②反向下游（库存反向 PURCHASE_IN/SALES_OUT 按原值 + 子账量回滚 + AP/AR 冲回[前置校验无核销]）③反向自动凭证（复用 T07a 红冲基元或对调分录）④原单 →REVERSED。invoicedQty/receivedQty/deliveredQty 回滚收口（还 D-8a）。

#### T07b 详规（基于侦察报告，本批）
**红字单据解读**：业务单据红冲 = 原单 →REVERSED + 反向全部下游副作用（库存/子账量/AP·AR）+ 红字凭证（复用 T07a `VoucherService.reverse` 红冲该业务单的自动凭证）。**不复制业务单据头**（红字凭证即「红字单据」的会计载体；原单 REVERSED 状态 + reversal linkage + 反向台账/库存完整记录冲销，复制单头无会计增量）。各 reverse 在对应 **AppService 层**同一 `@Transactional` 编排（原则 1：编排在 app 层），任一步失败整事务回滚。

**共享领域基元（foundation，purchase/sales 复用）**：
1. **库存按原成本反向**：`OutboundCommand` 加可选 `overriddenUnitCost`（默认 null 走移动加权；非空时 `postOutbound` 跳过加权、按指定单价算 totalCost）——采购入库红冲=outbound(收货数量, overriddenUnitCost=原 `PurchaseReceiptLine.unitCost`)；销售出库红冲=inbound(发货数量, unitCost=原 `SalesDeliveryLine.cogsAmount`/数量)（inbound 已接受 unitCost）。反向流水幂等键 `REVERSAL:<原docNo>:<行号>`（避与原流水 uk_idempotency_key 撞）。经库存唯一写入口 execute 原子。
2. **AP/AR 反向**：`PayableStatus`/`ReceivableStatus` 加 `REVERSED`；`AccountsPayable`/`AccountsReceivable` 加 `markReversed(operator)`（仅 `canBeReversed()`=settledAmount==0 且 status==OPEN 才可，否则抛——已核销发票须先冲收付款单 T07c）；仓储补 update 落 status。**账龄 DAO 与一致性勾稽排除 REVERSED**（aging WHERE status NOT IN ('SETTLED','REVERSED')；consistency 应付/应收==发票额规则跳过 REVERSED 对，避免红冲后误报）。
3. **子账量回滚**：`PurchaseReceiptLine`/`SalesDeliveryLine` 加 `subtractInvoiced(delta)`、`PurchaseOrderLine` 加 `subtractReceived`、`SalesOrderLine` 加 `subtractDelivered`（delta>0、回滚后不 <0 守门）；对应服务加 `reverseInvoiced`/`reverseReceipt`/`reverseDelivery` 回写入口。
4. **迁移 V25**：accounts_payable/accounts_receivable 无需加列（status 列 VARCHAR 容纳 REVERSED；linkage 经 sourceDocNo=被冲销发票号反查）——**裁定 T07b 无新增列**，仅状态值新增。若评审认为需显式 reversal 审计列，再加 `reversed_by_doc`。

**采购线 reverse（PurchaseReceiptAppService/PurchaseInvoiceAppService 加 reverse）**：
- 采购入库 reverse：校验 COMPLETED + 账期(自动凭证所在)→ 反向库存（outbound 原成本）→ `purchaseOrderService.reverseReceipt`（回滚 receivedQty）→ 红冲入库自动凭证（findBySourceDocNo(PR号) 取 PURCHASE_RECEIPT 凭证 → VoucherService.reverse）→ 原单 →REVERSED。
- 采购发票 reverse：校验 COMPLETED + 原应付 `canBeReversed`（无核销）→ `purchaseReceiptService.reverseInvoiced`（回滚 PR.invoicedQty）→ 应付 markReversed → 红冲发票自动凭证（PURCHASE_INVOICE 凭证 reverse）→ 原单 →REVERSED。

**销售线 reverse（对称 SalesDeliveryAppService/SalesInvoiceAppService 加 reverse）**：
- 销售出库 reverse：反向库存（inbound 原 COGS）→ `salesOrderService.reverseDelivery`（回滚 deliveredQty）→ 红冲出库自动凭证（SALES_DELIVERY 凭证 reverse）→ 原单 →REVERSED。（出库行 cogsAmount 固化可直接读回。）
- 销售发票 reverse：原应收 canBeReversed → `salesDeliveryService.reverseInvoiced`（回滚 SD.invoicedQty）→ 应收 markReversed → 红冲发票自动凭证（SALES_INVOICE 凭证 reverse）→ 原单 →REVERSED。

**REST + 工具**：各单 `POST /api/.../{docNo}/reverse`（沿用各自权限点 purchase:receipt|invoice / sales:delivery|invoice）+ 4 个 reverse Agent 工具（HIGH HITL）。
**账期守卫**：自动凭证红冲（VoucherService.reverse）内含账期 OPEN 校验，闭月时抛 PeriodClosedException → 整个 AppService.reverse 回滚（库存/子账/AP-AR 一并撤销），故业务单红冲天然受闭月保护，无需额外校验。
**幂等**：原单已 REVERSED 拒；自动凭证红冲幂等（T07a 三道）兜底。

### T07c：收付款红冲 + 核销反向 + 调拨/盘点红冲（本批）
**核销反向引擎（新核心）**：
- `AccountsReceivable.unsettle(amount)` / `AccountsPayable.unsettle(amount)`：`settledAmount -= amount`（守门 amount>0 且回退后 settled≥0，越退抛异常），状态按新 settled 重算（settled==0→OPEN、settled==amount→SETTLED、否则 PARTIAL）。不可对 REVERSED 子账 unsettle（reversed 子账 settled 恒 0）。
- `SettlementRecord.recordReversal(...)`：**追加 amount<0 的反向核销记录**（只追加原则不破，Σ核销记录恒=子账 settled_amount → 一致性规则8 口径不变；规则9 settled≤amount 仍成立；规则10 状态-余额一致仍成立）。`SettlementRecord` 放开 amount 可负（仅经 recordReversal 工厂，正向 record 仍校验>0）。**无 V25 迁移**（amount 列 DECIMAL 容纳负值；reversal 经 created_at 序列 + paymentDocNo 重建，不加 reversal_of_id）。
- `SettlementService.unsettleReceivable/unsettlePayable(targetId, amount, date, paymentDocNo, operator)`（@Audited）：装载子账→unsettle→save→追加反向核销记录。
- 一致性 rollup（T04c/T07b checkSettlementRollup）口径不变（Σ含负向记录=settled）。

**收付款单 reverse（CollectionReceiptAppService/PaymentDisbursementAppService 加 reverse）**：@Transactional：校验原单 COMPLETED（幂等：已 REVERSED 拒）→ 按 paymentDocNo=单号 `settlementRecordRepository.findByPaymentDocNo` 反查正向核销记录 → 逐条 unsettleReceivable/Payable（子账 settled 回退、状态回 PARTIAL/OPEN）→ 红冲现金侧凭证（findBySourceDocNo(单号) 取 COLLECTION_RECEIPT/PAYMENT_DISBURSEMENT 凭证 → voucherAppService.reverse 复用 T07a）→ 原单 →REVERSED。**这解锁 T07b 暂拒的"已核销发票红冲"**：先冲收付款单→子账 settled 回 0→canBeReversed=true→再 T07b 红冲发票。账期守卫经现金侧凭证红冲天然护住（闭月抛 PeriodClosed 整单回滚）。

**调拨单 reverse（TransferService.reverse 实现）**：@Transactional：校验 COMPLETED → 反向两腿库存（原 TRANSFER_OUT 调出仓 → 反向 inbound 回调出仓按原成本；原 TRANSFER_IN 调入仓 → 反向 outbound 用 overriddenUnitCost=原调入单价；幂等键 REVERSAL:TR号:行:OUT/IN）→ 原单 →REVERSED。**无 GL 红冲**（调拨不出凭证，库存内部转移）。

**盘点单 reverse（StockCountService.reverse 实现）**：@Transactional：校验 COMPLETED → 逐行反向（原盘盈 COUNT_GAIN → 反向 outbound 用 overriddenUnitCost=原盘盈单价；原盘亏 COUNT_LOSS → 反向 inbound 按原成本；幂等键 REVERSAL:SC号:行）→ 原单 →REVERSED。**无 GL 红冲**（盘点不出凭证）。

**REST + 工具**：4 reverse 端点（收/付款 POST /api/collections|payments/{docNo}/reverse finance:settlement；调拨 POST /api/inventory/transfers/{docNo}/reverse inventory:transfer；盘点 POST /api/inventory/stock-counts/{docNo}/reverse inventory:count）+ 4 HIGH HITL 工具。无新增权限点、无新增迁移。
**状态机**：REVERSED 终态，不可再 reverse（单向，财务审慎）。

## 3. T07a 实现细节（com.sjherp.domain.gl + app.gl）

### VoucherService.reverse
```
reverse(docNo, operator):
  原 = get(docNo)
  原.status==APPROVED 否则 throw IllegalStateException("仅已过账凭证可冲销，当前=...")
  原已被冲销(reversedById!=null) → throw IllegalStateException("凭证已冲销，红字号=...")  // 幂等
  红冲已存在 findBySourceDocNo(docNo) 含 VOUCHER_REVERSAL → throw（物理兜底前的应用层幂等）
  账期 OPEN 校验（accountingPeriodService.isOpen(原.period)）否则 PeriodClosedException
  红字行 = 原.lines 每行 new VoucherLineInput(accountCode, 原.credit, 原.debit, "冲销:"+原摘要)  // 借贷对调
  红字号 = numberGenerator.generate(VCH, YearMonth.from(原.voucherDate))
  createFromSource(红字号, 原.period, 原.voucherDate, "冲销 "+docNo, VOUCHER_REVERSAL, docNo, 红字行, operator)
  post(红字号, operator)
  原.reverse(operator, 红字号)   // APPROVED→REVERSED + reversedById
  红字.markAsReversalOf? —— 红字聚合 reversalOfId 经 createFromSource 落不进；T07a 在 reverse 内对红字聚合 markAsReversalOf(docNo) 后 save（或 createFromSource 增 reversalOf 入参）
  repository.save(原)
  return 红字
```
注意：红字凭证的 `reversalOfId` 回填——`createFromSource` 当前不带 reversalOf 参数。T07a 给红字凭证落 reversalOfId：在 post 后、save 时经聚合 `markAsReversalOf(docNo)`（DRAFT 时标记，但凭证 post 后已 APPROVED——故需在 create 后、post 前 markAsReversalOf）。调整顺序：create→markAsReversalOf→save→post。或给 JdbcVoucherRepository 落 reversal_of_id 列（V19 已有列）。实现时择一，保证红字凭证 reversal_of_id=原号、原凭证 reversed_by_id=红字号 双向可查。

## 4. 风险与决策
1. 红冲=借贷对调（非负额），不变式全满足（§1.1）。
2. 闭月冲销须先 reopen（§1.2），不自动重开（高敏，原则 2）。
3. 带核销的发票冲销 T07b 前置拒绝（§1.7），递归级联不做——保模型不破碎，清晰报错引导先冲收付款单。
4. 核销反向只追加（§1.5），settled_amount rollup 与一致性勾稽口径 T07c 同步改。
5. COGS 反向按固化原值（§1.6），不重算加权。
6. 全程 BigDecimal、tenant_id=0、UTC、@Audited、同事务原子、幂等。
