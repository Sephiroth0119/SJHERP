## 验收范围

- 销售模块保留客户档案和销售订单，新增仅 `sales:delivery` 可见的销售出库页签。
- 列表、详情、创建、审核、过账与草稿作废只调用真实端点；不提供编辑、删除或 `reverse`。
- WAREHOUSE 无需 `sales:order`，仅凭 `sales:delivery` 即可读取建单候选并完成新建。
- 候选端点只返回 `APPROVED` 或 `EXECUTING` 且仍有未发完行的订单；DRAFT、COMPLETED 和已发完订单不可读取。
- `deliverableOnly` 在 JDBC count 和分页之前以状态限制和 tenant-correlated `EXISTS(quantity > delivered_qty)` 筛选；旧四参数 `SalesOrderQuery` 构造器保持兼容。
- 创建从真实候选销售订单选择并引用真实行号，从真实启用仓库选择；请求体窄化为 `salesOrderNo/warehouseId/remark/lines[soLineNo/productId/quantity]`。
- 数量、金额、已发量、剩余可发量和 COGS 均按字符串承载；JSON number 响应在 API 边界归一化，不做 JavaScript 浮点运算。
- 创建、审核、过账和作废共享同步 in-flight 守卫。
- 过账按钮旁和二次确认均明确说明扣减库存、按移动加权固化 COGS、回写销售订单发货量、生成自动凭证，以及库存不足时整张出库单失败并全部回滚。
- 列表、详情、销售订单候选、仓库选择、仓库名称和商品名称补载均有独立竞态隔离；同条件可重查，名称失败时诚实回退。
- 四个受保护文件 `README.md`、`docs/业务-进销存报表.md`、`docs/工程-自驱开发循环.md`、`docs/领域模型概览.md` 均未修改。
