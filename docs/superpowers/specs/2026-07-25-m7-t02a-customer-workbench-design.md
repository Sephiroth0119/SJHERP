# M7-T02a 客户档案传统界面纵切

## 目标与边界

T02a 交付一个面向小企业操作员的客户档案工作台：列表、关键词/状态筛选、分页、详情、新建、编辑、启用/停用。只调用既有 `/api/partner/customers` REST 契约，不补造后端能力，不提前实现供应商、商品、仓库或采购/销售单据页面。M7-T02 总体仍为“进行中”。

真实后续小批次：T02b 供应商/仓库；T02c 商品/类目/单位；T02d 采购/销售单据；T02e 库存；T02f 生产；T02g 财务。每一批复用本批验证过的业务页壳、表格/空态/错误态/表单模式，但仅在对应真实 API 存在且权限明确后实施；本文件不代表这些批次已开始或完成。

## 设计拆解

客户页面的单一任务是“快速找到并维护一个真实客户”。沿用现有 SJHERP 的深色侧栏、白色内容区、蓝色主行动色和紧凑 13–14px 信息密度；不引入新组件库。列表使用普通表格和明确的行选择，详情固定在右侧（窄屏下改为下方），筛选栏保持键盘连续操作。唯一的业务化识别点是详情顶部的状态条：启用/停用与联系人信息放在同一条扫描路径上。

```text
客户档案  [关键词____] [状态▼] [查询]                 [新建客户]
┌──────────── 客户列表 ────────────┐  ┌──── 客户详情/编辑 ────┐
│ 编码 | 名称 | 联系人 | 电话 | 状态 │  │ 基本资料              │
│ ...                              │  │ [编辑] [启用/停用]    │
│ 分页                             │  │ 保存/取消             │
└──────────────────────────────────┘  └──────────────────────┘
```

表单中的 `creditLimit` 全程字符串承载；提交时只发送输入字符串，不做前端财务计算。读写权限均 fail-closed：缺少精确权限时不显示按钮，后端仍为最终授权边界。loading、空结果、网络错误、保存成功均有可读文案，按钮具备可见焦点与 disabled 状态。
