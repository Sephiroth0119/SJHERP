# 领域工具清单（Agent Tools）

> 状态：v1.x（2026-06，M4-T08 增补 M4 全量工具登记）
> 代码：`server/sjherp-app/src/main/java/com/sjherp/app/tool/`（按域分包：catalog / partner / warehouse）
> 装配：`DomainToolConfig`（常驻注册，所有 profile 生效）；演示工具仍在 `ToolConfig.DemoToolConfig`（仅 dev/local）
> 关联：[Agent执行循环.md](./Agent执行循环.md)（高风险拦截 §4、安全壳 §5）、[流程缺口通道.md](./流程缺口通道.md)（record_process_gap）

## 1. 设计约定

- **工具即领域服务**（CLAUDE.md 原则 1）：所有工具执行一律经各 domain Service 唯一入口，绝不绕过；
- **风险等级**：查询类 NORMAL（直接执行）；创建类 HIGH（档案创建影响主数据，框架强制确认卡片，
  用户点「确认执行」后才真正执行——提示词只要求模型复述要点后直接调用，避免双重确认）；
- **审计操作人**：写操作 created_by/updated_by 记 `agent:<userId>`（userId 为会话所属 sys_user.id，
  区分人工与 Agent 操作，公共助手 `ArchiveToolSupport.operator`）；
- **查询返回上限**：精简列表最多 10 条（`ArchiveToolSupport.MAX_ITEMS`），超量时附 note 引导用户缩小范围；
- **编码自动生成**：创建类工具一律不接收编码参数，由领域服务按编号规则生成（CUS/SUP/SKU/WH-年月-序号）；
- **权限点**：创建类工具声明的 `requiredPermission` 已真实生效（M2-T06）：
  `RolePermissionToolChecker` 按会话所属用户实时查角色 → [权限矩阵](./权限矩阵.md) 判定；
  权限不足时工具不执行，"权限不足"错误回灌给模型向用户说明。查询类工具无权限点（登录即可）。

## 3. create_product 的单位解析约定

基本单位按**名称**解析（用户在聊天里说"单位是把"，模型无从得知单位 id）：

- 名称在 `UnitService.findAll()` 中精确匹配（strip 后全等）；
- 不存在时返回清晰错误：点名不存在的单位 + 列出系统已有单位 + 引导话术
  （改用已有单位，或先在界面「基础档案-计量单位」创建——本批**没有** create_unit 工具，
  提示词明确要求模型不假装能创建单位）；
- 注意时序：HIGH 拦截发生在执行前，因此"单位不存在"要等用户**确认后**才暴露
  （工具执行失败 → 错误回灌 → 模型向用户解释并引导）。实测（2026-06，DeepSeek）模型
  能正确转述错误并给出两个引导选项。

## 4. 系统提示词约定（LlmAgent「当前业务能力」段）

- 查询直接调用，引用真实数据回答；
- 创建类：先在 text 复述要点 → 直接发起调用 → 框架自动出确认卡片，
  模型**不得**自己再造一轮"是否确认"问答（避免双重确认），也不得在未执行成功前声称已创建；
- 工具未覆盖的需求走流程缺口通道（record_process_gap）。

## 5. 测试

`sjherp-app` 的 `app/tool` 测试（mock 各 domain Service + 真实 `JsonSchemaToolArgumentValidator`）：
查询条件映射（固定 page=1/size=10）、精简字段与中文标签、创建命令映射、结算方式默认 MONTHLY、
操作人 `agent:<userId>`、领域校验拒绝转 fail 回灌、create_product 单位解析失败路径（不触碰 Service）、
schema 必填/枚举/多余字段校验。
