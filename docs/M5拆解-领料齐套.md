# M5-T04 JIT 领料与齐套 拆解与实现方案

> 路线图 §7 M5-T04（M 级）。本文是 T04 单一设计真源。
> 范围：按 BOM 生成领料单 + 齐套检查（缺料清单）+ 退料；**领料必须走 M3 库存唯一写入口**（CLAUDE.md 红线）。这是工单首次真正消耗库存的环节。
> 验收：领料过账真实扣减库存（移动加权）、库存不足整批回滚；齐套检查输出缺料清单。

## 0. 范围红线 + 关键事实
- **做**：领料单（MaterialIssue）+ 齐套检查（只读）+ 退料单（MaterialReturn）+ 库存消耗（经 InventoryPostingPort 唯一入口）。
- **不做**：报工/完工入库（T05）、料工费归集与 GL 凭证（T06）、Agent 工具（T07）。
- **关键事实**（Plan 核对）：库存流水枚举真名 `com.sjherp.domain.inventory.InventoryTxnType`（非 StockMovementType），本批加 `PRODUCTION_ISSUE(OUT)`/`PRODUCTION_RETURN(IN)` **零破坏面**（InventoryService 只看 direction()、无穷举 switch、流水按 name() 存字符串）。领域调库存经各域自建窄端口 `InventoryPostingPort`（app 用 TransactionalInventoryService 适配，领域零依赖）。最新迁移 V27→本批 **V28**。

## 1. 关键设计裁定
1. **领料单 MaterialIssue（MI-）**：header(workOrderDocNo/warehouseId 领料仓/status 六态/remark) + line(productId 子件/requiredQty 应领/quantity 实领/unitId/issuedCost 过账回填)。**一个工单可多张领料单累加**（JIT 分批 + 补料=再开一张），同构 SalesDelivery"一订单多出库部分发货"。
2. **退料 MaterialReturn（MR-）独立单据**（不做负数行），引用原领料单 materialIssueDocNo，过账走 PRODUCTION_RETURN 入库，**按原领料成本退回**（InboundCommand 显式 unitCost=issuedCost/quantity，避期间进货成本漂移）。退料量≤原领料行实领量（防超退）。
3. **齐套检查只读、单层、不预留库存、仅提示不阻断**：按工单 active BOM **单层直接子件**需求（plannedQty×grossQuantity 含损耗）对比领料仓 balanceOf 可用量→缺料清单{required/available/shortage}+kitted 布尔。半成品由各自工单生产，故只领直接子件。不锁库存（小企业简化）。领料不强制齐套（可分批/缺料领部分，过账时才强校验库存），同销售出库口径。
4. **领料过账强校验库存、整批回滚、绝不绕过唯一入口**：MaterialIssueAppService.post 同一 @Transactional——单据 APPROVED→EXECUTING→逐行组 OutboundCommand(PRODUCTION_ISSUE，移动加权)一批 execute（库存不足抛 InsufficientStockException 整批回滚）→回填 issuedCost=result.totalCost().negate()→COMPLETED。幂等键 MATERIAL_ISSUE:MI-xxx:行号。
5. **工单状态联动**：领料要求工单 EXECUTING（已开工），**不自动开工**（开工为显式动作）；本批不回写工单字段（工单无 issuedQty 汇总，归集留 T06）。
6. **成本边界**：领料出库自然带出移动加权成本，仅记 issuedCost 供 T06 读；**本批不调 AutoVoucherService、不出"借生产成本/贷原材料"凭证**（与 SalesDeliveryAppService 刻意不同），GL 留 T06。
7. **权限 production:material**（护领料/退料写 + 齐套查询受控，工单查询权限点不复用）；ADMIN/BOSS，不引入 PRODUCTION 角色。
8. **Agent 工具留 T07**。

## 2. 领域模型（com.sjherp.domain.production 续建，纯 Java 零依赖）
- `MaterialIssue extends BusinessDocument`（header+行；create 校验工单 EXECUTING/行非空/数量>0、restore、assignId、totalIssuedCost；状态机用基类六态全表不覆写 beforeTransition，同 SalesDelivery）+ `MaterialIssueLine`（issuedCost 只回填一次≥0 2位，照 SalesDeliveryLine.assignCogs）+ LineInput/Repository/Query/NotFoundException。
- `MaterialReturn extends BusinessDocument`（引用 materialIssueDocNo）+ Line/Repository/Query/NotFoundException。
- `InventoryPostingPort`（生产域窄端口：execute(List<StockMovementCommand>, operator)，照 sales 范式）；`InventoryAvailabilityPort`（只读 balanceOf，照 MrpInventorySource）。
- `MaterialIssueService`（@Audited create/approve/post/cancel + get/search）、`MaterialReturnService`（create/approve/post，退料按原单价 InboundCommand）、`KittingCheckService`（只读 check(workOrder, warehouseId)→KittingCheck/KittingCheckLine）。

## 3. 领料过账编排（核心，照 SalesDelivery 双层范式）
```
MaterialIssueAppService.post(docNo, op)  [@Transactional 外层]
 └ materialIssueService.post(docNo, op)  [@Audited]
    1 mi=get; registerEventPublisher
    2 mi.startExecution(op)              // APPROVED→EXECUTING
    3 batch=每行 OutboundCommand(warehouseId, productId, PRODUCTION_ISSUE, quantity,
              "MATERIAL_ISSUE", docNo, lineNo, 幂等键 MATERIAL_ISSUE:docNo:lineNo)  // 不传 overriddenUnitCost→移动加权
    4 results=inventory.execute(batch, op)  // 唯一入口；库存不足 InsufficientStockException 整批回滚
    5 每行 assignIssuedCost(result.totalCost().negate())
    6 mi.complete(op)                    // EXECUTING→COMPLETED
    7 save
 └ 本批不调 autoVoucherService（与销售出库刻意不同，GL 留 T06）
```
退料 post 对称：PRODUCTION_RETURN + InboundCommand(unitCost=原领料单价)，幂等键 MATERIAL_RETURN:MR-xxx:行号。

## 4. 迁移 V28__production_material_issue.sql（四表，照 V17 sales_delivery）
utf8mb4 / DATETIME(6) / DECIMAL 禁 float / tenant_id DEFAULT 0 入唯一键最左。
- `material_issue`(id/tenant_id/doc_no[uk]/work_order_doc_no[idx]/warehouse_id/remark/status/reversal_of_id/reversed_by_id/审计4)
- `material_issue_line`(id/tenant_id/material_issue_id/line_no/product_id/required_qty DECIMAL(18,6)/quantity DECIMAL(18,6)/unit_id/issued_cost DECIMAL(18,2) NULL；uk tenant_id,material_issue_id,line_no)
- `material_return`(同 issue 头 + material_issue_doc_no)
- `material_return_line`(product_id/quantity/unit_id/returned_cost DECIMAL(18,2)/可选 src_issue_line_no)
- **加宽 inventory_transaction.txn_type VARCHAR(16)→(32)**（V28 内 ALTER）：原 16 容不下新增枚举 `PRODUCTION_RETURN`（17 字符）；流水类型按 name() 存字符串无 CHECK 约束，加宽兼容现有值并为后续生产流水预留。〔修正初稿"无需改流水表"——该假设错误，CI 真库 `Data too long for column 'txn_type'` 暴露〕

## 5. REST + 权限（类级 @PreAuthorize('production:material')）
- /api/production/material-issues：POST 建单 / {docNo}/approve|post|cancel / GET 查询·{docNo}（受控）
- /api/production/material-returns：POST / {docNo}/approve|post / GET（受控）
- GET /api/production/kitting-check?workOrderDocNo=&warehouseId=（独立 KittingCheckController 护 production:material，避 WorkOrderController 类级 production:wo 冲突）
- DTO 金额/数量 toPlainString、@NotNull/@DecimalMin、错误体 {"error":...}；ProductionExceptionHandler +MaterialIssue/ReturnNotFound→404、InsufficientStockException→409。
- AppService 直接标 @Transactional（做跨库存编排，照 SalesDeliveryAppService，不另建 Transactional 包装类）。

- app @Tag(integration-db)：端到端领料过账真扣 inventory_balance + 写 PRODUCTION_ISSUE 流水 + 移动加权、库存不足回滚无残留、退料反向入库金额守恒、MaterialIssueApiPermissionTest 无权 403、InventoryTxnType.values() 若有全量断言加新值通过。

## 7. 风险与遗留登记
R1 工单领料仓来源（工单 warehouseId 预留可空，本批领料单 header 显式指定/齐套 ?warehouseId=，T05 若工单必填生产仓再对齐）；R2 不预留库存（检查到领料间可能被占，post 强校验兜底）；R3 工单不回写已领量（聚合 material_issue 行查询，T06 再决定汇总字段）；R4 退料超退仅单单据维度校验（跨单累计不做）；R5 半成品只领单层（领到底层需求确认）；R6 领料不出 GL 凭证（留 T06，期间报表在制品/生产成本不反映领料）；R7 领料单不实现 COMPLETED→REVERSED 冲销（退料用独立单据替代）；R8 齐套/领料未做单位换算（BOM 子件单位假定=库存基本单位，与 MRP 的单位归一不对称；单位不一致时静默错算，登记后续与 MRP 单位归一对齐——本批简化）。

## 9. CI 真库集成测试暴露并修复（integration-db job，本地全反应堆构建结构性测不到）
本地 `mvn clean test` 默认排除 @Tag(integration-db)，故以下三处仅在 CI Testcontainers MySQL 暴露，均已修：
1. **DI 装配缺 StockChecker bean**：MaterialIssueFlowIntegrationTest.TestConfig 装配 CatalogInfraConfig（其 productService 依赖 StockChecker），但未提供该 bean → `NoSuchBeanDefinitionException`。修：TestConfig 补 `@Bean JdbcStockChecker stockChecker(JdbcTemplate)`（照 OpeningStockImportIntegrationTest 范式）。
2. **测试断言列名错误**：assertBalanceAmount 查 `SELECT total_amount FROM inventory_balance`（total_amount 实为 voucher 表列），真库报 `Unknown column`。修：改 `cost_amount`（V10 inventory_balance 真列名），共 2 处。
3. **txn_type 列宽不足**：见 §4 修正——VARCHAR(16) 容不下 PRODUCTION_RETURN（17 字符），V28 内 ALTER 加宽到 (32)。
> 教训：新增 InventoryTxnType 值后须核对 inventory_transaction.txn_type 列宽；端到端真库集成测试是发现"本地 Fake 掩盖的真库约束"的唯一闸门。
