# M5-T03 WO 生产任务单（工单）拆解与实现方案

> 路线图 §7 M5-T03（M 级）。本文是 T03 单一设计真源。
> 范围：工单主体 + 状态机（计划→下达→生产中→完工→关闭/冲销）+ 从 MRP 生产建议/手工创建 + 查询 + 冲销（状态层面）。
> 验收：工单状态合法流转推进、非法流转被拒；从 MRP PRODUCTION 建议建单数量正确。

## 0. 范围红线
- **做**：WorkOrder 头单据 + 状态机 + 手工/从建议建单 + 查询 + 作废/冲销（状态层面）+ REST + 权限。
- **不做**：领料齐套（T04）、报工/完工入库（T05）、成本归集（T06）、Agent 工具（T07）。`completedQty/bomVersion/routingVersion/warehouseId/计划日期` 字段预留，本批仅建单赋初值，无业务逻辑。

## 1. 关键设计裁定
1. **状态机复用 DocumentStatus 六态，不加 CLOSED**：WO 五业务态映射——计划=DRAFT、下达=APPROVED、生产中=EXECUTING、完工=COMPLETED（=关闭，本批无 T05 副作用差异）、冲销=REVERSED、作废=CANCELLED。不污染全局已稳定流转表（不破坏 Voucher/SalesOrder 等）。WO 覆写 `beforeTransition` **收紧**白名单（钩子只收紧不放宽）。CLOSED 若 T05 需区分，加 WorkOrder 内部 boolean 子状态，不动 DocumentStatus（登记）。
2. **纯头无子行**：物料行 T04 领料生成、工序行引用 Routing（T05）；本批头记 productId+plannedQty+unitId+版本/仓/来源引用即可。
3. **从建议建单**：入参 (mrpRunDocNo, productId)，从 MrpRun 找 type==PRODUCTION 的建议，netRequirement→plannedQty、baseUnitId→unitId；校验建议存在且 PRODUCTION、productId 有 active BOM。手工：productId+plannedQty+unitId（产品存在启用校验在 app 入口层）。同品多层级 PRODUCTION 建议取首条（登记消歧增强）。
4. **精度**：plannedQty/completedQty 一律 BigDecimal/DECIMAL(18,6)，建单守 plannedQty>0。
5. **冲销收紧为未投产可冲销**：PLANNED 走 `cancel`（作废）、RELEASED 走 `reverse`（冲销）——贴合既有单据"草稿作废/审核后冲销"口径。EXECUTING/COMPLETED→REVERSED 本批**否决**（有 T04/T05 实物/成本副作用，无法安全反向，待后续放开）。本批冲销**不动库存、不出凭证**（无副作用）。
6. **权限 production:wo（ADMIN/BOSS），查询同样受控**：工单含产量计划/来源 MRP 等经营敏感数据且来源是受控 MRP，与 MRP 同口径类级 @PreAuthorize 覆盖全端点。不引入 PRODUCTION 角色。
7. **Agent 工具留 T07**。

## 2. 领域模型（com.sjherp.domain.production，续建）
- `WorkOrder extends BusinessDocument implements AuditTarget`：id（回填）、productId、plannedQty(>0)、unitId、completedQty(初 0 预留)、bomVersion?/routingVersion?/warehouseId(预留)、mrpRunDocNo?(来源)、sourceType(MANUAL/MRP_SUGGESTION)、plannedStart/EndDate?、remark?；`create`(草稿 DRAFT，守门 plannedQty>0)、`restore`(不校验)、`assignId`；语义流转方法 `release`=approve / `start`=startExecution / `complete` / 作废用基类 cancel / 冲销用基类 reverse；覆写 `beforeTransition` 白名单。
- `WorkOrderSourceType{MANUAL, MRP_SUGGESTION}`、`WorkOrderService`（@Audited createManual/createFromSuggestion/release/start/complete/cancel/reverse + get/search，docNo=generate(DocumentNumberRule.of("WO"))）、`WorkOrderRepository`、`WorkOrderQuery`、`WorkOrderNotFoundException`。

## 3. 状态机白名单（beforeTransition，DocumentStatus 视角）
合法：DRAFT→APPROVED（下达）、DRAFT→CANCELLED（作废）、APPROVED→EXECUTING（开工）、EXECUTING→COMPLETED（完工）、APPROVED→REVERSED（下达后未投产冲销）。
否决（抛 IllegalStateTransitionException）：DRAFT→EXECUTING/COMPLETED/REVERSED、APPROVED→COMPLETED、EXECUTING→REVERSED、COMPLETED→REVERSED、任何终态→任何态。（基类本允许 EXECUTING/COMPLETED→REVERSED，WO 收紧否决之。）

## 4. 迁移 V27__work_order.sql（单表，照 V14 头表 + V26 精度）
`work_order`：id PK / tenant_id DEFAULT 0 / doc_no(WO-) / product_id / planned_qty DECIMAL(18,6) / completed_qty DECIMAL(18,6) DEFAULT 0 / unit_id / bom_version INT NULL / routing_version INT NULL / warehouse_id NULL / source_type VARCHAR(20) / mrp_run_doc_no VARCHAR(64) NULL / planned_start_date DATE NULL / planned_end_date DATE NULL / status VARCHAR(16) / reversal_of_id / reversed_by_id NULL / remark VARCHAR(500) NULL / 审计四列。`uk_work_order_doc_no(tenant_id,doc_no)` + idx product/status/mrp。DECIMAL 禁 float，无物理 FK（照既有）。collation 与同期迁移对齐（建单前核对）。

## 5. REST + 权限（类级 @PreAuthorize('production:wo')，/api/production/work-orders）
POST（手工建单）/ POST /from-suggestion / POST /{docNo}/release|start|complete|cancel|reverse / GET（分页 productId·status 过滤）/ GET /{docNo}（404）。BigDecimal toPlainString()、CurrentUser.operator()。ProductionExceptionHandler 补 WorkOrderNotFound→404、IllegalStateTransitionException→409（与既有单据口径核对）。

## 7. 风险与遗留登记
R1 CLOSED 子状态（T05 区分完工/关闭时加内部 boolean）；R2 同品多层级 PRODUCTION 建议取首条（消歧增强）；R3 投产后冲销（EXECUTING/COMPLETED→REVERSED 待 T04/T05/T06 反向后放开，本批否决无副作用）；R4 查询权限受控（备选登录即可）；R5 Agent 工具留 T07；R6 V27 collation 核对；R7 IllegalStateTransitionException HTTP 映射（409，与既有单据口径对齐）；R8 bomVersion/routingVersion 仅存引用不校验 active（T04/T05 再校）。
