# M4-T05 月末结转与关账流程 拆解与实现方案

> 路线图 §6 M4-T05（L 级，**beta 退出标准核心**）。本文是 T05 的单一设计真源，实现严格据此。
> 范围（路线图四步）：**存货成本结转检查 → 损益结转 → 试算平衡 → 关账**；向导式（前端 precheck 预检）+ Agent 引导式（HITL 工具）两种入口。
> 验收：**完整模拟一个月业务后关账成功**（真库集成：采购→入库→应付→付款 + 销售→出库→应收→收款 → 关账 → 损益类归零、本年利润=毛利、账期 CLOSED、再过账被拒）。
> **不做**（登记延后）：维护型 `account_period_balance` 期末冻结表（T01 §8 决策 2 原列 T05；真正消费者是 T06 资产负债表/利润表，随 T06 协同设计 opening 结转语义）；年末 4103→4104 利润分配年结（年结非月结）；结转损益凭证的红冲与重开后重结（依赖 T07 统一冲销）。

## 0. 与既有基建的衔接（已读真源，勿凭记忆）

| 既有能力 | 位置 | T05 如何用 |
|---|---|---|
| 试算平衡/科目余额派生 | `VoucherService.trialBalance(period)` → `List<AccountBalance>(code, totalDebit, totalCredit)`（仅已过账 APPROVED 凭证行 SUM，按 code 升序） | 取损益类科目本期净额，算结转分录；关账后做 Σ借==Σ贷 断言 |
| 自动凭证生成流程 | `AutoVoucherService.generate(...)`：金额≤0 跳过 → `findBySourceDocNo` 幂等 → 账期保障 → `createFromSource` → `post` | 结转凭证复用同一流程骨架（来源类型 PERIOD_CLOSING、来源单号=账期键） |
| 凭证唯一写入口 | `VoucherService.createFromSource(docNo, period, voucherDate, summary, sourceType, sourceDocNo, lines, operator)` + `post(docNo, operator)` | 结转凭证经此建+过账（借贷平衡由 `Voucher.create` 强制，关账守卫由 `post` 强制） |
| 关账原语 | `AccountingPeriodService.close(period, operator)`（T01「只改状态」OPEN→CLOSED，@Audited） | T05 在其上编排完整流程，最后一步调它 |
| 关账守卫 | `VoucherService.post` 校验账期 OPEN，否则抛 `PeriodClosedException` | 结转凭证必须在账期 **仍 OPEN** 时过账，故「结转→断言→关账」严格此序 |
| 一致性检查 | `ConsistencyCheckService.check()` → `ConsistencyReport`（全库十条勾稽，ERROR/WARN） | 结转前闸门：有 ERROR break 即拒绝关账 |
| 凭证号 | `DocumentNumberGenerator.generate(VOUCHER_RULE=VCH, YearMonth)`（按凭证日期年月段计序） | 结转凭证号 VCH-yyyyMM-序号 |
| 科目类别 | `AccountService.get(code).getType()`：`AccountType.PROFIT_LOSS`（损益）、`getBalanceDir()` | 识别损益类科目（仅 PROFIT_LOSS 参与结转，COST 不结转——成本类期末转库存/WIP，留 M5） |

**预置科目（V19 已就位）**：损益类 = 收入侧 `6001 主营业务收入 / 6051 其他业务收入 / 6111 投资收益 / 6301 营业外收入`（CREDIT），费用侧 `6401 主营业务成本 / 6402 其他业务成本 / 6403 税金及附加 / 6601 销售费用 / 6602 管理费用 / 6603 财务费用 / 6711 营业外支出 / 6801 所得税费用`（DEBIT）；结转目标 `4103 本年利润`（EQUITY/CREDIT）。**T05 不硬编码损益科目清单**——按 `AccountType.PROFIT_LOSS` 动态识别（新增损益科目自动纳入），仅 `4103` 作为结转目标常量。

**无新增数据库迁移**：结转损益是一张普通凭证，复用 `voucher`/`voucher_line`。

## 1. 损益结转算法（财务核心，必须精确；BigDecimal 全程，2 位 HALF_UP）

账结法（月结），对账期 `P` 生成**一张**结转损益凭证。遍历 `trialBalance(P)`：

```
revenueSum = 0; expenseSum = 0; lines = []
for bal in trialBalance(P):
    acc = accountService.get(bal.accountCode)
    if acc.type != PROFIT_LOSS: continue            // 仅损益类参与结转
    net = bal.totalDebit - bal.totalCredit          // = AccountBalance.netBalance()
    if net == 0 (compareTo): continue               // 本期无发生额，跳过
    if net > 0:                                      // 费用类（借方净额）→ 贷该科目冲平
        lines += creditLine(acc.code, net)
        expenseSum += net
    else:                                            // 收入类（贷方净额）→ 借该科目冲平
        lines += debitLine(acc.code, -net)
        revenueSum += (-net)
// 本年利润 4103 两腿（各 >0 才出行，避免 0 额行违反 VoucherLine「恰一方>0」）
if revenueSum > 0: lines += creditLine("4103", revenueSum)   // 收入转入本年利润（贷增）
if expenseSum > 0: lines += debitLine("4103", expenseSum)    // 费用转入本年利润（借减）
```

**平衡自证**：Σ借 = Σ(收入冲平借=revenueSum) + (4103借=expenseSum) = revenueSum+expenseSum；Σ贷 = Σ(费用冲平贷=expenseSum) + (4103贷=revenueSum) = expenseSum+revenueSum。**恒等** ✓。
**净利润** netProfit = revenueSum − expenseSum（4103 净额：贷 revenueSum − 借 expenseSum = 净利润，正=盈利贷余）。
**边界**：
- 仅收入（expenseSum=0）：行 = [各收入借, 4103贷 revenueSum]，≥2 行平衡 ✓；
- 仅费用：[各费用贷, 4103借 expenseSum] ✓；
- 损益全无发生额（revenueSum=expenseSum=0）：**不生成结转凭证**（无金额无凭证，同 AutoVoucherService signum≤0 语义），账期照常可关；
- 盈亏两平（revenueSum=expenseSum>0）：4103 同时出借、贷两行（不同行号、各单边），合法且审计透明（毛额展示）。

结转后 `trialBalance(P)` 中每个损益科目本期 Σ借==Σ贷（净额归零），4103 承接净利润——这是**关账后损益归零**的来源（关账断言据此）。
**voucherDate**：取账期末日（`YearMonth.from(P).atEndOfMonth()`），落在账期 P 内（满足 `VoucherService.create` 日期校验）。摘要：`"期末结转损益 " + P`。

## 2. 应用层（`com.sjherp.app.gl`）

### 2.1 PeriodCloseService（@Service，月末结转关账编排器，全系统最高风险路径之一）
注入：`VoucherService`、`AccountService`、`AccountingPeriodService`、`ConsistencyCheckService`、`DocumentNumberGenerator`。

```java
/** 关账可行性预检（只读，向导/Agent 引导展示用，不写库、不抛业务异常）。 */
@Transactional(readOnly = true)
public PeriodCloseReadiness precheck(String period);

/** 执行月末结转关账（验收核心，单一 @Transactional 原子）。 */
@Transactional
public PeriodCloseResult close(String period, String operator);
```

**`close(period, operator)` 严格步序（任一失败整事务回滚，不留半结转/半关账）**：
1. **账期 OPEN 校验**：`accountingPeriodService.get(period)`（不存在→404）；非 OPEN → 抛 `PeriodCloseBlockedException`（已关账不可重复关）。
2. **重结防护（幂等/安全）**：`voucherService.findBySourceDocNo(period)` 非空 → 抛 `PeriodCloseBlockedException`（"账期已存在结转损益凭证 X；重开后重新关账须先冲销原结转凭证，统一在 M4-T07"）。因 close 原子，正常路径下账期 OPEN 时不会有结转凭证；命中即重开后重结场景，**硬拒不静默重复**（保数据模型不破碎）。
3. **结转前一致性闸门（"存货成本结转检查"）**：`consistencyCheckService.check()`；筛 `ERROR` 级 break，非空 → 抛 `PeriodCloseBlockedException`（携带 break 摘要清单）。`WARN`（如三单数量越界）不阻塞。理由：账实/勾稽不平时绝不关账（CLAUDE.md 原则 4，不静默；移动加权 COGS 已实时入账，故"存货成本结转检查"=结转前存货账实/成本勾稽校验，非周期盘存制的成本搬运）。
4. **损益结转**：按 §1 算法构造结转凭证行；若有损益发生额 → `createFromSource(docNo, period, 期末日, 摘要, PERIOD_CLOSING, period, lines, operator)` 建草稿 → `post`（**账期仍 OPEN，过账通过**）。无损益发生额则跳过（closingVoucherDocNo=null）。
5. **试算平衡断言**：重取 `trialBalance(period)`；断言 Σ全部借 == Σ全部贷（防御性，恒成立）；断言所有 `PROFIT_LOSS` 科目本期净额=0（结转完整性）。不成立 → 抛 `IllegalStateException`（结转逻辑缺陷兜底，回滚）。
6. **关账**：`accountingPeriodService.close(period, operator)`（OPEN→CLOSED）。
7. 返回 `PeriodCloseResult`。

**`precheck(period)`**（只读，不写不抛）：算 §1 结转预览（不过账）+ 跑一致性 break 清单（ERROR/WARN 分列）+ 试算平衡 Σ借/Σ贷 + 账期态 + 是否已存在结转凭证；`closeable = isOpen && 无既存结转凭证 && 无 ERROR break`。供前端向导展示与 Agent 引导。

### 2.2 DTO / 异常
- `PeriodCloseReadiness`（record）：period、status（OPEN/CLOSED）、closeable、alreadyClosed（已存在结转凭证）、consistencyErrors（List<String> 摘要）、consistencyWarnings（List<String>）、closingPreviewLines（List<结转行预览：accountCode/accountName/debit/credit 字符串>）、totalRevenue、totalExpense、netProfit、trialBalanceDebit、trialBalanceCredit（金额一律 `toPlainString`）。
- `PeriodCloseResult`（record）：period、closingVoucherDocNo（可空）、totalRevenue、totalExpense、netProfit、trialBalanceDebit、trialBalanceCredit、closedBy、closedAt（金额字符串）。
- `PeriodCloseBlockedException extends IllegalStateException`：携 `List<String> reasons`；→ HTTP 409。`GlExceptionHandler` 加映射（体含 reasons 列表，便于向导/Agent 复述为何不能关账）。

### 2.3 REST（扩展 `GlPeriodController`，权限复用 `finance:period`，**不新增权限点**）
- **改写** `POST /api/gl/periods/{period}/close`：由直调 `AccountingPeriodAppService.close`（T01 只改状态）**改为**调 `PeriodCloseService.close`（完整流程：闸门+结转+断言+关账）。返回体扩展为 `PeriodCloseResult`（含结转凭证号/净利润）。`finance:period` 不变。
- **新增** `GET /api/gl/periods/{period}/close-precheck` → `PeriodCloseReadiness`（查询登录即可，照账期查询不设权限点惯例；或 `finance:period`，与本控制器写口径一致取 `finance:period` 更稳——**裁定：precheck 设 `finance:period`**，关账族操作统一口径）。
- `AccountingPeriodService.close` 仍保留（领域原语，被 PeriodCloseService 末步调用）；`AccountingPeriodAppService.close` 不再被 REST 直接使用（保留供测试/兼容，或标注由 PeriodCloseService 取代——**裁定：保留方法但 REST 改走 PeriodCloseService**）。

## 3. Agent 工具（`com.sjherp.app.tool.gl`，路线图 §6 T05「Agent 引导式入口」，复用 `finance:period`）
照既有 HITL 工具范式（`PostPurchaseInvoiceTool` 等）：
- `precheck_period_close`（NORMAL，requiredPermission=`finance:period`）：入参 period；调 `PeriodCloseService.precheck`；返回可读 readiness（是否可关账、ERROR/WARN 清单、结转预览、净利润、试算平衡）。供 Agent 先给用户看"能不能关、关了什么样"。
- `close_accounting_period`（**HIGH**，requiredPermission=`finance:period`）：入参 period；description 复述要点（将对账期 X 跑结转前一致性检查、生成并过账结转损益凭证、把损益类结转入本年利润 4103、随后关账，关账后该期禁止再过账，**不可逆**，系统将请求确认）；调 `PeriodCloseService.close`；异常映射 `ToolResult.fail`（PeriodCloseBlocked/PeriodClosed/NotFound/IAE）。
- `DomainToolConfig` 注入 `PeriodCloseService` + 注册 2 工具 + 更新计数注释（常驻 50→52）；`HighRiskToolPermissionTest` 基线 +1 HIGH（close_accounting_period），下界相应上调。

## 5. 风险与决策
1. **结转目标仅 PROFIT_LOSS**：COST（5001/5101）期末不转 4103（成本类随完工转库存/WIP，属 M5-T06 生产成本结转）；本期若 COST 有余额，留存为在产/库存成本，不进损益。登记：M5 接生产后复核 COST 期末处理。
2. **结转凭证幂等**：来源类型 PERIOD_CLOSING + 来源单号=账期键（6 位，不与业务单号 PI-/RCPT- 等冲突），`findBySourceDocNo` 查重；`uk_voucher_source` 物理兜底（注：现有 uk 仅 source_doc_no，T02 为 V20 `uk_voucher_source`——结转沿用，每账期至多一张结转凭证）。
3. **重开后重结**：T05 硬拒（既存结转凭证则 close 抛 blocked），正确处理=先红冲原结转凭证再重结，依赖 M4-T07 统一冲销，登记延后。
4. **一致性闸门全库口径**：`check()` 为全库十条勾稽；有任何 ERROR 即拒关账（最稳，不在脏数据上关账）。可能因他期/无关 ERROR 阻塞本期关账——小企业月度节奏下可接受（先治脏再关账）。登记：按账期收敛闸门为后续优化。
5. **account_period_balance 期末冻结表延后到 T06**：已关账期不可再过账，其派生余额天然稳定（trialBalance 仍可派生）；冻结表是优化 + 期初结转载体，与资产负债表（T06）协同设计 opening 结转语义更内聚。本批不做，登记。
6. 全程 BigDecimal/DECIMAL(18,2)、tenant_id=0、UTC；写经领域服务/AppService；@Audited 覆盖（结转凭证 create/post、period.close 均已带审计）。
