# SJHERP 安全基线（M8-T03）

面向**小企业私有部署**：能用浏览器安全地打开系统，挡住常见撞库和误配，并说清楚聊天会不会把业务数据送到第三方大模型。不是云上 SaaS 加固，也不是 WAF / SSO（那些留给后续刀）。

一键安装与升级仍看 [部署-一键安装.md](./部署-一键安装.md)；备份看 [部署-备份恢复.md](./部署-备份恢复.md)。

## 1. HTTPS

默认 `SJHERP_TLS_MODE=self-signed`：安装时在 `deploy/certs/` 生成自签证书，nginx 在 **443** 终止 TLS；**80** 除 `GET /api/health`（容器探活）外 301 到 HTTPS。冒烟脚本对自签证书使用 `curl -k`。

| 模式 | `.env` | 证书 | 适用 |
|---|---|---|---|
| 自签（默认） | `SJHERP_TLS_MODE=self-signed` | 安装脚本生成 `deploy/certs/fullchain.pem` + `privkey.pem` | 内网 / 先跑起来 |
| 正式证书 | `SJHERP_TLS_MODE=custom` | 把 Let's Encrypt 或机构证书放到上述两个文件名 | 有域名的公网 |
| 仅 HTTP | `SJHERP_TLS_MODE=off` | 不需要 | 本机开发；浏览器不走 HTTPS |

自签证书**浏览器会告警**，属预期。内网可点「继续访问」；不要把自签证书当公网方案。

### 接入 Let's Encrypt（有公网域名时）

在宿主机（示例，域名换成你的）：

```bash
sudo apt-get install -y certbot
sudo certbot certonly --standalone -d erp.example.com
sudo cp /etc/letsencrypt/live/erp.example.com/fullchain.pem deploy/certs/fullchain.pem
sudo cp /etc/letsencrypt/live/erp.example.com/privkey.pem deploy/certs/privkey.pem
sudo chown "$USER":"$USER" deploy/certs/*.pem
chmod 600 deploy/certs/privkey.pem
```

`deploy/.env`：

```
SJHERP_TLS_MODE=custom
```

然后 `./deploy/upgrade.sh --skip-git --skip-backup`。证书续期后重新复制这两个文件并 `docker compose ... restart nginx`。

HSTS 默认**不加**（自签 + IP 访问时 HSTS 会把浏览器锁死）。上了可信证书且固定域名后，可在 `deploy/nginx/nginx-tls.conf` 的 443 server 自行加：

```
add_header Strict-Transport-Security "max-age=31536000" always;
```

端口：`SJHERP_HTTP_PORT`（默认 80）、`SJHERP_HTTPS_PORT`（默认 443）。防火墙放行二者。CI / 探活仍打 HTTP `/api/health`（容器内），对外冒烟走 `base_url()`（HTTPS 时带 `-k`）。

## 2. 密码策略

领域层 `PasswordPolicy` + 管理 API `@StrongPassword` 双守门：

- 8–64 位
- 至少各一个**大写字母、小写字母、数字**
- 拒绝常见弱口令（如 `Admin123`）以及与登录名相同
- **不强制特殊字符**——`install.sh` 生成的是 `Adm` + 12 位十六进制

管理员重置：`POST /api/identity/users/{id}/password`（仅 ADMIN）。  
本人改密：`POST /api/auth/password`（须旧密码）。

## 3. API 限流

两层，默认同口径，可用环境变量调：

| 入口 | 默认 | 环境变量 |
|---|---|---|
| `POST /api/auth/login`、`POST /api/auth/password` | 20 次/分钟/IP | `SJHERP_RATE_LIMIT_LOGIN` |
| `POST /api/chat/sessions/{id}/messages` | 60 次/分钟/IP | `SJHERP_RATE_LIMIT_CHAT` |
| 总开关 | 开 | `SJHERP_RATE_LIMIT_ENABLED` |

应用层返回 `429 {"error":"请求过于频繁，请稍后再试"}`；nginx 对登录/聊天同样 `limit_req`。工作台列表刷新不限。

## 4. 密钥放哪里

| 机密 | 位置 | 是否进库 |
|---|---|---|
| MySQL / JWT / 初始 admin 密码 / LLM API Key | `deploy/.env`（git 忽略） | 否 |
| TLS 私钥 | `deploy/certs/privkey.pem`（git 忽略） | 否 |
| 用户登录密码 | `sys_user.password_hash` | 只存 BCrypt，不明文 |
| GitHub / 开发者 Agent token | 配置项，默认关闭 | 否 |

**没有**把 LLM Key 落到 MySQL。`AesGcmSecretEncryptor` 已实现，留给「以后若必须把密钥写入数据库」；当前守卫测试 `SensitiveSchemaGuardTest` 禁止 Flyway 出现 `api_key` 一类列。不要对单据金额做全库加密表演。

## 5. LLM 数据出境（Q-7）

聊天默认 provider 是 DeepSeek（`https://api.deepseek.com`）。一旦配置了 `SJHERP_LLM_API_KEY` 且目标被判定为公网第三方：

- `GET /api/auth/me` 返回 `llmEgress`（`thirdParty`、`destination`、中文 `notice`）
- 聊天页顶部黄条展示该告知

判定启发式：host 为 localhost / 127.0.0.1 / `*.local` / RFC1918 内网 → 本地；其余公网 HTTPS → 第三方。

可选：

```
# 发给模型前打码手机号 / 邮箱 / 18 位身份证（金额、单号不打，否则 Agent 做不了进销存）
SJHERP_LLM_REDACT=true

# 禁止 chat provider 指向公网（启动失败）。配合本地 Ollama：
SJHERP_LLM_LOCAL_ONLY=true
```

本地模型示例（需自备 Ollama，本 compose 不含）：

```
# application-local 或覆盖 sjherp.llm.providers.deepseek.base-url
# 更干净的做法：增加一个 ollama provider，把 sjherp.llm.roles.chat 指过去
```

`deploy/.env` 可先把 `SJHERP_LLM_API_KEY` 留空：聊天走占位 Agent，**传统工作台仍可用**，也没有任何业务数据出网。

未配置 Key 或 `sjherp.agent.mode=placeholder` 时不展示出境条。

## 6. 本刀审查结论（全库安全扫描）

**P0（默认可利用）**：未发现。生产姿态 `local/dev` 未激活时 swagger 保持 401；compose 另设 `SJHERP_FORBID_DEV_PROFILE=true`，误开 dev profile 会启动失败。

**P1 已修**：

- `GET /api/gaps` 任意登录角色可读全部缺口场景 → 现与写接口同权 `gap:triage`
- 库存/报表关键字 `LIKE` 未转义 `%` `_`（非注入，属匹配放大）→ `SqlLikes`
- 聊天 SSE 把未预期 `RuntimeException.getMessage()` 回给浏览器 → 固定文案，细节只打日志

**残留（不在本刀改业务口径）**：

- 若干查询「登录即可」（应付列表、库存余额/成本、部分报表）——权限矩阵长期约定；收紧会拆仓管/销售现有工作台
- ADR-002：`tenant_id` 预留、v1.0 单租户，部分 `UPDATE`/`findById` 未带租户条件；SaaS 多租户另开刀
- 登录无账号锁定（有 IP 限流）；无密码有效期、无历史密码
- CORS 仅放行 `http://localhost:5173`（开发 Vite）；生产同域走 nginx，不需要 `*`
- 无 Spring Actuator 暴露
- 全站 WAF、SSO、监控告警 → M8-T04 及以后

SQL：业务写路径走 JdbcTemplate 参数绑定，未发现用户输入拼进 SQL。MyBatis 未使用。
