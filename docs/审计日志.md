# 审计日志（M2-T07）

> CLAUDE.md 原则 3 的落地：每一笔业务数据变更必须有审计记录——谁（用户/哪个 Agent）、何时、依据什么指令（Agent 操作关联会话）、改了什么。本文与代码同步演进，代码为准。

## 设计决策

### 审计点：领域 Service 写方法（不是 Controller，也不是 SQL 层）

- **为什么不是 Controller**：Agent 工具与 REST API 共用同一个领域 Service Bean（CLAUDE.md 原则 1：领域服务是写操作唯一入口）。在 Service 边界做审计，单点标注天然覆盖人工与 Agent 两条路径；Controller 边界则要给每个入口各写一遍，且 Agent 工具不经过 Controller。
- **为什么不是 SQL/触发器层**：SQL 层只有"哪行变了"，没有业务语义（一次 `customer.disable` 是一次行 UPDATE，但审计要的是"谁停用了哪个客户"）。审计动作以业务意图命名（`product.create` / `customer.disable` / `user.assign_roles`）。

### 实现方式：方案 a（AOP 切面 + @Audited 注解）为主，领域事件接线附带完成

- **a) Spring AOP 切面（采用，主路径）**：`@Audited(action, targetType)` 标在领域 Service 公有写方法上，app 层 `AuditAspect` 拦截（spring-boot-starter-aop，Boot 生态）。理由：侵入小（领域层只多一个纯 Java 注解，零 Spring 依赖）、覆盖快（一个切面管所有已装配 Service）、与既有"domain 纯 Java + app 显式装配"架构吻合。
- **b) 领域事件（本任务附带接线，面向 M3 单据）**：`DomainEventPublisher` 端口（M2-T01 留的待办）在 app 装配 `SyncDomainEventPublisher`（同步分发），`AuditDomainEventListener` 订阅 `DocumentStatusChangedEvent` 落 audit_log（action=`document.status_changed`）。M3 单据领域服务注入该发布器后，状态流转自动获得审计，不必逐方法标注。
- 不二选一的原因：档案/用户类写操作没有领域事件（不值得为审计专门造事件），切面是最低成本全覆盖；而单据状态机已天然发事件，订阅即得。两条通道写同一张表。

### 操作人与会话关联

- 操作人沿用全仓约定：**人工 = 登录名**（`CurrentUser.operator()`），**Agent = `agent:<userId>`**（`ArchiveToolSupport.operator()`）。切面从方法的 `operator` 参数取值（全仓 Service 写方法均带该参数，编译开 `-parameters`），前缀即可区分人工/Agent。
- **session_id**：`ChatService.handleMessage` 在处理消息前设置 `AuditContext`（ThreadLocal，工具同步执行在同一线程，ADR-001），finally 清除；Agent 写操作由此关联到来源会话（"依据什么指令"可经会话回放追溯）。人工 REST 路径为空。

### 失败兜底（与 invocation listener 同哲学）

审计取材/落库的任何异常：只 WARN 日志 + `AuditMetrics` 计数器（可发现），绝不阻塞业务返回。审计插入用 REQUIRES_NEW 独立事务，与业务事务双向隔离。业务方法抛异常时不记审计（写操作未发生）。

## 表结构（V9__audit_log.sql）

`audit_log`：id、tenant_id（ADR-002 恒 0）、operator（含 agent: 前缀）、action、target_type、target_id、target_code、summary、session_id（可空）、created_at（UTC）。索引：`(operator, created_at)`、`(target_type, target_id)`。只插入不更新。

## 变更摘要（summary）口径与已知限制

- 聚合根实现 `AuditTarget`（纯 Java 接口）：`auditTargetId / auditTargetCode / auditSummary`（关键字段中文摘要，**绝不含密码/哈希**）。
- create / delete：记关键字段快照（delete 为删除前快照，CategoryService/UnitService 的 delete 已改为返回快照并补 operator 参数）。
- update / enable / disable / assignRoles 等按 id 写的方法：切面在执行**前**反射调 Service 的 `get(id)` 取变更前摘要，与返回值的变更后摘要拼为 `变更前[...] → 变更后[...]`（前后相同则只记 after，如改密操作）。
- **限制（TODO）**：摘要是"关键字段快照级"对比，不是字段级精确 diff（例如同时改名称和电话，需人工对比两段摘要找差异）；before 快照多一次仓储读（档案量级可忽略）。完整字段级 diff（逐字段 old→new）留待审计查询界面需要时实现。
- 防御性截断 2000 字符。

## 查询 API

`GET /api/audit-logs?operator=&action=&targetType=&targetId=&from=&to=&page=&size=`（from/to 为 ISO-8601 时刻），**ADMIN/BOSS 限定**（审计含全员操作轨迹），时间倒序分页；参数非法 400 `{"error"}`，越权 403 统一文案。审计查询**界面**（M2-T07 验收提及）随 X-4 前端任务补充，API 已就绪。
