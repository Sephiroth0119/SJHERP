# 业务文档：进销存报表（M3-T12）

> 面向业务与知识库。本文说明四张**只读**进销存报表：库存余额表、收发存汇总、采购入库明细、销售出库明细。报表是查询产出，**只读不写库**（CLAUDE.md「报表只读查询除外」）——全部经只读 SQL（`ReportQueryDao`），绝不绕过领域模型写数据。

## 1. 定位

进销存跑通后（M3-T01~T11），业务需要把账"看出来"。本里程碑交付四张报表，回答四个最常问的问题：

| 报表 | 回答 | 端点 |
|---|---|---|
| 库存余额表 | 现在每个仓库每个商品有多少货、值多少钱、加权单价多少？库存总值多少？ | `GET /api/reports/inventory-balance` |
| 收发存汇总 | 某个期间，每个商品期初多少、收了多少、发了多少、期末多少？ | `GET /api/reports/stock-movement-summary` |
| 采购入库明细 | 某期间向谁、买了什么、入库多少、花了多少钱？总进货额？ | `GET /api/reports/purchase-detail` |
| 销售出库明细 | 某期间卖给谁、什么、出库多少、卖了多少钱、成本多少、毛利多少？ | `GET /api/reports/sales-detail` |

## 2. 四张报表口径

### 2.1 库存余额表
- 数据源：`inventory_balance`（库存余额唯一真源两列 `quantity` / `cost_amount`）。
- 行：每个(仓库,商品)一行；**加权单价**为派生值（金额÷数量，6 位 HALF_UP，数量≤0 显「—」），不冗余存储。
- 合计：**库存总值** = Σ结存金额（跨商品可加）。数量跨商品/单位不可加，故不给数量合计。
- 过滤：仓库 / 商品 / 关键字（商品名或编码）/ `includeZero`（默认含双零历史行，置 false 隐藏）。
- 说明：与 `GET /api/inventory/balances` 同源，报表版额外给库存总值与 includeZero 开关。

### 2.2 收发存汇总
- 数据源：`inventory_transaction`（库存流水，带符号）。
- 期间：`fromDate` / `toDate` **必填**，业务日闭区间（内部转半开 `[from 00:00, (to+1) 00:00)` UTC 墙钟）。
- 每行（仓库,商品）：**期初**(数量/金额) + **收**(期内入向) + **发**(期内出向) + **期末**(数量/金额)。
  - 期初 = Σ(`created_at` < from) 的流水；
  - 收 = Σ期内 quantity>0（金额同口径 total_cost>0）；发 = Σ期内 quantity<0 取正（金额 total_cost<0 取正）；
  - 期末 = Σ(`created_at` < (to+1)) 的流水。
- **tie-out 恒等式**：`期初 + 收 − 发 = 期末`（数量、金额各自恒成立，按构造保证；集成测试逐行断言）。
- 维度集 = 期末前有任意流水的(仓库,商品)；合计只给金额（期初/收/发/期末金额，可加）。

### 2.3 采购入库明细
- 粒度：**采购入库单行**（实际进货 = 命中库存的口径），联 入库单→采购订单→供应商、仓库、商品。
- 列：入库单号 / 收货日 / 采购订单号 / 供应商 / 仓库 / 商品 / 数量 / 收货单价 / 入库金额 / 状态。
- 期间：按业务日 `receipt_date`（闭区间，可选）。过滤：供应商 / 商品 / 仓库 / 状态 均可选。
- 合计：**总进货额** = Σ入库金额。

### 2.4 销售出库明细
- 粒度：**销售出库单行**，联 出库单→销售订单行（取售价）→客户、仓库、商品。
- 列：出库单号 / 出库日 / 销售订单号 / 客户 / 仓库 / 商品 / 数量 / 售价 / **销售额** / **COGS** / **毛利** / 状态。
  - 售价 = 销售订单行单价；销售额 = 数量×售价（2 位 HALF_UP，逐行 BigDecimal 现算）；
  - COGS = 出库行移动加权成本（未过账为「—」）；毛利 = 销售额 − COGS。
- 期间：按出库单**过账时间** `created_at`（半开区间，可选）——⚠️ 销售出库单 V17 无业务日字段，故用过账时间，与采购按 `receipt_date` 存在**口径差异**（已登记）。
- 合计：销售额 / 成本 / 毛利总计。**注意**：未过账行有销售额而无 COGS，会让毛利总计偏大；要精确毛利请加过滤 `status=COMPLETED`。

## 3. 精度与口径约定（CLAUDE.md 原则 5）
- 金额/数量/单价一律 `BigDecimal`，JSON 中以**字符串**承载（`toPlainString`），绝不用 JSON 数字——口径同库存查询与选项返回协议。
- 逐行金额（销售额/毛利/加权单价）在 DTO 层用 BigDecimal 现算；跨行合计用 DECIMAL 精确 SQL 聚合（MySQL DECIMAL 为精确十进制，非浮点）；正数场景 MySQL `ROUND(,2)` 等同 HALF_UP，逐行口径一致。
- **主表一律 LEFT JOIN**：报表是账务产出，绝不能因某维度档案缺失而**静默丢行**——宁可显示 null 名称也要暴露这一行（区别于业务查询的 INNER JOIN）。

## 4. 权限
| 报表 | 权限 | 理由 |
|---|---|---|
| 库存余额表 / 收发存汇总 | 登录即可 | 与库存查询 `/api/inventory/*` 一致 |
| 采购入库明细 | `purchase:order` | 沿用采购模块读权限 |
| 销售出库明细 | `sales:order` | 沿用销售模块读权限（含毛利） |

未新增权限点；分页统一钳制 `[1, MAX_SIZE=200]`，防一次拉全表。
