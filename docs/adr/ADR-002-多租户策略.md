# ADR-002：多租户策略 —— 私有部署优先，预留 tenant_id

- 状态：已接受（2026-06-11，对应路线图 Q-1）
- 决策人：产品负责人（路线图开工指令确认）

## 背景

SJHERP 面向小型企业。部署形态影响 M2 起所有表结构与权限模型：
SaaS 多租户需要从第一张表起做租户隔离（行级/库级），私有部署则单企业单实例。

## 决策

1. **v1.0 按私有部署交付**：单企业单实例（app + MySQL + Qdrant 一套），用 M8-T01 的一键部署脚本交付。
2. **所有业务表自创建起预留 `tenant_id BIGINT NOT NULL DEFAULT 0` 列**，并纳入唯一键/常用索引的最左前缀设计考量；应用层暂不读写该列（恒为 0），不做任何隔离逻辑。
3. 领域层、API 层不出现租户概念；未来若转 SaaS，隔离逻辑在持久层与认证层引入，领域代码不动。

## 理由

- 小企业客户对数据私有性敏感，私有部署是更顺的初期商业路径；
- 多租户隔离做错的代价（数据串号）违反"数据模型不破碎"原则，不在 v1.0 引入这个风险；
- 预留列的成本几乎为零，但避免了未来全量表结构迁移。

## 后果

- v1.0 运维成本随客户数线性增长（每客户一实例），M8-T01 的自动化部署质量变得关键；
- 已有表（agent_session、agent_message、gap_record 等）需在下一个迁移中补 tenant_id 列（任务并入 M2 首个迁移）。
