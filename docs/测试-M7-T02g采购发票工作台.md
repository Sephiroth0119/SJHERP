## 验收范围

- 采购模块保留供应商档案、采购订单和采购入库，新增仅 `purchase:invoice` 可见的采购发票页签。
- 列表、详情、创建、审核、过账只调用真实端点；不提供编辑、删除、草稿作废或 `reverse`。
- ACCOUNTANT 无需 `purchase:receipt`，仅凭 `purchase:invoice` 即可读取建单候选并完成新建。
- 候选端点只返回 `COMPLETED` 且仍有未开完行的入库单；DRAFT、REVERSED 和已开完入库单不可读取。
- `invoiceableOnly` 在 JDBC count 和分页之前以 `EXISTS(quantity > invoiced_qty)` 筛选并强制 `COMPLETED`；不在 Controller 拉全表或对已分页结果补救过滤，旧五参数 `PurchaseReceiptQuery` 构造器保持兼容。
- 创建从真实候选入库单选择并引用真实行号；请求体窄化为 `purchaseReceiptNo/invoiceDate/supplierInvoiceNo/remark/lines[receiptLineNo/quantity/amount]`。
- 数量、金额、已开票量和剩余可开票量均按字符串承载；JSON number 响应在 API 边界归一化，不做 JavaScript 浮点运算。
- 创建、审核、过账共享同步 in-flight 守卫；过账按钮旁和二次确认均明确说明回写已开票量、生成应付与会计凭证。
- 列表、详情、候选和供应商选择均有竞态隔离；同条件可重查；供应商、仓库和商品名称失败时诚实回退。
- 四个受保护文件 `README.md`、`docs/业务-进销存报表.md`、`docs/工程-自驱开发循环.md`、`docs/领域模型概览.md` 均未修改。
