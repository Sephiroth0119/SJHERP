## 验收范围

- 采购模块保留供应商档案和采购订单，新增仅 `purchase:receipt` 可见的采购入库页签。
- 列表、详情、创建、审核、过账只调用真实端点；不提供编辑、删除、草稿作废或红冲。
- WAREHOUSE 无需 `purchase:order`，仅凭 `purchase:receipt` 即可读取建单候选并完成新建。
- 候选端点只返回 `APPROVED` 且仍有未收行的订单；DRAFT、COMPLETED 和已收完订单不可读取。
- `receivableOnly` 在 JDBC count 和分页之前以 `EXISTS(quantity > received_qty)` 筛选；不在 Controller 拉全表或对已分页结果补救过滤。
- 创建从真实候选订单选择并引用真实行号，从真实启用仓库选择；请求体窄化为 `purchaseOrderNo/warehouseId/receiptDate/remark/lines[poLineNo/quantity/unitCost]`。
- 数量、单价、金额、已收量和未收量均按字符串承载；JSON number 响应在 API 边界归一化，不做 JavaScript 浮点运算。
- 创建、审核、过账共享同步 in-flight 守卫；过账有明确库存/凭证影响说明和二次确认。
- 列表、详情、候选和仓库请求均有竞态隔离；同条件可重查；引用名称失败时诚实回退。
