# 业务文档：期初数据导入（M2-T09）

> 面向业务与知识库。本文说明小企业上线 SJHERP 时，如何用 Excel 模板把**已有档案与期初库存**一次性导入系统，以及导入失败如何排错。

## 1. 为什么需要它

新系统上线第一痛点：手里已有几百个商品/客户/供应商、各仓还压着一批存货。逐条手敲不现实。期初导入提供 **Excel 模板下载 → 填写 → 上传校验导入** 的批量建账通道。导入是**建账期一次性管理动作**，走 REST 端点（不是聊天工具），由老板/管理员操作。

## 2. 本期范围（M2-T09 交付）

| 导入类型 | 模板 | 写入口 | 状态 |
|---|---|---|---|
| 商品档案 | 商品模板 | 商品领域服务 | ✅ |
| 客户档案 | 客户模板 | 客户领域服务 | ✅ |
| 供应商档案 | 供应商模板 | 供应商领域服务 | ✅ |
| 期初库存 | 期初库存模板 | `InventoryAdjustmentService.opening`（OPENING 类型，移动加权成本建账）| ✅ |
| 期初应收/应付 | — | — | ⏸ **暂缓到 M4** |

**期初应收应付为什么暂缓**：当前应收/应付账款只能由"销售发票过账""采购发票过账"产生（保证每笔应收应付都有单据来源、可勾稽）。直接为期初余额硬写一条应收/应付，会绕过这条铁律、破坏数据模型完整性（CLAUDE.md 原则 1/2）。正确做法是在 M4 财务模块提供"期初应收应付建账"的专门领域入口（与核销 M4-T03 同期），届时再补本导入项。本期**不做任何 hack 写库**。

## 3. 操作流程

1. **下载模板**：`GET /api/import/templates/{type}`（登录即可，无权限点）。`type` ∈ 商品/客户/供应商/期初库存。
2. **填写**：按模板表头逐列填写；编码、名称等必填列不能空。
3. **上传导入**：`POST /api/import/**`（需 `data:import` 权限：ADMIN/BOSS）。系统逐行校验后导入。

期初库存导入的每一行都经库存唯一写入口 `opening` 落账：生成一条 OPENING 流水 + 余额，单价×数量按移动加权口径入成本金额——与日常出入库共用同一套成本核算，账实从第一天起就一致。

## 4. 校验与失败处理（验收硬指标）

- **逐行校验**：每行独立校验（编码重复、单位/仓库/商品不存在、数量为负、金额格式非法等）。
- **失败行明确报错**：失败行返回**行号 + 具体原因**（如「第 5 行：单位『吨』不存在」「第 8 行：商品编码 SKU-001 重复」），用户据此修正后重传。
- **整体策略：全有或全无**。只要有任意一行校验失败，**整批回滚**（`ImportRejectedException` 触发事务回滚），不留半截脏数据——建账期宁可整批重来，也不接受"导了一半"的破碎状态。
- **操作人记登录名**（非 `agent:` 前缀）：导入是人工批量操作，审计如实记录操作人。

## 5. 注意事项

- 商品按**编码精确匹配**定位（编码优先、名称次之）；导入前确保编码规范唯一。
- 期初库存导入前，相关商品/仓库档案必须已存在（可先导档案再导库存）。
- 大文件：默认 multipart 限制对小企业期初文件通常够用；如行数极多可在 `application.yml` 调高 `spring.servlet.multipart` 限制。
