# M4-T04 收付款单 拆解与实现方案

> 路线图 §6 M4-T04（标 M，实为 L——含资金账户档案 + 收/付款两类单据 + 核销联动 + 现金侧凭证 + Agent HITL）。
> 本文是 T04 单一设计真源。依赖 M4-T03 核销引擎（docs/M4拆解-应收应付核销账龄.md）、M4-T02 AutoVoucherService、M4-T01 总账。
> **本质裁定（承 T03 §0）**：收付款单是 T03 核销引擎的**生产触发器**——过账时**同事务内**（a）逐行调 `SettlementService.settleReceivable/settlePayable` 冲减子账、（b）生成现金侧凭证（借银行/贷应收；借应付/贷银行）。核销与收现金是同一经济业务，故二者原子同事务，任一失败整单回滚。
> **高风险**：涉及资金与过账，Agent 侧建单/审核/过账各独立 HIGH 确认卡片（HITL）。

## 0. 子批拆分（L 任务，逐批 CI 绿）

- **T04a 现金/银行账户档案**（PaymentAccount master）：收付款的"钱从哪进/出哪个账户"主数据，映射到 GL 货币科目（1001/1002/1012）。docs 过账生成现金侧凭证须知道借/贷哪个 GL 科目，故 master 是 docs 的前置依赖，先做。
- **T04b 收款单 + 付款单**（CollectionReceipt / PaymentDisbursement）：header+分摊行 BusinessDocument；过账同事务内联动 T03 核销 + 现金侧凭证；REST。
- **T04c Agent HITL 工具 + 一致性勾稽**：收/付款 建/审/过账/查询工具（建·审·过账各独立 HIGH）+ ConsistencyCheckService 补核销 rollup 勾稽。

## 1. T04a 现金/银行账户档案（PaymentAccount master）

**完全照 warehouse 主数据范式**（domain Warehouse/WarehouseService/WarehouseRepository + infra Jdbc + app Controller + V4 DDL + DomainToolConfig 工具），仅字段与一处校验不同。

- **域** `com.sjherp.domain.fund`（新包）：
  - `PaymentAccountType` 枚举：`CASH("库存现金")` / `BANK("银行存款")` / `OTHER("其他货币资金")`。
  - `PaymentAccount`（`implements AuditTarget`，`ArchiveStatus` 状态 ENABLED/DISABLED，**非状态机**）：字段 id、code（唯一，沿用 warehouse 编号方式——自动编号 `DocumentNumberRule.of("FA")` → FA-yyyyMM-序号）、name、accountType、**glAccountCode**（映射的 GL 货币科目编码，如 1001/1002/1012）、bankName（可空，BANK 用）、accountNo（可空，银行账号）、status、审计四列。工厂 `create`/`restore`/`assignId`/`update`/`enable`/`disable`。
  - `PaymentAccountRepository` 端口：save / findById / findByCode(用于过账取 glAccountCode) / existsByCode / search(PaymentAccountQuery)。
  - `PaymentAccountService`（依赖 PaymentAccountRepository + DocumentNumberGenerator + **AccountRepository**[T01 gl 端口]）：create/update/enable/disable/get/search，均 @Audited。
    - **关键校验（唯一新逻辑）**：create/update 时 `glAccountCode` 必须是**已存在、启用、末级**的 GL 科目（`AccountRepository.findByCode` 非空 + isLeaf + enabled），且应为货币资金类（建议限定 1001/1002/1012 或 ASSET/DEBIT 末级——以"末级+启用"为硬校验，货币类为软约定写注释，避免过度耦合科目语义）。glAccountCode 非法 → IllegalArgumentException（→400）。
  - 异常：`PaymentAccountNotFoundException`。
- **infra**：`JdbcPaymentAccountRepository`（照 JdbcWarehouseRepository）。
- **app**：`PaymentAccountController`（/api/fund/accounts，照 WarehouseController；写 `finance:payment_account`、查询登录即可）；装配照 warehouse（service 走 config @Bean 或组件扫描，与 warehouse 一致）。
- **迁移 V22** `V22__payment_account.sql`（照 V4 warehouse DDL；tenant_id BIGINT 非 UNSIGNED 与全库一致；uk(tenant,code) + idx(tenant,name)）。
- **权限**：新增 `FINANCE_PAYMENT_ACCOUNT("finance:payment_account","资金账户档案")`，授 ADMIN/BOSS/ACCOUNTANT。
- **Agent 工具**（T04c 一并）：create_payment_account（NORMAL，建档）+ search_payment_accounts（NORMAL）。
- **测试**：域单测（create 校验 glAccountCode 末级/启用、enable/disable、唯一）、controller 切片、infra integration-db（CRUD 落库）。

## 2. T04b 收款单 / 付款单（核心财务联动）

**照 PurchaseInvoice header+lines 范式**（域聚合+行+service create/approve/post、infra Jdbc、app AppService 在 post 同事务调 AutoVoucher、REST）。

### 2.1 收款单 CollectionReceipt（域 `com.sjherp.domain.collection`）
- `CollectionReceipt extends BusinessDocument`（DRAFT→APPROVED→COMPLETED，post 走 startExecution→complete 一步，照 PurchaseInvoice）：header docNo（`RCPT-`）、customerId、paymentAccountId（收入哪个资金账户）、receiptDate、remark、lines。
- `CollectionReceiptLine`：lineNo、receivableId、allocatedAmount（>0，2 位）。`CollectionReceiptLineInput` 入参 record。
- `totalAmount()` = Σ allocatedAmount。create 校验 ≥1 行、行号唯一、各 allocatedAmount>0。
- `CollectionReceiptService`：create（DRAFT）/approve（APPROVED）/post（→COMPLETED）/get/search，@Audited。**post 仅推进单据状态机**（领域层不直接碰子账/GL——跨聚合编排放 AppService 同事务，照 PurchaseInvoiceAppService 的 post 调 AutoVoucher 模式）。

### 2.2 付款单 PaymentDisbursement（域 `com.sjherp.domain.payment`）
- 对称：header docNo（`PAYV-`，避开已有 PAY/PINV 等前缀冲突——确认未用）、supplierId、paymentAccountId、paymentDate、remark、lines。
- `PaymentDisbursementLine`：lineNo、payableId、allocatedAmount。

### 2.3 过账编排（AppService 同事务，验收核心）
`CollectionReceiptAppService.post(docNo, operator)` `@Transactional`：
1. `CollectionReceipt posted = collectionReceiptService.post(docNo, operator)`（单据状态机 →COMPLETED）。
2. 取 `PaymentAccount acct = paymentAccountService.get(posted.getPaymentAccountId())`（拿 glAccountCode）。
3. **逐行核销**：for each line → 先校验 `AccountsReceivable.customerId == posted.customerId`（防跨客户核销）→ `settlementService.settleReceivable(line.receivableId, line.allocatedAmount, posted.receiptDate, posted.getDocNo(), operator)`。超额（allocated > 未核销余额）由 T03 抛 `OverSettlementException` → 整单回滚（不能收超过欠款）。
4. **现金侧凭证**：`autoVoucherService.generateForCollectionReceipt(posted, acct.getGlAccountCode(), operator)` → 借 glAccountCode（银行/现金，总额）/ 贷 1122 应收账款（总额）。
- 付款对称：校验 `AccountsPayable.supplierId == posted.supplierId` → `settlePayable` → `generateForPaymentDisbursement` 借 220202 应付 / 贷 glAccountCode。
- **原子性**：核销 + 凭证 + 单据状态同一 @Transactional，任一抛异常全回滚（资金/核销/GL 不会半生效）。
- **幂等**：单据状态机（COMPLETED 不可重过账）为主防线；凭证 AutoVoucher 的 findBySourceDocNo 查重为纵深；核销记录 paymentDocNo=单号，T07 红冲按此反查。

### 2.4 AutoVoucherService 扩展
- `VoucherSourceType` 新增 `COLLECTION_RECEIPT("收款单")` / `PAYMENT_DISBURSEMENT("付款单")`。
- 新增常量 `ACC_CASH="1001"`、`ACC_BANK="1002"`（实际借/贷科目由 paymentAccount.glAccountCode 动态传入，非写死——常量仅作默认/文档）。
- `generateForCollectionReceipt(CollectionReceipt, String glAccountCode, String operator)`：借 glAccountCode / 贷 1122，金额=totalAmount，voucherDate=receiptDate，sourceType=COLLECTION_RECEIPT，sourceDocNo=docNo（沿用既有 generate 私有流程：signum≤0 跳过 / findBySourceDocNo 幂等 / 账期推算+ensure / createFromSource+post）。
- `generateForPaymentDisbursement(...)`：借 220202 / 贷 glAccountCode，voucherDate=paymentDate。

### 2.5 REST（app）
- `CollectionReceiptController` /api/collections：POST 建单、/{docNo}/approve|post、GET 列表、GET /{docNo}；`PaymentDisbursementController` /api/payments 对称。均 `@PreAuthorize("@perm.has('finance:settlement')")`（复用 T03 预留的核销写权限——收付款单驱动核销，本就是 finance:settlement 的写入口）。DTO 金额字符串。

### 2.6 迁移 V23 / V24
- `V23__collection_receipt.sql`（collection_receipt + collection_receipt_line，照 V15 purchase_invoice/_line DDL：doc_no 唯一、reversal_of_id/reversed_by_id 预留冲销 T07）。
- `V24__payment_disbursement.sql` 对称。

## 3. T04c Agent HITL 工具 + 一致性勾稽

- **Agent 工具**（照 PostPurchaseInvoiceTool HITL 范式，DomainToolConfig 注册）：
  - 收款：create_collection / approve_collection / post_collection / query_collections。
  - 付款：create_payment / approve_payment / post_payment / query_payments。
  - 资金账户：create_payment_account / search_payment_accounts（T04a 落，此处汇总）。
  - **建·审·过账各独立 `ToolRiskLevel.HIGH`**（涉资金过账，HITL 确认卡片复述要点：将过账收款单 X、冲减应收 Y、收入账户 Z、生成现金侧凭证、不可撤销）；查询/建档 NORMAL。requiredPermission：收付款单工具 `finance:settlement`、资金账户 `finance:payment_account`。description 中文复述要点（框架级确认，非靠话术）。
- **ConsistencyCheckService 补勾稽**（承 T03/T13；T04 后核销在生产发生，新增）：
  - 规则：每笔 AR/AP 的 `settled_amount == Σ settlement_record.amount`（子账 rollup = 核销记录真源，原则 4 账实一致）；`settled_amount ≤ amount`（无超额持久化）。
  - 规则：`status` 与余额一致（SETTLED⟺余额0、PARTIAL⟺0<已核销<amount、OPEN⟺已核销0）。
  - **不变**：既有规则4/5（应付/应收 `amount` == 发票额）仍成立——`amount` 不可变，核销只动 `settled_amount`，不破坏发票勾稽。
  - **登记延后**：GL 1122/220202 余额 vs 子账未核销合计的总账级勾稽，留 M4-T06 财务报表（资产负债表）落地时随科目余额体系一并做。
- 测试：工具单测（HIGH/permission/参数/确认文案）、勾稽单测 + 端到端 integration-db（采购→入库→发票→付款→AP 核销+借220202贷1002凭证；销售→出库→发票→收款→AR 核销+借1002贷1122凭证；断言子账 settled/status、核销记录 paymentDocNo=单号、凭证借贷与科目、试算平衡、0 ERROR break）。

## 4. 范围与不做（明确边界）
- **做**：资金账户档案、收/付款单（建/审/过账/查、分摊核销、现金侧凭证）、Agent HITL、核销 rollup 勾稽。
- **不做（延后）**：①收付款**冲销/红冲**（按 paymentDocNo 反查核销记录反向 + 反向凭证）→ M4-T07 统一冲销；②**预收/预付**（无 AR/AP 对象的在账收付，挂 1123 预付/2203 预收）→ 本批要求每行必关联 AR/AP，预收预付留后续小批；③GL 总账级 vs 子账勾稽 → M4-T06；④多币种 → 远期。
- **登记债**：JdbcAccountsPayableRepository 核销 UPDATE 未带 tenant_id（ADR-002 多租户统一收口，承 T03）。

## 6. 风险与决策
1 收付款=核销引擎生产触发器，过账同事务内 settle+现金侧凭证+单据状态原子，任一失败整单回滚（资金不半生效）。
2 现金侧借/贷科目由 paymentAccount.glAccountCode 动态决定（不写死 1001/1002），master 校验该码为末级启用 GL 科目。
3 每行分摊必关联具体 AR/AP 且对手方一致（防跨客户/供应商误核销）；超额核销 T03 硬拒→整单回滚（不能收/付超过欠款）。
4 复用 finance:settlement 作收付款单写权限（T03 已预留）；新增 finance:payment_account 仅护资金账户档案。
5 Agent 建·审·过账各独立 HIGH 确认（框架级 HITL，非话术）。
6 冲销/预收预付/总账级勾稽明确延后（T07/后续/T06）；核销 rollup 勾稽本批补（生产核销已发生，原则 4）。
7 单据前缀 RCPT-/PAYV-（避开 PAY/PINV/PR 等已用前缀），[A-Z]{1,10} 合规。
