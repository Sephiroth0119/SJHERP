# 领域模型概览

> 状态：**草稿（整体待细化）**。本文列出五个业务域的核心聚合与单据清单，作为 sjherp-domain 模块的建模起点。状态流转规则最终以领域层代码为准，本文同步演进。

## 通用单据状态机

> 已实现（M2-T01）：`sjherp-domain` 的 `DocumentStatus`（流转表）+ `BusinessDocument`（流转入口、钩子、冲销关联、领域事件）。本节与代码同步演进，代码为准。

所有业务单据遵循统一状态机（具体域可在 `beforeTransition` 钩子中收紧规则，但不得放宽流转表）：

```
草稿(DRAFT) → 审核(APPROVED) → 执行(EXECUTING) → 完成(COMPLETED)
     ↓              ↘               ↘                ↘
作废(CANCELLED)      冲销(REVERSED) ← ─ ─ ─ ─ ─ ─ ─ ─ ┘
```

合法流转表（单一真源在 `DocumentStatus`）：

| 当前状态 | 允许流转到 | 说明 |
|---|---|---|
| DRAFT | APPROVED、CANCELLED | 草稿未产生业务影响，可作废 |
| APPROVED | EXECUTING、REVERSED | 审核后业务内容锁定 |
| EXECUTING | COMPLETED、REVERSED | |
| COMPLETED | REVERSED | 已过账，只可冲销 |
| REVERSED / CANCELLED | （终态） | 不再流转 |

- 状态流转规则定义在领域层，所有写操作必须经过领域服务并受状态机约束；非法流转抛 `IllegalStateTransitionException`（含单据号、当前态、目标态）。
- 财务相关记录**只可冲销、不可物理修改/删除**（`BusinessDocument` 不存在删除方法）；冲销不修改原单业务内容，仅做"冲销标记 + 红字关联"：原单 `reversedById` 指向红字冲销单，红字单 `reversalOfId` 指向原单，红字单本身是独立的反向单据。
- 单据编号统一为"前缀-年月-序号"（如 `PO-202606-0001`），由 `DocumentNumberGenerator` 生成，序号按"前缀+年月"作用域独立递增（生产序号供给已落地：infra `JdbcSequenceProvider`，`doc_sequence` 表行锁递增，并发安全且重启不重号）。
- 每次状态流转自动发布领域事件 `DocumentStatusChangedEvent`（事件 id / 发生时间 / 单据号 / 前后状态 / 操作人），供审计日志、凭证生成、检查 Agent 订阅（已接线，M2-T07：app 装配 `SyncDomainEventPublisher` 同步分发，`AuditDomainEventListener` 落 audit_log，action=document.status_changed；M3 单据服务注入该发布器即自动获得审计）。
- 每次状态流转记录审计日志：谁（用户/Agent）、何时、依据什么指令、改了什么（统一审计机制见 docs/审计日志.md）。

## 基础档案 —— 商品档案（已实现，M2-T02）

> 已实现：`sjherp-domain` 的 `domain/catalog` 包（领域模型与服务）+ `sjherp-infra` 的 `persistence/catalog`（MySQL 仓储，V2 迁移）+ `sjherp-app` 的 `app/catalog`（REST API）。商品档案是后续客户/供应商/仓库等档案的模式样板。

档案不是单据：没有状态机流转，只有**启用/停用**两态（`ArchiveStatus`，重复启停被拒）；档案**不可物理删除**（历史单据引用必须永远可追溯），下线即停用。

| 聚合/概念 | 说明 |
|---|---|
| 商品 Product（聚合根） | code 租户内唯一（手填或留空自动编号 `SKU-年月-序号`，复用 `DocumentNumberGenerator`）；名称/规格/条码/备注/所属类目（可空）/基本单位（必填，库存与成本核算的计量基准）；审计字段 created_by/at、updated_by/at |
| 多单位换算 UnitConversion（值对象） | 从属商品聚合整体读写：1 换算单位 = rate 基本单位（如 1 箱 = 12 瓶）；rate 为 `BigDecimal`（DECIMAL(18,6)，必须 > 0），换算单位不得重复、不得等于基本单位；除法换算按目标精度 HALF_UP |
| 类目 Category | 树形档案，最多 3 层（层级创建时固化，不支持挪动父类目）；名称租户内唯一；删除有引用保护（有子类目或被商品引用则拒绝） |
| 计量单位 Unit | 名称租户内唯一；precision（0–6）= 以该单位计量时数量保留的小数位数；删除有引用保护（被商品用作基本/换算单位则拒绝） |

- 所有写操作经领域服务（`ProductService` / `CategoryService` / `UnitService`）唯一入口；引用完整性（基本单位/类目/换算单位必须存在）在服务层校验。
- 编号序号由 `doc_sequence` 表 + `JdbcSequenceProvider`（`SELECT ... FOR UPDATE` 行锁递增，REQUIRES_NEW 独立提交）保证并发不重号、**重启不重号**。
- 多租户（ADR-002）：所有 catalog 表带 `tenant_id`（恒为 0），`(tenant_id, code)` / `(tenant_id, name)` 联合唯一。
- REST：`/api/catalog/products|categories|units`（Bean Validation 字段校验，错误响应统一 `{"error": "..."}`）。

## 基础档案 —— 往来与仓库档案（已实现，M2-T03 / M2-T04）

> 已实现：`sjherp-domain` 的 `domain/partner`（客户/供应商）与 `domain/warehouse`（仓库）+ `sjherp-infra` 的 `persistence/partner|warehouse`（MySQL 仓储，V4 迁移）+ `sjherp-app` 的 `app/partner|warehouse`（REST API）。严格复用商品档案模式：启停两态、不可物理删除、编码留空自动编号、领域服务唯一写入口、`(tenant_id, code)` 联合唯一。

| 聚合 | 说明 |
|---|---|
| 客户 Customer（聚合根） | code 自动编号 `CUS-年月-序号` 或手填；名称（必填）/联系人/电话/地址/税号（可空）；结算方式 `SettlementMethod`（必填：MONTHLY 月结 / CASH 现结 / PREPAID 预付）；信用额度 `BigDecimal`（DECIMAL(18,2)，可空表示不设限，不可为负，**超限校验留 M3 销售订单**）；默认币种固定 CNY（Q-4 决策，字段预留多币种）；审计字段同商品 |
| 供应商 Supplier（聚合根） | code 自动编号 `SUP-年月-序号` 或手填；字段同客户但无信用额度/币种 |
| 仓库 Warehouse（聚合根） | code 自动编号 `WH-年月-序号` 或手填；名称（必填）/地址/负责人（可空）；`locationEnabled` 是否启用库位管理（**本期仅字段预留，库位表与库位维度库存留 M3 按需**）；审计字段同商品 |

- 写操作经 `CustomerService` / `SupplierService` / `WarehouseService` 唯一入口；停用前的引用约束检查（在途单据、非零库存等）留 TODO 待 M3 单据落地后补齐。
- REST：`/api/partner/customers|suppliers`、`/api/warehouse/warehouses`（POST/PUT/enable/disable/分页关键字查询/按 id 查询，错误响应统一 `{"error": "..."}`）。

## 用户与角色（已实现，M2-T05）

> 已实现：`sjherp-domain` 的 `domain/identity`（User 聚合 + UserService + PasswordHasher 端口）+
> `sjherp-infra` 的 `persistence/identity`（MySQL 仓储，V6 迁移，表 `sys_user`）与 `identity`
> （BCrypt 实现，spring-security-crypto）+ `sjherp-app` 的 `app/security`（JWT 认证链）、
> `app/auth`（登录/当前用户 API）、`app/identity`（用户管理 API，ADMIN 限定）。

用户是档案而非单据：只有启用/停用两态（`ArchiveStatus`），**不可物理删除**（审计
created_by/updated_by 与会话归属必须永远可追溯），离职即停用。

| 概念 | 说明 |
|---|---|
| 用户 User（聚合根） | username 租户内唯一（创建后不可改，审计记录以该值标识操作人）；displayName 可改；passwordHash（BCrypt，领域层不透明存储，绝不存明文）；角色集合（至少一个）；审计字段同档案 |
| 角色 Role（固定枚举） | ADMIN 管理员 / BOSS 老板 / ACCOUNTANT 会计 / WAREHOUSE 仓管 / PURCHASER 采购 / SALES 销售。小企业从简不做自定义角色；功能权限点与角色映射留 M2-T06 |
| 密码规则 | 至少 8 位且同时包含字母与数字（更复杂策略留 M8-T03）；本人改密须核对旧密码，管理员重置无需旧密码（API 限定 ADMIN） |
| 认证 | JWT（HS256，12h，密钥环境变量 `SJHERP_JWT_SECRET`）；token 只证明身份（sub=用户 id），角色与启停状态逐请求从库刷新——停用/改角色立即生效，无需 token 吊销 |
| 登录失败口径 | 用户名不存在与密码错误统一报"用户名或密码错误"（不泄露登录名是否存在）；停用账号拒绝登录 |

- 写操作经 `UserService` 唯一入口；登录名唯一由仓储查重 + `(tenant_id, username)` 联合唯一键兜底；角色集合存 JSON 数组列（固定枚举且量级小，不建关联表）。
- 种子数据：V6 迁移内置 `admin` / `Admin@2026`（ADMIN 角色），**部署后必须立即修改**。
- 操作人来源：各 REST Controller 统一从登录态解析（`CurrentUser.operator()`，记登录名）；Agent 自动操作统一记 `agent:<userId>`（哪个用户的会话触发即记该用户 id）。M2-T07 已落地统一审计：领域 Service 写方法标注 `@Audited`，app 层 `AuditAspect` 写 audit_log（V9 迁移），详见 docs/审计日志.md。
