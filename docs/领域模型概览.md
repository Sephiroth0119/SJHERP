# 领域模型概览

> 状态：**草稿（整体待细化）**。本文列出五个业务域的核心聚合与单据清单，作为 sjherp-domain 模块的建模起点。状态流转规则最终以领域层代码为准，本文同步演进。

## 通用单据状态机

> 已实现（M2-T01）：`sjherp-domain` 的 `DocumentStatus`（流转表）+ `BusinessDocument`（流转入口、钩子、冲销关联、领域事件）。本节与代码同步演进，代码为准。

所有业务单据遵循统一状态机（具体域可在 `beforeTransition` 钩子中收紧规则，但不得放宽流转表）：

```
草稿(DRAFT) → 审核(APPROVED) → 执行(EXECUTING) → 完成(COMPLETED)
     ↓              ↘               ↘                ↘
作废(CANCELLED)      冲销(REVERSED) ← ─ ─ ─ ─ ─ ─ ─ ─ ┘
```

合法流转表（单一真源在 `DocumentStatus`）：

| 当前状态 | 允许流转到 | 说明 |
|---|---|---|
| DRAFT | APPROVED、CANCELLED | 草稿未产生业务影响，可作废 |
| APPROVED | EXECUTING、REVERSED | 审核后业务内容锁定 |
| EXECUTING | COMPLETED、REVERSED | |
| COMPLETED | REVERSED | 已过账，只可冲销 |
| REVERSED / CANCELLED | （终态） | 不再流转 |

- 状态流转规则定义在领域层，所有写操作必须经过领域服务并受状态机约束；非法流转抛 `IllegalStateTransitionException`（含单据号、当前态、目标态）。
- 财务相关记录**只可冲销、不可物理修改/删除**（`BusinessDocument` 不存在删除方法）；冲销不修改原单业务内容，仅做"冲销标记 + 红字关联"：原单 `reversedById` 指向红字冲销单，红字单 `reversalOfId` 指向原单，红字单本身是独立的反向单据。
- 单据编号统一为"前缀-年月-序号"（如 `PO-202606-0001`），由 `DocumentNumberGenerator` 生成，序号按"前缀+年月"作用域独立递增（生产序号供给 `SequenceProvider` 由 infra 实现，**待办**：infra 落地数据库序号表实现）。
- 每次状态流转自动发布领域事件 `DocumentStatusChangedEvent`（事件 id / 发生时间 / 单据号 / 前后状态 / 操作人），供审计日志、凭证生成、检查 Agent 订阅（**待办**：infra/app 接入 `DomainEventPublisher` 实现与审计落库，归属 M2-T07）。
- 每次状态流转记录审计日志：谁（用户/Agent）、何时、依据什么指令、改了什么。
