# SJHERP 一键安装（M8-T01）

目标：小企业 IT 同事在全新 **Ubuntu** 上大约 30 分钟装好，用浏览器打开登录页。

本刀交付生产向 `docker compose`（**nginx / app / MySQL / Qdrant**）+ 安装脚本 + 升级脚本。**定时备份与恢复演练见 [部署-备份恢复.md](./部署-备份恢复.md)（M8-T02）。HTTPS、密码策略、限流与 LLM 出境见 [部署-安全基线.md](./部署-安全基线.md)（M8-T03）。监控留给 M8-T04。**

## 30 分钟路径

在一台能上网的 Ubuntu（22.04 / 24.04）上：

```bash
sudo apt-get update
sudo apt-get install -y git curl ca-certificates openssl
git clone https://github.com/Sephiroth0119/SJHERP.git
cd SJHERP
./deploy/install.sh
```

脚本会：

1. 没有 Docker 时自动安装 Docker Engine（需要 sudo）
2. 若没有 `deploy/.env`，从模板复制并生成随机密钥
3. 构建并启动四个容器：MySQL、Qdrant、Spring Boot、nginx
4. 等待 `GET /api/health` 返回 UP，再做登录页 + 管理员登录冒烟
5. 打印访问地址和初始 `admin` 密码

浏览器打开脚本打印的地址（默认 `https://服务器IP/`，自签证书需在浏览器点继续访问）。用户名 **admin**，密码在 `deploy/.env` 的 `SJHERP_ADMIN_PASSWORD`。仅 HTTP 时设 `SJHERP_TLS_MODE=off`。

> 首次编译后端镜像会下载 Maven 依赖，视网络可能要 5–15 分钟，属正常。

## 前置条件

| 项 | 要求 |
|---|---|
| 系统 | Ubuntu 22.04/24.04 amd64（其他 Linux 需自行先装 Docker） |
| 内存 | 建议 ≥ 4 GB（2 GB 可能 OOM） |
| 磁盘 | 建议 ≥ 20 GB 可用 |
| 网络 | 能访问 Docker Hub、Maven Central、npm registry |
| 权限 | 安装 Docker 需要 sudo；之后当前用户在 `docker` 组可免 sudo |
| 端口 | 默认宿主机 **80** 与 **443**（`SJHERP_HTTP_PORT` / `SJHERP_HTTPS_PORT`） |

不需要本机预装 JDK、Maven、Node。应用在镜像里构建。

**不要做的事：** 不要改 `web-dist/`（预发静态包）。生产前端由 `deploy/nginx/Dockerfile` 从 `web/` 现编。

## 装了什么、端口怎么开

| 容器 | 作用 | 宿主机端口 |
|---|---|---|
| nginx | 静态前端 + 把 `/api` 反代到 app（含聊天 SSE）；默认 TLS | `SJHERP_HTTP_PORT`（80）、`SJHERP_HTTPS_PORT`（443） |
| app | Spring Boot；启动时 **Flyway 自动迁移**；创建初始 admin | 不暴露 |
| mysql | 业务真源 MySQL 8.4 | 不暴露（仅容器内网） |
| qdrant | 大记忆派生索引 | 不暴露；记忆默认关闭，不影响登录 |

开发用中间件仍是 `deploy/docker-compose.dev.yml`（只起 MySQL/Qdrant，不含 app/nginx）。

## 环境变量

模板：`deploy/.env.example`（可提交）。真实文件：`deploy/.env`（git 忽略）。

安装脚本会生成：

- `MYSQL_ROOT_PASSWORD` / `SJHERP_DB_PASSWORD`
- `SJHERP_JWT_SECRET`（≥ 32 字节）
- `SJHERP_ADMIN_PASSWORD`（≥ 8 位，大写+小写+数字；用户名固定 `admin`）
- 自签证书 `deploy/certs/*.pem`（`SJHERP_TLS_MODE=self-signed`）

可选：

- `SJHERP_LLM_API_KEY`：不填则聊天走占位 Agent，**传统工作台仍可用**
- `SJHERP_MEMORY_ENABLED`：默认 `false`。打开前需另装 Ollama（本 compose 不含）
- `SJHERP_CONSISTENCY_ENABLED`：生产默认 `true`（定时勾稽，只告警不静默改数）
- `SJHERP_HTTP_PORT` / `SJHERP_HTTPS_PORT`：宿主机端口
- `SJHERP_TLS_MODE`：`self-signed`（默认）/ `custom` / `off`，详见安全基线

改 `.env` 后执行 `./deploy/upgrade.sh --skip-git --skip-backup` 让容器重新读变量。  
**已经创建过的 admin 密码不会因为改 `.env` 而变化**（只在库中尚无 admin 时写入）。

## 升级

```bash
cd SJHERP
./deploy/upgrade.sh
```

默认：`git pull --ff-only` → 对运行中的 MySQL 做一次 dump 到 `deploy/backups/mysql/`（`backup.sh --reason pre-upgrade`）→ 重建镜像并启动。  
app 启动时 Flyway 执行新的 `Vxx` 脚本，**不必手工跑迁移**。日常定时备份与 Qdrant 快照见 [部署-备份恢复.md](./部署-备份恢复.md)。

常用开关：

- `--skip-git`：按当前工作区构建（不要拉远程）
- `--skip-backup`：跳过 dump（不推荐）
- `--check`：只校验脚本和 compose，不改机器

## 回滚边界

1. **Flyway 只向前**。已经执行的 `Vxx` 不会被本脚本回退。
2. **有新迁移时的安全回滚**：用升级前的 `deploy/backups/mysql/sjherp-pre-upgrade-*.sql.gz` 走 `./deploy/restore.sh --mysql <文件>` → 检出旧版本代码 → `./deploy/upgrade.sh --skip-git --skip-backup`。
3. **没有新迁移时**：检出旧代码再升级脚本 `--skip-git` 通常即可。
4. **禁止** `docker compose down -v`：`-v` 会删掉 MySQL/Qdrant 数据卷。恢复不要删 volume。
5. Qdrant 快照、cron、恢复演练见 [部署-备份恢复.md](./部署-备份恢复.md)。记忆默认关闭时，救数仍以 MySQL 为准。
6. 本刀不做自动 merge/deploy 到客户机以外的环境。

```bash
./deploy/restore.sh --mysql latest
./deploy/smoke.sh --login
```

## 常用命令

```bash
./deploy/install.sh --check     # 不启动，校验脚本和 compose
./deploy/backup.sh              # MySQL dump + Qdrant 快照
./deploy/restore-smoke.sh       # 备份→恢复→登录演练（会覆盖当前库）
./deploy/smoke.sh               # 登录页 + /api/health
./deploy/smoke.sh --login       # 再加上 admin 登录
docker compose --project-directory deploy -f deploy/docker-compose.yml --env-file deploy/.env ps
docker compose --project-directory deploy -f deploy/docker-compose.yml --env-file deploy/.env logs -f app
```

## 常见失败

| 现象 | 处理 |
|---|---|
| 拉 `mysql` / `qdrant` 镜像很慢或失败 | 配置 Docker 镜像加速后 `sudo systemctl restart docker`。例：`/etc/docker/daemon.json` 写入 `{"registry-mirrors":["https://docker.m.daocloud.io"]}` |
| Maven / npm 构建超时 | 检查出网；稍后重跑 `./deploy/install.sh`（已生成的 `.env` 会保留） |
| 80 / 443 端口被占用 | 改 `deploy/.env` 的 `SJHERP_HTTP_PORT` / `SJHERP_HTTPS_PORT`，再 `./deploy/upgrade.sh --skip-git --skip-backup` |
| 浏览器提示证书不受信任 | 默认自签证书，属预期；换 Let's Encrypt 见 [部署-安全基线.md](./部署-安全基线.md) |
| `/api/health` 一直失败 | `docker compose ... logs app`。常见原因：`.env` 密钥仍是示例值、JWT 太短、admin 密码不符合强度（大写+小写+数字） |
| 登录页空白但 health 正常 | 看 nginx 日志；确认没有改用 `web-dist/`，生产静态来自 `web/` 构建 |
| 登录 401 | 用 `.env` 里**首次启动**的 admin 密码；改 `.env` 不会改已有用户密码 |
| `Permission denied` 访问 Docker | 注销重登，或 `sudo usermod -aG docker $USER` |
| 内存不足 / 容器被杀 | 加大虚拟机内存到 4 GB+ |
| 聊天只会占位回复 | 未配 `SJHERP_LLM_API_KEY`，属预期；配好后重启 app |

## 全新 Ubuntu 手测清单

云端 CI 负责：compose config、脚本 `--check`、构建镜像，并尽量 `up` 后冒烟。若某环境不能起全套容器，请在干净 Ubuntu 上按序打勾：

1. [ ] 全新 Ubuntu，未预装 JDK/Maven/Node
2. [ ] `./deploy/install.sh` 一次跑完，打印 URL 与 admin 密码
3. [ ] 浏览器打开登录页，标题含 SJHERP
4. [ ] `curl -kfsS https://127.0.0.1/api/health` 含 `"status":"UP"`（`TLS_MODE=off` 时用 http）
5. [ ] 用 admin + 打印的密码能登录
6. [ ] `docker compose ... ps` 中 mysql/qdrant/app/nginx 为 running（或 healthy）
7. [ ] 再跑 `./deploy/upgrade.sh --skip-git`（可验证重建不丢卷）；登录页仍可用
8. [ ] `./deploy/backup.sh` 在 `deploy/backups/mysql/` 与 `deploy/backups/qdrant/` 产出文件；`./deploy/restore-smoke.sh` 通过
9. [ ] 确认 `web-dist/` 无改动、`deploy/.env` 未入库

验收记录见 `docs/测试-M8-T01一键部署.md`。
