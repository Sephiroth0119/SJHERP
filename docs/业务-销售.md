# 业务说明 — 销售（下单 → 出库 → 发票应收）

> 面向业务的说明（M3-T08/T09/T10）。给老板、销售、仓管、会计看，不是给程序员看的。
> 一句话：**客户要买东西 → 我们记一张销售订单 → 按订单发货出库 → 给客户开发票、挂上"客户欠我们的钱"（应收）。**

## 1. 销售全流程，三步走

小企业卖货，从答应客户到收到钱，系统里走三张单据，环环相扣：

```
①销售订单（SO）  →  ②销售出库单（SD）  →  ③销售发票（SINV）  →  应收账款（客户欠款台账）
  约定卖什么、         按订单实际发货、        给客户开票、         记下客户欠我们多少钱、
  多少、什么价         真正扣库存、算成本       金额不超已发货         什么时候到期
```

每一步都"承上启下"：出库单必须挂在某张已审核的销售订单上，发票必须挂在某张已发货的出库单上。
这样数据不会断链——任何一笔欠款，都能一路倒查到"是哪张订单、发了哪批货"。

### ① 销售订单（SO-年月-序号）

**是什么**：和客户的销售约定。记下卖给谁（客户）、卖什么（商品）、卖多少（数量）、什么价（销售单价）。

**关键点：下单不动库存。** 下单只是"说好了要卖"，仓库里的货一个都不会少。真正减库存要等到出库。

**可用库存检查（只提示不拦）**：下单时如果指定了仓库，系统会顺手看一眼"这个仓现在够不够"。
不够也照样让你下单，只是给个提示："商品 X 下单 100，仓里只有 60，发货前记得补货"。
为什么不拦？因为下单常常发生在备货之前——客户先订，我们再去进货，这是正常生意。

**单价从哪来**：直接录入（订单上写多少就是多少）。v1.0 不做"客户等级价/阶梯价"这类自动定价，简单直接。

**状态**：草稿 → 审核（审核后才能据它发货）。审核前可以作废。

### ② 销售出库单（SD-年月-序号）

**是什么**：按某张销售订单实际发货。可以**部分发货**——订单 100 个，这次先发 70 个，剩 30 个下次再发。

**关键点：出库过账才真正减库存。** 出库单"审核 + 过账"后，系统才把货从仓库扣掉
（经库存唯一入口走一笔"销售出库 SALES_OUT"流水），并干两件大事：

1. **算出这批货的成本（COGS），记到出库行上**（见第 2 节，这是利润核算的命根子）；
2. **回写订单的累计发货量**：订单行记下"已发 70、还剩 30"，下次发货不会超发。

**不超发**：每次发货数量不能超过订单行的剩余可发量。订单 100、已发 70，这次最多再发 30。

**库存不够会怎样**：销售出库**默认强校验库存**——仓里货不够，整张出库单过账失败、全部回滚，
一个流水都不留（不像下单那样只提示）。因为这时是要真减库存了，不能减成负数把账搞乱。

**状态**：草稿 → 审核 → 过账（完成）。过账后库存已动，只能冲销不能删（退货 M4 做）。

### ③ 销售发票（SINV-年月-序号）与应收账款

**是什么**：对已发货的商品给客户开票。挂在某张已过账的出库单上，**开票数量不能超过已发货数量**
（发了 70 才能开 70 以内，不能凭空多开）。

**跨发票防重复开票**：和采购侧对称——每张出库行记一个「累计已开票量」，开票时卡的是
**剩余可开票量 = 已发货量 − 已开票量**，跨发票累计。发了 70、开过一张 70 的发票（已开满），
再对同一出库行开第二张就被拒（剩余 0），不会因为换发票号重复全额开票把应收翻倍；分次开
（先 40 再 30）也支持，开满后再开就拒。发票过账时，回写量与应收挂账在同一笔事务里同生共死。
（注：早期版本曾不跨发票累计，仅留 P2，现已修复为跨发票硬卡——见 docs/M3拆解-库存与成本.md §7。）

**应收怎么产生**：发票"审核 + 过账"后，系统按发票金额自动生成一条**应收账款**——
就是"这个客户因为这张发票，欠我们多少钱、什么时候到期"。状态是"未核销（OPEN）"，
意思是钱还没收到。等以后收款，再去核销冲减（收款核销 M4-T03 做，本期先把欠款记清楚）。

**状态**：草稿 → 审核 → 过账（完成，生成应收）。

## 2. COGS 是什么，为什么重要

**COGS = Cost of Goods Sold = 销货成本**，大白话：**"卖出去的这批货，当初花了多少钱进的。"**

它在**出库时**算出来，用的是**移动加权成本**——把仓里同一商品历次进货的钱平摊成一个"平均单价"，
出库就按这个平均单价结转成本。

**小例子**：
- 先进 100 个，每个 10 元（花了 1000 元）；
- 又进 80 个，每个 12.5 元（花了 1000 元）；
- 现在仓里 180 个，共花了 2000 元 → 平均每个 `2000 ÷ 180 = 11.111111` 元；
- 卖出（出库）70 个，这 70 个的 COGS = `11.111111 × 70 = 777.78` 元。

这 777.78 元会**记到销售出库行上**。

**为什么重要**：利润 = 卖的钱 − 成本。
- 这 70 个卖价是每个 25 元，卖了 `70 × 25 = 1750` 元；
- 成本（COGS）是 777.78 元；
- 这单毛利 = `1750 − 777.78 = 972.22` 元。

没有 COGS，就算不出真实利润——只知道收了多少钱，不知道挣了多少。所以出库时把 COGS 锁定记下来，
是 M4 利润核算的基础。COGS 用的成本和库存账上扣减的金额**严格一致**（一笔出库流水，库存少这么多钱、
出库行记这么多成本），账永远对得上。

## 3. 三张单据怎么环环相扣（一个完整例子）

老王的杂货批发：

1. **下单**：张三百货要 100 箱可乐，谈好每箱 25 元 → 开一张销售订单 SO-202606-0001，审核。
   （此时仓库可乐一箱没动；如果仓里不够 100 箱，系统会提示"发货前补货"。）
2. **发货**：仓库先发 70 箱 → 开销售出库单 SD-202606-0001，挂在 SO 上，审核、过账。
   - 仓库可乐少 70 箱；
   - 系统按移动加权算出这 70 箱成本 COGS（比如 777.78 元）记到出库行；
   - 订单记下"已发 70、还剩 30"。
3. **开票**：给张三百货开发票 SINV-202606-0001，挂在 SD 上，开 70 箱 × 25 元 = 1750 元，审核、过账。
   - 生成应收账款：张三百货欠 1750 元，到期日 7 月 14 日，状态"未核销"。
4. **后续**：剩 30 箱再开一张出库单接着发；收到钱后核销应收（M4 做）。

## 4. 和库存、利润的关系（一句话各表）

- **和库存**：销售出库过账是库存"减少"的正规入口之一（采购入库是"增加"）。一切经库存唯一写入口，
  账实一致、对账恒等式永远成立（卖出的数量金额 = 库存减少的数量金额）。
- **和成本/利润**：出库时锁定 COGS（移动加权），是算毛利的成本端；发票金额是收入端。
  利润 = 发票金额 − COGS，M4 据此出利润表。
- **和财务**：发票过账生成应收（客户欠款），是应收账款的来源。财务记录只能冲销、不能删改
  （开错了走红字冲销，M4 做），保证账目可审计、不被偷偷篡改。

## 5. 谁能做什么（权限）

| 动作 | 谁能做 |
|---|---|
| 销售订单（建/审/查） | 管理员、老板、销售 |
| 销售出库（建/审/过账/查） | 管理员、老板、销售、仓管 |
| 销售发票（建/审/过账/查）、查应收 | 管理员、老板、销售、会计 |

聊天里也能下单：对 Agent 说"给张三百货下单 100 箱可乐，每箱 25 元"，它会复述要点、弹确认卡，
你点确认才真正建单（建的是草稿订单，后续审核、发货、开票按上面流程走）。

## 6. 本期范围与后续（说清楚没做什么）

- **退货 / 红字单**：销售出库、发票的冲销（退货、开错票）留 M4 统一做（红字单驱动反向流水/冲减应收），
  本期单据一旦过账只能等 M4 冲销，不提供物理删除。
- **收款核销**：应收本期只"挂账"（记下欠多少），收到钱后的核销冲减是 M4-T03。应收已预留"已核销金额"字段。
- **价格策略**：客户等级价/阶梯价不做，订单和发票都用录入价。
