# 工程方案：自驱开发循环（Self-Driving Dev Loop）

> 目的：把"按路线图逐个完成任务"固化为一条**可重复、有质量闸门、可自驱**的流水线，让主控 Agent 能连续推进 M5-T05→T08（及后续里程碑），只在**真正需要人介入的门控**处停下。
> 本文是开发流程的单一真源；路线图 docs/产品路线图-0到1.md 是任务计划的单一真源，二者配合：路线图说"做什么"，本文说"怎么循环地做"。

## 0. 适用前提（不可妥协，继承 CLAUDE.md）
- 数据模型完整性高于一切；财务只可冲销不可物删/改；借贷平衡；金额/数量一律 BigDecimal；@Audited 全覆盖写方法。
- 这些是**质量闸门的硬断言**，不随自驱循环降级。循环只加速"正确的事"，不放宽正确性。

## 1. 循环总览（每个任务一圈）

```
┌─ 取下一个未完成任务（路线图任务表，按编号顺序）
│
├─ ① PLAN：Plan agent 产出实现策略（关键文件/状态机/边界/风险）
├─ ② DESIGN DOC：写 docs/Mx拆解-<任务>.md（设计单一真源，落关键裁定）
├─ ③ IMPLEMENT：派工 subagent 按设计写代码（模型分级见 §4）
├─ ④ BUILD：JDK21 全反应堆 mvn clean test（本机门禁）
│      └─ 编译/测试失败 → 主控修复，回 ④（不进入评审）
├─ ⑤ REVIEW：opus 单/多镜头对抗校验（schema：P0-P3/file/location/issue/fix/confidence）
├─ ⑥ FIX：修 P0/P1（及廉价 P2/P3）→ 回 ④ 复验绿
├─ ⑦ DOC SYNC：CLAUDE.md 状态段 + 路线图任务行✅+§0.5 变更条 + 权限矩阵（如有新权限点）
├─ ⑧ TEST DOC：写 docs/测试-Mx-<任务>.md（验收红线对照/用例意图/跑测命令/评审固化）
├─ ⑨ COMMIT：折叠 subagent 杂提交 → 单一干净中文 commit（类型: 简述）
├─ ⑩ PUSH：push 到 feat/mx-txx 特性分支（见 §3 推送门控）
├─ ⑪ CI：轮询 3 job 绿（前端 tsc+build / 后端 mvn verify / 后端 DB 集成测试）
│      └─ CI 红 → 拉日志、主控修复、回 ④
└─ ⑫ 回到顶部取下一个任务
```

## 2. 停止条件（只在这些点停，其余自驱）
1. **HIGH 风险运行时 HITL**：资金/过账/关账等运行时高风险确认——构建任务通常无此门，故一般不触发。
2. **CI 持续红且需决策**：非平凡失败（如设计层面冲突）需人定夺方向。
3. **设计歧义**：任务验收口径不清、需在互斥方案间抉择（用 AskUserQuestion，不臆测）。
4. **合并到 main**：特性分支 → main 的合并由人（PR review）把关（见 §3）。
> 其余一切（编译错、测试红、评审 P0/P1、文档同步）主控自行闭环，不打断用户。

## 3. 推送门控（关键约束，本方案的核心解法）
- 直推默认分支 `main` 被 auto-mode classifier 拒（理由：绕过 PR review，CLAUDE.md 规定 feat/xxx 分支）。
- **解法 = 每个任务推到特性分支 `feat/mx-txx`**（已验证放行），CI 在分支上跑；合并到 main 走 PR（人把关），符合 CLAUDE.md Git 约定。
- 命令：`git push origin HEAD:refs/heads/feat/mx-txx`（不切本地分支，直接建远程分支）。
- 合并策略：任务批次可各自一分支，或一个 `feat/m5` 累积分支汇总后整体 PR——由用户选。本循环默认**每任务一分支**，便于独立 review/回滚。

## 4. 模型分级派工（CLAUDE.md §13.6）
- **sonnet**：模式复制类（照既有范式建聚合/REST/JdbcRepository/DTO）。
- **opus**：复杂逻辑（状态机白名单、成本核算、MRP/勾稽算法）与对抗校验（评审）。
- **主控（当前模型）**：编排、决策、修复、文档、提交；质量闸门不降档。
- 派工铁律：**subagent 不得 git commit、不得跑 mvn**（构建/提交由主控控制，杂提交事后 reset --soft 折叠）。

## 5. 自驱节奏（ScheduleWakeup）
- 构建步骤同步执行，无需睡眠等待。
- **唯一需要等待**：⑪ 轮询 CI。CI 一轮约数分钟——用 ScheduleWakeup（缓存窗口内 60–270s，或长回退 1200s+）回探，而非空轮询。
- 上下文将满时：靠 context 摘要续命，循环状态以路线图✅行 + 本文为准，可无缝接续。

## 6. 单任务验收 checklist（每圈出口必须全绿）
- [ ] 设计文档落地（docs/Mx拆解-*.md），关键裁定可追溯。
- [ ] 全反应堆 JDK21 测试全绿（agent+domain+infra+app 计数记入文档）。
- [ ] opus 对抗校验执行，P0/P1 清零（P2/P3 修或登记）。
- [ ] 红线断言覆盖（数据模型/财务/审计/精度），新行为有单测固化。
- [ ] @Tag(integration-db) 真库集成测试覆盖关键往返/端到端（CI 跑）。
- [ ] 文档四同步（CLAUDE.md / 路线图行+§0.5 / 权限矩阵 / 测试文档）。
- [ ] 单一干净 commit + 推特性分支 + CI 3 job 绿。
