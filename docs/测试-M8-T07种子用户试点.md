# M8-T07 种子用户试点测试与验收记录

## 当前状态

T07 已完成**演示干跑**实现。产品方决定先用虚构「演示*」企业把「部署 → 完整会计期间 → 缺口通道」路径跑通，**暂不接真实企业**。真实客户名以后再换。

未改 `web-dist/`，未改领域状态机，未用 Flyway 灌业务种子（避免生产一键安装自动污染账套）。

## 验收范围

- 部署复用 M8-T01：`./deploy/install.sh`，不重造 compose
- 装入 1 家丰富演示企业（默认 `sunshine` / 演示阳光文具）；可选第二套 `qinghe` / 演示青禾食品（v1.0 单租户互斥，须空库或恢复后再装）
- 种子经已有档案服务与单据 AppService 走 **create → approve → post**，数量金额 `BigDecimal`，名称带「演示」或「Demo」
- 链路：采购订单 → 入库 → 采购发票 → 付款核销 → 销售订单 → 出库 → 销售发票 → 收款核销；另给独立 SKU 做 `OPENING`
- **不关账**；关账预检只读。账期取当前 UTC 月（与销售出库 COGS 凭证日对齐）
- 样例缺口写入既有 `gap_record`；试点中新问题走 Agent 工具 `record_process_gap`
- `deploy/seed-pilot.sh --check` 纳入 `install.sh --check` 与 CI 部署资产 job

## 本刀不做

- 真实小企业进场、付费意向客户替换演示名
- 多租户并行隔离两套账
- 自动审核过账绕开状态机、空名称假数据
- 改 `web-dist/`、单据状态机红线、Flyway 业务种子
- 种子内执行月末关账

## 本地 / 预发如何装种子

1. 按 [部署-一键安装.md](./部署-一键安装.md) 起栈（或本机已有 app + MySQL）。
2. `chmod +x deploy/seed-pilot.sh`
3. `./deploy/seed-pilot.sh`（默认 sunshine）。需 `deploy/.env` 的 admin 密码。
4. 也可 ADMIN/BOSS 调 `POST /api/pilot/demo-seed`，body `{"pack":"sunshine"}`。
5. 启动时装载（仅预发/本地）：`SJHERP_DEMO_SEED=true`（compose 已映射，**生产保持 false**）。
6. 换 qinghe：先恢复到空库（或新 volume），再 `./deploy/seed-pilot.sh --pack qinghe`。禁止在已装 sunshine 的同一套账并行再装。

装载成功响应含单据号、样例缺口号、`periodCloseable`。`alreadyLoaded=true` 表示幂等跳过。

## 完整会计期间干跑清单（手测）

种子只把单据过账到可关账状态，**关账仍须人点**。用 admin 登录后按序勾选：

1. [ ] 档案：仓库/商品/供应商/客户/资金账户名称均以「演示」开头，无空名
2. [ ] 采购订单已审核；入库已过账；采购发票已过账（应付已生成）
3. [ ] 付款单已过账，应付已核销
4. [ ] 销售订单已审核；出库已过账（扣库存、COGS）；销售发票已过账（应收已生成）
5. [ ] 收款单已过账，应收已核销
6. [ ] 期初 SKU（草稿纸/面粉）库存台账有 OPENING 流水
7. [ ] `GET /api/gl/periods/{period}/close-precheck`：`closeable=true`，ERROR 为空（`{period}` 为种子返回的 UTC 月，如 202610）
8. [ ] （可选手测）确认关账卡片后关账：账期 CLOSED；再过账被拒。本步**不要**用种子脚本代劳
9. [ ] 缺口通道见下一节：能列出样例缺口，并能再记一条试点问题

无浏览器时，第 1–7 步由 `DemoSeedFlowIntegrationTest` 覆盖；第 8–9 步须手测或聊天。

## 缺口通道用法

系统**没有**「创建缺口」REST。创建入口是 Agent 工具 `record_process_gap`（常驻，登录用户可在聊天里让 Agent 记）。

试点中发现系统做不到的事时：

1. 打开 **Agent 助手**，用中文描述场景、期望、现在缺什么。
2. 确认后让 Agent 调用 `record_process_gap`（模块如 FINANCE/PURCHASE，严重度 LOW/MEDIUM/HIGH）。
3. 记下返回的 `GAP-yyyyMM-序号`。
4. ADMIN/BOSS 用 `GET /api/gaps`（权限 `gap:triage`）查看、流转状态。不要物删。

种子会写一条样例缺口（标题前缀「演示试点样例缺口：」），证明通道可写。试点新问题请另开记录，不要改样例当正式缺陷。

## NO_WEB_DIST

任何提交不得改 `web-dist/`。`git diff --stat -- web-dist` 应为空。`seed-pilot.sh --check` 若发现工作区 `web-dist/` 有 diff 则失败。

## Pass / Fail

| 项 | Pass | Fail |
|---|---|---|
| 种子可装 | REST/`seed-pilot.sh` 200，单据号齐全 | 500/绕过状态机/空名 |
| 幂等 | 再装 `alreadyLoaded=true`，不重复建单 | 第二张同 marker 采购订单 |
| 互斥 | 已装 sunshine 再装 qinghe → 409 | 同一套账两套企业档案并行 |
| 关账预检 | 0 ERROR、账期仍 OPEN | 种子直接 CLOSED，或 ERROR 阻塞却当成功 |
| 缺口 | 样例缺口落库；文档写明 `record_process_gap` | 声称用 REST POST 创建缺口 |
| web-dist | 无变更 | 任何 `web-dist/` 文件进入提交 |
