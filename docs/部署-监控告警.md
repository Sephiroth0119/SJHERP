# SJHERP 监控告警（M8-T04）

面向**小企业私有部署**：一台机器上看接口是否慢、聊天花了多少 token、磁盘会不会把备份撑爆。不是云上 APM，也不引入 Prometheus Server / Grafana / PagerDuty。

一键安装见 [部署-一键安装.md](./部署-一键安装.md)；备份见 [部署-备份恢复.md](./部署-备份恢复.md)；HTTPS 见 [部署-安全基线.md](./部署-安全基线.md)。

## 1. 应用指标（接口耗时 / 错误率）

Spring Boot Actuator + Micrometer Prometheus 文本：

| 地址 | 谁能访问 | 内容 |
|---|---|---|
| `http://127.0.0.1:8081/actuator/prometheus` | 仅宿主机回环 | `http.server.requests`（次数、耗时直方图、status） |
| `http://127.0.0.1:8081/actuator/health` | 仅宿主机回环 | UP/DOWN，无细节 |
| `GET /api/ops/http-summary` | ADMIN / BOSS | 进程内累计请求、4xx/5xx、最大耗时（重启归零） |

nginx **不**反代 `/actuator`。compose 把 management 端口映射为 `127.0.0.1:${SJHERP_METRICS_PORT:-8081}:8081`，不要改成 `0.0.0.0`。公网健康检查仍走 `GET /api/health`（明文探活或 HTTPS）。

本机刮取示例：

```bash
curl -fsS http://127.0.0.1:8081/actuator/prometheus | grep http_server_requests
```

以后若自建 Prometheus，把 scrape target 指到上述地址即可。本仓库不附带 Prometheus 容器。

## 2. LLM 成本日报

真源是已有表 `agent_invocation`（M1-T06），按 UTC 自然日聚合 LLM 行的次数、失败、prompt/completion token、耗时。**不新建业务表**。

| 入口 | 说明 |
|---|---|
| `GET /api/ops/llm-daily?date=yyyy-MM-dd` | ADMIN/BOSS；`date` 省略则为当天（UTC） |
| 每天 00:05 UTC 日志 | `LlmDailySummaryJob` 打昨日汇总 |
| `SJHERP_ALERT_LLM_DAILY=true` | 把昨日汇总 POST 到 webhook（默认关） |

金额：只有同时配置了

```
SJHERP_LLM_PRICE_PROMPT_PER_MILLION=...
SJHERP_LLM_PRICE_COMPLETION_PER_MILLION=...
```

才用 `BigDecimal` 估算（4 位 HALF_UP，单位视为人民币）。**留空则 `estimatedCost` 为 null**，文案写明「只汇总 token，不估算金额」——厂商未返回 usage 的行按 0，这不是账单。

## 3. 错误告警

宿主机脚本 `./deploy/monitor.sh`（建议 cron，见 `deploy/crontab.example`）：

1. `GET /api/health` 非 UP → 失败（HTTPS 时与冒烟一样 `curl -k`）
2. 近窗 `docker compose logs app` 中 ` ERROR ` 行数超过 `SJHERP_ERROR_LOG_MAX`（默认 50 / 15m）→ 失败
3. 可选：刮取 Prometheus；端口不通记 WARN，不单独当致命（应用仍可能经 nginx 正常）

失败且配置了 `SJHERP_ALERT_WEBHOOK` 时 POST：

```json
{"text":"SJHERP 监控失败\n...","status":"CRIT","source":"sjherp-monitor"}
```

Slack Incoming Webhook 可直接吃 `text`。钉钉 / 企业微信需要一个小适配器把字段转成它们的 `msgtype`。相同失败内容默认去重（`deploy/backups/.last-alert-signature`），`--force-alert` 可强制重发。

邮件：本刀不内置 SMTP。把 webhook 指到自己的转发脚本（或 serverless）再发信即可。

应用进程内 webhook（`AlertWebhookClient`）只用于可选的 LLM 日报，**应用挂了发不出告警**——健康/磁盘必须靠宿主机 cron。

## 4. 磁盘 / 备份监控

检查 `deploy/backups/` 所在文件系统可用空间，以及：

| 文件 | 阈值 |
|---|---|
| `deploy/backups/mysql/latest.sql.gz` | 年龄 ≤ `SJHERP_BACKUP_MAX_AGE_HOURS`（默认 26，略大于每日 02:15 UTC cron） |
| `deploy/backups/qdrant/latest.snapshot` | 同上 |

磁盘可用 < `SJHERP_DISK_MIN_MB`（默认 1024）视为失败。刚装完还没跑过 `backup.sh` 时用：

```bash
./deploy/monitor.sh --allow-missing-backup
```

## 5. 立刻做

```bash
./deploy/monitor.sh --check          # 语法 + 自测过期备份逻辑
./deploy/backup.sh                   # 先有一份最新 dump
./deploy/monitor.sh                  # 健康 + 磁盘 + 备份新鲜度
```

crontab 在备份那一行下面加上（路径换成仓库根）：

```
10 3 * * * /bin/bash /ABS/PATH/TO/SJHERP/deploy/monitor.sh >> /ABS/PATH/TO/SJHERP/deploy/backups/monitor.log 2>&1
```

## 6. 环境变量

见 `deploy/.env.example`：`SJHERP_METRICS_PORT`、`SJHERP_DISK_MIN_MB`、`SJHERP_BACKUP_MAX_AGE_HOURS`、`SJHERP_ERROR_LOG_*`、`SJHERP_ALERT_WEBHOOK`、`SJHERP_ALERT_LLM_DAILY`、`SJHERP_LLM_PRICE_*`。密钥与 webhook URL 不要提交进 git。

## 7. 和安装 / 备份 / 安全的关系

- `./deploy/install.sh --check` 会跑 `monitor.sh --check`（含自测）
- CI 在 `restore-smoke.sh` 之后再跑 `monitor.sh`（此时已有新鲜备份）
- TLS 默认、`restore-smoke`、`smoke.sh --login` 行为不变
- **禁止改 `web-dist/`**；不引入 Prometheus/Grafana 容器；无 Flyway 业务迁移
