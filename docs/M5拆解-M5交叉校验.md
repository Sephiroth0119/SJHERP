> 范围：领料-工单成本-完工入库-存货-凭证**全链路勾稽**——把生产链端到端应恒成立的不变式固化为
> `ConsistencyCheckService` 显式校验规则 + 一条端到端真库集成测试（0 ERROR break），并产出交叉校验报告。

## 0. 范围红线 + 关键事实（已核对代码）
- **做**：把 M5 生产链全链路勾稽不变式固化为 `ConsistencyCheckService` 新规则（接 §2 接入点三处改动模式）+ 端到端集成测试 + 交叉校验报告（本文 §6）。
- **不做**：新业务功能、新单据、新 REST 写端点、新权限点（交叉校验是只读校验，复用既有 `run_consistency_check` 工具/`/api/consistency` 端点/`@Scheduled` 检查 Agent）；不新增迁移（纯只读 SQL）。
- **关键事实**（已核对）：
  - ① `ConsistencyCheckService` 现有 11 规则，**生产链仅规则 11（完工工单工费已结转，WARN 非阻塞）**——全链路金额勾稽尚无 ERROR 级固化。
  - ② 新增规则标准三处改动：`ConsistencyCheckType` 加枚举 → `ConsistencyCheckDao` 加 record+RowMapper+只读聚合 SQL → `ConsistencyCheckService` 加纯比对静态方法 + `check()` 接线 + 单测。
  - ③ 比对一律 `BigDecimal#compareTo`（规避 750 与 750.00 标度差异）；SUM/列 NULL 经 `nz()`/`COALESCE` 收敛 0；只读 DAO 零写路径（红线：纠错走红字冲销不静默改账）。
  - ④ 库存流水类型：`PRODUCTION_ISSUE`(OUT) / `PRODUCTION_RETURN`(IN) / `PRODUCTION_IN`(IN) / `CostAdjust`(NEUTRAL，调金额不调量)。
  - ⑤ 生产 GL 科目：5001 生产成本（WIP，借方余额）/ 5101 制造费用 / 2211 应付职工薪酬 / 1403 原材料 / 1405 库存商品（产成品）。生产凭证「已过账集」口径同 M4-T07a 红线：`status IN (APPROVED, REVERSED)`。

## 1. 全链路勾稽不变式清单（T08 核心）
> 每条：等式 / 涉及表字段 / 严重度 / 依据。ERROR=动了真账须阻塞；WARN=提示非阻塞（避免误卡关账）。

| # | 不变式 | 涉及表/字段 | 严重度 | 依据 |
|---|--------|-----------|--------|------|
| INV-1 领料出库勾稽 | 领料单行 `issued_cost`（负）的绝对值 ≡ 该领料单 PRODUCTION_ISSUE 库存流水 Σ\|total_cost\| | material_issue_line.issued_cost ↔ inventory_transaction(PRODUCTION_ISSUE, src_doc_no=MI) | ERROR | 领料过账唯一入口，issuedCost=totalCost().negate()（T04） |
| INV-2 退料入库勾稽 | 退料单行金额 ≡ 该退料单 PRODUCTION_RETURN 库存流水 Σtotal_cost（按原领料成本） | material_return_line ↔ inventory_transaction(PRODUCTION_RETURN) | ERROR | 退料按原领料成本入回（T04） |
| INV-3 完工入库勾稽 | 报工单 `inbound_cost`（正）≡ 该报工单 PRODUCTION_IN 库存流水 Σtotal_cost | production_report.inbound_cost ↔ inventory_transaction(PRODUCTION_IN, src_doc_no=PR) | ERROR | 完工入库唯一入口，增量料费模型（T05） |
| INV-4 工单完工量勾稽 | 工单 `completed_qty` ≡ Σ该工单已过账报工单 `completed_qty` | work_order.completed_qty ↔ Σ production_report(COMPLETED).completed_qty | ERROR | recordCompletion 累加回写（T05 D11） |
| INV-5 料费守恒（R1） | Σ工单完工入库料金额（PRODUCTION_IN）≡ Σ该工单领料净出库料金额（PRODUCTION_ISSUE − PRODUCTION_RETURN） | inventory_transaction 按 work_order 维度净额 | ERROR | T05↔T06 硬边界：料 100% 随完工结转，T06 不动料（R1） |
| INV-6 成本结转工费勾稽 | 成本结转单行 `completed_cost` 中工费增量 ≡ 经 CostAdjust 追加到产成品的金额 | production_cost_settlement_line ↔ inventory_transaction(CostAdjust) | ERROR | 工费经库存唯一入口 CostAdjust 追加（T06） |
| INV-7 生产凭证借贷平衡 | 每张生产来源凭证 Σ借 = Σ贷 | voucher_line（生产来源 voucher） | ERROR（理论恒成立，兜底） | 保存即校验借贷平衡（M4-T01） |
| INV-8 WIP 5001 勾稽 | 5001 借方余额 = Σ(料归集借5001+工费归集借5001) − Σ完工结转贷5001 ≥ 0（在产留存） | voucher_line(account=5001) | WARN | WIP 留 5001 借方余额（T06 ADR） |
| INV-9 完工工单工费已结转 | 已有规则 11（completed_qty>0 工单应有已过账成本结转行） | work_order ↔ production_cost_settlement_line | WARN | 既有（M5-T06 D9），不改 |

## 2. 新增规则接入点（三处改动模式，逐条照 §1）
拟固化为新 ERROR 规则：**INV-1、INV-3、INV-4、INV-5**（领料/完工入库/完工量/料费守恒——动真账的金额数量勾稽）。
INV-2 随 INV-1 对称纳入。INV-6/INV-8 视 opus 报告判断（INV-6 若已被现有库存恒等式规则1/2 间接覆盖则不重复固化；INV-8 WARN）。INV-7 借贷平衡保存即校验，集成测断言即可，按报告定是否兜底成规则。
> **最终规则清单与编号以 opus 交叉校验报告（§6）确认的缺口为准**——优先固化「仅靠流程隐式保证、无显式校验」者，已被规则1/2/集成测断言覆盖者不重复。

每条新规则：
1. `ConsistencyCheckType` 加枚举（code + 中文名，编号续 12…）。
2. `ConsistencyCheckDao` 加 record + RowMapper + `@Transactional(readOnly=true)` 聚合 SQL（LEFT JOIN 防丢行、tenant_id=0、COALESCE 收敛）。
3. `ConsistencyCheckService`：加纯比对静态方法（入参聚合行 record，无 IO 可单测）+ `check()` 内 for 接线。

## 6. 交叉校验报告（opus agent 产出，已折入）

### 6.1 现状结论
M5 生产链当前**几乎无固化勾稽**：`ConsistencyCheckService` 11 规则中仅规则 1/2（库存数量/金额恒等式，ERROR）自动纳入 PRODUCTION_ISSUE/RETURN/IN/CostAdjust 流水、规则 11（WARN）只查「完工工单是否做了成本结转」存在性。承载生产链财务正确性的 I1–I8（尤其 **R1 料费守恒 I4**）**全部仅靠 `post()` 流程过程正确性隐式保证**，无 DAO 事后对账规则，也无一条端到端集成测试串完整链路。

### 6.2 最终敲定的新规则清单（本批实现规则 12–16）
| 新规则 | ConsistencyCheckType | 严重度 | 比对逻辑 |
|---|---|---|---|
| 规则12 | `MATERIAL_ISSUE_COST`（领料/退料成本勾稽） | ERROR | COMPLETED 领料行 `issued_cost` ≡ −Σ PRODUCTION_ISSUE.total_cost；COMPLETED 退料行 `returned_cost` ≡ Σ PRODUCTION_RETURN.total_cost |
| 规则13 | `PRODUCTION_INBOUND_COST`（完工入库成本勾稽） | ERROR | COMPLETED 报工单 `inbound_cost` ≡ Σ PRODUCTION_IN.total_cost |
| 规则14 | `WORK_ORDER_MATERIAL_CONSERVATION`（工单料费守恒 R1） | **ERROR（超额）/ WARN（差额=WIP）** | 每工单 Σinbound_cost vs Σissued_net(=Σissued−Σreturned)：diff=Σinbound−Σissued_net **> 0.01（1 分容差）→ ERROR**（料虚增 R1 破）；0<diff≤0.01 入库 round2×qty 舍入残差不报；diff<0 → WARN（WIP 在产料） |
| 规则15 | `WORK_ORDER_COMPLETED_QTY`（完工量勾稽） | ERROR | work_order.completed_qty ≡ Σ已过账报工.completed_qty |
| 规则16 | `COST_SETTLEMENT_ADJUST`（工费追加勾稽） | ERROR | COMPLETED 结转行工费增量 ≡ Σ COST_ADJUST.total_cost（该 PC 单号+行号） |

> **规则14 容差（评审 P2-2 修复）**：ERROR 侧加 1 分容差——增量料费模型使 Σ完工入库料收敛到 Σ净领料，仅差最后一张报工「单位成本 round2×completedQty」的舍入残差（≤~0.0000005×qty 量级）；若按精确 compareTo 判定，该残差会落入 `diff>0` 误报 ERROR 阻塞月末关账。仅当 diff>0.01 方判真料虚增；WARN 侧（在产 WIP）不变。
> **规则15 旁证范围（评审 P3-1 据实）**：本规则仅核对 `work_order.completed_qty` ≡ Σ已过账报工 `completed_qty`，**不**交叉核对 Σ PRODUCTION_IN.quantity（二者当前同源 `pr.completedQty` 驱动，无活跃缺陷）；该数量旁证登记后续可选增强，本批不扩实现。
> 规则17（产成品账证 1405 GL↔库存勾稽）**本批不固化**——依赖 P2-B 科目错配先裁定（否则 1403/1405 错配会使其持续误报），登记后续。

### 6.3 红线发现（升报用户裁定 + 登记技术债）
- **P2-A【R1 真实缺陷，需裁定】**：`ProductionReportService.sumIssuedCostForWorkOrder` 只累加领料 issuedCost 毛额、不减退料 → 「报工后退料」路径下 Σ完工入库料 > Σ净领料，违反 R1「Σ完工入库料成本 ≡ Σ领料**净**出库成本」。修复互斥方案：①`sumIssuedCostForWorkOrder` 改净额（减退料）②领域约束「工单有已过账报工后禁退料」③仅靠规则14 ERROR 兜底。confidence 中高。
  - **【裁定 2026-06-28：方案① 改净额，已落地】** 本批将原 `sumIssuedCostForWorkOrder` **重命名为 `sumNetIssuedCostForWorkOrder`** 并改为 **Σ领料 issuedCost − Σ退料 returnedCost**（净额口径，`ProductionReportService` 新注入 `MaterialReturnRepository`，退料经 `material_issue_doc_no` 关联领料单 → 按工单领料单号反查 COMPLETED 退料累计退回成本），使 R1 在「报工后退料」路径下恒成立，补该路径单测（报工前退料净额减退料/报工后退料致增量≤0 拒过账/无退料净额==毛额回归）。**规则14 ERROR 保留为纵深防御**（即便未来改动重新破坏 R1 也能事后探测+阻塞关账；尤其「全部报工完成后再退料」无法回溯抵减已入库，规则14 是该病态路径唯一防线，新增端到端集成测试验证）。
- **P2-B【科目错配，需会计裁定/ADR】**：生产料归集贷 1403 原材料，但 M3 采购入库借 1405 库存商品 → 1403 长期贷方负余额、存货科目分类失真（存货**总额** 1403+1405 仍 tie-out，仅科目级失真）。修复需统一原材料采购入库与生产领料归集的存货科目口径，属会计政策裁定。confidence 中（结构性隐患，当前测试未覆盖采购→生产组合）。
  - **【裁定 2026-06-28：登记 ADR 后续修】** 本批**不改科目口径**（改动触及 M3 采购凭证模板，范围超出 T08 交叉校验本身）。起 ADR 草案 `docs/ADR-003-存货科目口径统一.md` 记录现状/影响/候选方案，登记技术债 R-T08-2，排后续任务修复。规则17（产成品账证 1405 GL↔库存勾稽）随本裁定一并延后（避免在科目错配未修前持续误报）。
- **P3-A**：成本结转双锚点跨「建单→过账」口径不一致（已登记 R-T06-8），规则16 可作事后探测网。
- **P3-B**：生产单据（报工/领料/成本结转）COMPLETED 后无红冲路径，与 M4「全单据类型红冲」红线不对齐（`NoPhysicalDeleteArchitectureTest` 已护「不可删」，「可冲销」未满足）；属 M5 后续任务，登记。
- **P3-C**：规则11 仅 WARN，生产链此前无 ERROR 级专属勾稽 → 料虚增可静默逃逸关账闸门；规则14 ERROR 补此洞。
