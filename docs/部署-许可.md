# 部署：离线许可（M8-T08）

SJHERP 是小企业**私有部署**，不是在线计费中心。本页只说明如何放置和检查离线 license。商业模式（买断 / 订阅 / 免费+服务）未定，本骨架不收费、不锁死。

## 默认行为

| 情况 | 结果 |
|---|---|
| 未放置 license 文件 | **未配置**，业务照常可用（开发 / 试用 / 试点默认） |
| 文件有效且未到期 | 有效；帮助页显示签发对象与到期日 |
| 已过到期日、仍在宽限 | 宽限期内，只提示，不阻断 |
| 过期超过宽限 / 签名无效 / 文件坏掉 | 默认只警告。仅当 `SJHERP_LICENSE_ENFORCE=true` 时硬阻断业务 API |

硬阻断仍放行：`GET /api/health`、登录、`GET /api/auth/me`、`GET /api/license/status`、本机 actuator，避免把试点客户锁死。

## 放置文件

1. 向供应商索取 `sjherp.license.json` 和验签公钥 PEM（生产私钥不在本仓库）。
2. 放到 `deploy/license/sjherp.license.json`。该文件已被 gitignore。
3. 生产公钥二选一：
   - `SJHERP_LICENSE_PUBLIC_KEY_PATH=/app/license/vendor-public.pem`（同时把 PEM 放进 `deploy/license/`）
   - 或把 PEM 正文写入 `SJHERP_LICENSE_PUBLIC_KEY`
4. 留空公钥变量时，应用使用镜像内**测试公钥**（只认仓库样例密钥签发的文件，不能当生产）。
5. `docker compose up -d` 后 app 只读挂载 `deploy/license` → `/app/license`。

`deploy/.env.example` 已列出变量。不要把真实生产私钥提交进 git。

## 脚本

```bash
chmod +x deploy/license.sh
./deploy/license.sh --check
./deploy/license.sh --verify --file deploy/license/sample.license.json
./deploy/license.sh --issue --subject "试点客户" --expires 2027-10-23 --seats 5 \
  --out deploy/license/sjherp.license.json
```

`--check` 不需要 Docker：脚本语法、样例 JSON 解析、用测试公钥验签、确认硬阻断默认关闭、`NO_WEB_DIST`。

Java 签发 CLI（需已编译 app 类路径）与脚本等价，见 `com.sjherp.app.license.LicenseCli`。

## 管理员查看

登录 ADMIN/BOSS → **帮助** → 「许可状态」。接口：`GET /api/license/status`（`license:view`）。没有支付、下单或订阅 UI。

## 与一键安装的关系

`./deploy/install.sh --check` 会调用 `license.sh --check`。生产一键安装**不要**打开 `SJHERP_LICENSE_ENFORCE`，除非供应商已经签发正式文件并且你明确要在过期后停业务。
