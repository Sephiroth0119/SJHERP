# M5-T05 报工与完工入库 拆解与实现方案

> 路线图 §7 M5-T05（M 级）。本文是 T05 单一设计真源。
> 范围：报工（工时记录 + 完工数量）+ 完工入库（在产品→产成品，走 M3 库存唯一写入口）。
> 验收：完工入库真实增加产成品库存（移动加权不被稀释）、回写工单累计完工量；工时落库供 T06 归集。

## 0. 范围红线 + 关键事实
- **做**：报工单（ProductionReport）= 工时记录 + 完工数量 + 完工入库（经 InventoryPostingPort 唯一入口）；回写工单 completedQty。
- **不做**：料工费完整归集与成本结转（T06）、GL 凭证（T06）、报废成本核算（T06）、完工冲销/退库（后续）、Agent 工具（T07）。
- **关键事实**（Plan 核对）：① 库存唯一写入口范式已稳固，**复用现有 `InventoryPostingPort` + `MaterialIssueInventoryPostingAdapter`，不新建端口/适配器**。② `WorkOrder.completedQty` 当前只读且 **`JdbcWorkOrderRepository.update` 不写 completed_qty 列**——T05 必须补回写行为 + 改 update SQL（同 M5-T03 reversedById 漏写同类隐患）。③ 产品档案无标准成本/计划成本字段 → 完工入库成本只能取已发生料费。④ **新增 InventoryTxnType 值后务必核对 inventory_transaction.txn_type 列宽**（T04 CI 教训：VARCHAR(16) 容不下 17 字符值；本批 PRODUCTION_IN 仅 12 字符，列已在 V28 加宽到 32，安全）。最新迁移 V28→本批 **V29**。

## 1. 关键裁定清单（D1–D11，附推荐）
| # | 决策点 | 裁定 |
|---|--------|------|
| D1 | 聚合分合 | **合一**：`ProductionReport` 一单管工时+完工量+完工入库（小企业一次车间动作，分离引入跨单勾稽/二次幂等，违从简取向） |
| D2 | 完工入库成本来源 | **料费占位成本**：该工单**所有已过账领料单 issuedCost 之和 ÷ 本次完工量**作单位成本，显式 unitCost 入库（同 PRODUCTION_RETURN 范式，金额来自真实领料出库不凭空生成）。否决零成本（稀释移动加权，违 T04 评审 P2 同理）/否决暂不入库（违任务标题与"完工入库走唯一入口"） |
| D3 | 无料费时 | **拒绝过账**（照 MaterialReturn.resolveUnitCost 无成本即拒范式），纯外购/无料工单成本由 T06 兜底，登记 R3 |
| D4 | 工单完工触发 | **不自动**推进工单 EXECUTING→COMPLETED；completedQty≥plannedQty 仅软提示，手工点完工（保持 T03 状态机白名单不改） |
| D5 | 超额完工 | **允许**，recordCompletion 仅校验非负/>0，不硬卡 ≤plannedQty（与领料不卡 BOM 用量上限的宽松取向一致），登记 R4 |
| D6 | 库存枚举 | 新增 `InventoryTxnType.PRODUCTION_IN`（Direction.IN，"完工入库"），本批唯一枚举改动 |
| D7 | 端口/适配器 | **复用**现有 InventoryPostingPort + 适配器，不新建 |
| D8 | 权限点 | 新增 `production:report`（"报工与完工入库"；优于 complete[单据同时管工时+完工+入库，report 涵盖广]，优于复用 wo/material[独立车间动作分开授权]） |
| D9 | 工时计费 | T05 **不算钱**，只存 reportedHours（DECIMAL(18,6)），costRate/laborCost 留 T06 |
| D10 | scrapQty | 记录但**不入库**，报废成本核算留 T06 |
| D11 | WorkOrder 改动 | 新增 `recordCompletion(qty, operator)` 累加 completedQty（防负）；**修 JdbcWorkOrderRepository.update 补 completed_qty 列**（当前漏写，回写会静默丢失） |

## 2. 领域模型（com.sjherp.domain.production 续建，纯 Java 零依赖）
- `ProductionReport extends BusinessDocument`（header）：
  - 字段：id/docNo（PR- 前缀）/workOrderDocNo（必填，工单须 EXECUTING）/warehouseId（产成品入库仓）/productId（冗余自工单，校验=工单 productId）/completedQty（本次合格入库量 BigDecimal>0）/scrapQty（报废量 ≥0 默认 0，不入库）/unitId/inboundCost（过账回填，正数 2 位）/remark/状态机六态/reversal 链路/审计4。
  - 行集合 `List<ProductionReportLine>`（工时行，至少一行）。
  - 不覆写 beforeTransition（基类六态全表，同 MaterialIssue）。状态机 DRAFT→APPROVED→EXECUTING→COMPLETED；DRAFT→CANCELLED。过账=APPROVED→EXECUTING→COMPLETED。
  - 方法：create（校验工单 EXECUTING/productId 一致/completedQty>0/scrapQty≥0/至少一行工时）、restore、assignId、assignInboundCost（回填一次 ≥0 2 位）。
- `ProductionReportLine`（工时行）：id/lineNo/operationSeqNo（可空，工序序号快照弱关联）/operationName（可空快照）/workCenter（可空快照，T06 用）/reportedHours（BigDecimal>0，6 位）/reportedQty（可空，默认=completedQty）/unitId。**不设 costRate/laborCost**（T06）。
- `ProductionReportService`（@Audited create/approve/post/cancel + get/search）：post 编排见 §3。依赖 ProductionReportRepository + InventoryPostingPort + WorkOrderRepository + MaterialIssueRepository（取料费）。
- `WorkOrder` 加 `recordCompletion(BigDecimal qty, String operator)`：completedQty=completedQty.add(qty)，校验 qty>0。

## 3. 报工过账编排（核心，照 MaterialIssueService 双层范式）
```
ProductionReportAppService.post(docNo, op)  [@Transactional 外层]
 └ productionReportService.post(docNo, op)  [@Audited]
    1 pr=get; registerEventPublisher
    2 校验关联工单存在且 EXECUTING
    3 unitCost = Σ(该工单已过账领料单各行 issuedCost) / pr.completedQty
         └ 若工单无已过账领料/料费 Σ=0 → 抛 IllegalArgumentException（D3 拒绝零成本入库）
    4 pr.startExecution(op)               // APPROVED→EXECUTING
    5 cmd=InboundCommand(warehouseId, productId, PRODUCTION_IN, completedQty, unitCost,
              null, "PRODUCTION_REPORT", docNo, 1, 幂等键 PRODUCTION_REPORT:docNo:1)
    6 results=inventory.execute(List.of(cmd), op)   // 唯一入口，移动加权
    7 pr.assignInboundCost(result.totalCost())       // 入库为正
    8 workOrder.recordCompletion(completedQty, op); workOrderRepository.save(workOrder)  // 回写累计完工量
    9 pr.complete(op)                     // EXECUTING→COMPLETED
   10 save
 └ 本批不调 autoVoucherService（GL 留 T06）
```
> 料费汇总口径：取 workOrderDocNo 关联的全部 COMPLETED 领料单的行 issuedCost 求和。分批完工时按"本次完工量 × (累计料费/工单累计完工量)"近似分摊为 R2 登记（T05 简化：首次/单次完工按已领料全额 ÷ 本次完工量）。

## 7. 风险与遗留登记
- R1（成本边界核心）：T05 入库成本仅含"料"（已过账领料汇总），不含"工""费"。T06 须在产成品库存上追加 COST_ADJUST（工费增量）并出 GL。**勾稽契约**：T05 入库金额 ≡ 该工单领料出库金额（料的进出守恒）；T06 只动增量，不改写 T05 已入金额。T05/T06 切分硬边界，T06 文档须引用本条。
- R2（分批完工料费分摊）：多次报工料费分摊未完全定义；T05 近似"本次完工量×(累计料费/累计完工量)"，精确分摊（标准成本/约当产量）留 T06。
- R3（无料工单/纯外购完工）：料费=0 时 T05 拒绝完工入库，成本由 T06 全工费结转兜底。
- R4（超额完工无上限）：T05 允许超 plannedQty，无阈值/审批控制，留后续。
- R5（工单自动完工）：T05 不自动推进工单 COMPLETED，completedQty≥plannedQty 仅软提示，自动完工/关闭联动留后续。
- R6（完工入库冲销/报废返工）：报工单不实现 COMPLETED→REVERSED（同 MaterialIssue R7）；完工冲销/退库留独立单后续；scrapQty 仅记录不入库，报废成本核算属 T06。
- R7（GL 凭证）：T05 不出 GL，完工入库 GL（在产品→产成品科目结转）留 T06。
- R8（工时与工序弱关联）：工时行存工序快照不强校验是否在当前工艺路线版本内（路线可改版），可能产生孤儿工时，T06 归集需容错。

## 8. 评审修复（opus 单镜头对抗校验）
- **0 阻断剩余**；库存唯一入口/原子性/状态机/@Audited/精度/权限三处同步/DTO 校验经审查全部正确。
- **P0 已修（财务正确性红线）**：分批完工（≥2 张报工单）时料费**重复入账**——原 post 每次都把工单**全部** COMPLETED 领料 issuedCost 重新求和再除本次完工量，第二张报工把前序已结转料费又计一遍，产成品库存价值虚增、污染移动加权、违反 R1"料的进出守恒"。修复=**增量模型**：本次结转料费 = 工单全部已过账领料 issuedCost − 前序报工已结转料费（`ProductionReportRepository.sumInboundCostByWorkOrder` 锚点，仅统计 COMPLETED 报工 inbound_cost）；增量≤0 拒过账（D3 扩展，防零成本入库稀释）。新增/改造 3 单测固化（多次报工 inbound_cost=增量+Σ守恒、增量=0 拒绝、集成测断言成品 cost_amount=Σ领料出库）。**根因暴露**：原"多次报工"单测与集成测**只断言数量/completedQty 不断言金额**，掩盖了缺陷——已补 cost_amount/inboundCost 断言。
- **P1 已修**：`ProductionReport.assignInboundCost` Javadoc 称"只回填一次"但无守门（仅靠状态机间接挡）→ 补 `if (inboundCost != null) throw IllegalStateException`，与 assignId 范式一致。
- **P3 已修**：inboundCost 字段 Javadoc 据实改为增量口径（原描述"按累计完工量分摊"与实现不符）。
- **P2 登记（遗留）**：unitCost=增量÷completedQty 舍入后 ×completedQty 反算 totalCost 回填，除不尽时与原料费有 ≤1 分残差（同 M4-T07 库存红冲残差模式）；后续引入 InboundCommand.overriddenTotalCost 直传总额消除（与 R1/T07 遗留合并）。
