# 业务说明 — 采购（下单 → 收货 → 发票应付）

> 面向业务读者：讲采购全流程的业务含义、各单据状态、为什么要这样校验，不讲代码实现。
> 对应任务：M3-T05 采购订单 / M3-T06 采购入库单 / M3-T07 采购发票与应付（路线图 §5 采购线）。

## 一、采购线一句话

向供应商买东西，要走三张单子，环环相扣：

1. **采购订单（PO-）**：先和供应商说好「我要买什么、买多少、什么价」——这是**承诺**，还没真的拿到货。
2. **采购入库单（PR-）**：货到了，清点入库——这一步**库存才真正增加**。
3. **采购发票（PINV-）**：供应商把发票开来，登记并核对——这一步**生成应付账款**（我们欠供应商多少钱）。

为什么要拆成三张单、而不是一张？因为现实里这三件事经常**不同时发生**：订了 100 个，可能分两次到货（先到 60 再到 40）；货到了发票还没寄来；发票金额可能比订单价多一点（运费）。拆开记，才能如实反映「订了多少 / 到了多少 / 该付多少」这三笔账，账才不会糊。

## 二、采购订单（PO-）

### 它是什么
对供应商的采购承诺。单据头写明**供应商**和**下单日期**，每一行写一个商品的**订购数量、采购单价、行金额**（金额 = 数量 × 单价）。

### 关键点：下单不动库存
下了采购订单，仓库里的库存**一点不变**——因为货还没到。采购订单只是「打算买」，不是「已经有」。库存只有在收货（采购入库单过账）那一刻才会增加。这是很多人最容易搞混的地方。

### 状态怎么走
- **草稿**：刚建好，可以作废（还没产生任何承诺影响）。
- **已审核**：确认无误后审核，内容锁定，**从这一刻起才可以收货**。
- **已关闭**：这批采购完成了（或主动不再收货），关闭后不再收货。

每一行还记一个**累计到货量**：每次收货过账时自动累加，用来跟踪「这一行订了 100，已经到了 60，还差 40」。

### 小例子
向「华东金属」下单：不锈钢板 100 张 @50 元（行金额 5000）、螺丝 2000 颗 @0.5 元（行金额 1000）。订单总额 6000 元。此刻库存里这两样东西一个没多——只是约定好了。审核后，这张单就等着收货。

## 三、采购入库单（PR-）

### 它是什么
按某张采购订单收货的单子。单据头引用**一张采购订单** + **收货仓库** + **收货日期**，每一行引用采购订单的某一行，写**这次收了多少、收货单价是多少**（收货单价默认就是采购订单上的单价，可以改）。

### 关键点 1：支持部分收货
不要求一次收完。可以「先收 60，过几天再收 40」。系统会卡一条硬规则：**每次收货数量不能超过该采购订单行的「未收量」**。比如订了 100、已收 60，这次最多只能再收 40，填 50 会被拒绝。为什么要卡？因为收货数量超过订单量，要么是录错了，要么是流程出了问题——宁可拦下让人核对，也不能让「实际到货」对不上「当初订的」，账一旦对不上就很难查。

### 关键点 2：收货才动库存，而且只走「唯一入口」
采购入库单**审核 → 过账**后，库存才真正增加。过账时，系统对每一行生成一笔「采购入库」的库存流水（入库单价 = 收货单价），并且**同一笔操作里**把到货量回写到采购订单对应行的「累计到货量」。

这两件事（库存增加 + 订单到货量更新）是**绑在一起、要么都成功要么都不做**的。绝不会出现「库存进了、但订单上还显示没到货」这种自相矛盾的状态。库存的增加一律走全系统**唯一的库存写入口**（和盘点、调拨用的是同一个口子），保证库存成本用统一的移动加权口径算、账永远平。

### 状态怎么走
草稿 → 已审核 → （过账中）→ 已完成。已完成的入库单只能冲销（退货红字单，M4 阶段统一做），不能删改——收货是已经发生的事实，财务上只能用反向单据抵消，不能假装没发生。

### 小例子
接上例，这批 100 张不锈钢板分两次到。第一张采购入库单：引用那张采购订单的不锈钢板行，收 60 张 @50。过账后：仓库里不锈钢板 +60，采购订单那一行显示「已到货 60 / 还差 40」。第二次再开一张入库单收剩下的 40，过账后订单那行变成「已到货 100 / 已收齐」。

## 四、采购发票与应付（PINV-）

### 它是什么
登记供应商开来的发票，并和收货单核对。单据头引用**一张采购入库单**，每一行引用收货的某一行，写**开票数量、开票金额**。

### 关键点 1：三单匹配（从简）+ 重复开票防控
「三单」指采购订单、采购入库单、采购发票。三单匹配就是核对这三张单子对不对得上，防止多付钱。本期从简，只卡最要紧的一条：**发票上的开票数量不能超过实际收到的数量**——而且是**跨发票累计**地卡。

为什么这条最要紧？因为应付（我们要付的钱）是按发票算的。如果发票数量超过实收，就会**虚增应付**——明明只收到 60 个的货，发票却开 100 个的钱，付出去就亏了。所以发票数量超过已收，直接拒绝。

**跨发票防重复**：每张收货行都记一个「累计已开票量」。开票时卡的是**剩余可开票量 = 收货量 − 已开票量**，不是单看本张发票。比如收了 60，开过一张 60 的发票（已开满），再对同一收货行开第二张，剩余可开票量是 0，直接拒绝——不会因为换了个发票号就能重复全额开票把应付翻倍。分次开也支持：先开 40（剩 20），再开 20（开满），第三张就开不出来了。发票一旦过账，回写量在同一笔事务里落库，和应付生成同生共死（要么都成、要么都回滚）。

注意：**金额**不强制等于「数量 × 收货单价」。因为发票里常会有运费、折扣、税差，导致金额和当初的货款有合理出入，所以金额由发票上的实际数字填，系统不硬卡——但数量这条红线必须守住。

另外，只有**已过账**（库存已入账）的采购入库单才能开票——东西都还没确认收到，凭什么认这笔账。

### 关键点 2：过账生成应付账款
采购发票**审核 → 过账**后，系统生成一笔**应付账款**：欠哪个供应商、欠多少（= 发票总额）、来源是哪张发票、**什么时候到期**、状态「未核销」。

到期日按供应商的**结算方式**自动算：
- **现结 / 预付**：到期日 = 发票日（货到付款 / 已先付）。
- **月结**：到期日 = 次月同日（月底对账后下月结）。

「未核销」意思是这笔钱还没付。真正的**付款核销**（付了钱把应付勾掉，支持分次付）在后续的财务模块（M4）做，本期只负责把「该付多少、什么时候付」如实记下来。

应付账款是**财务台账记录**，只能新增、不能修改删除（这是财务铁律）。记错了只能用红字发票冲销，不能直接改数字——保证每一分钱的来龙去脉都查得到。

### 小例子
接上例，「华东金属」把不锈钢板那批 100 张的发票寄来了，金额 5050 元（5000 货款 + 50 运费）。开一张采购发票，引用那张已过账的入库单，开票数量 100（没超过已收的 100，通过）、金额 5050。审核、过账后，生成一笔应付：欠华东金属 5050 元，来源 PINV-…，月结的话到期日是下个月今天，状态「未核销」。在「应付列表」里就能看到这笔账，等财务去付款核销。

## 五、采购线与库存成本的关系

- **下单**：不碰库存、不碰成本（只是承诺）。
- **收货过账**：库存数量增加、库存金额按收货单价增加，企业的存货成本由此累积（用移动加权口径，和盘点/调拨同一套算法，账永远平）。
- **开票过账**：不碰库存（货早在收货时就入账了），只生成应付——把「欠供应商的钱」单独立账。

一句话串起来：**订单管「打算买多少」，入库管「实际进了多少货、多少成本」，发票管「实际欠多少钱」。** 三笔账各管一摊、互相勾稽，谁也别想糊弄。

## 六、谁能操作（权限）

- **采购订单**（下单/审核/关闭/查询）：管理员、老板、采购。
- **采购入库单**（收货/审核/过账/查询）：管理员、老板、采购、仓管（仓管负责实际收货入库）。
- **采购发票**（登记/审核/过账/查询）：管理员、老板、采购、会计（会计负责发票与应付）。
- **应付列表查询**：登录即可看（只读台账）。
