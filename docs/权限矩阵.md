# 权限矩阵（M2-T06）

> 状态：v1.0（2026-06，M2-T06 交付）
> 代码（单一真源，本文档与之同步维护）：
> `server/sjherp-domain/.../identity/Permission.java`（权限点定义）、
> `server/sjherp-domain/.../identity/RolePermissions.java`（角色→权限静态映射，EnumMap，不落库）
> 接线：工具层 `app/security/RolePermissionToolChecker`（实现 agent 的 `ToolPermissionChecker`，AgentInfraConfig 装配进 AgentLoop）；
> REST 层 `app/security/PermissionGuard`（bean 名 `perm`，`@PreAuthorize("@perm.has('...')")`）
> 关联：[领域工具清单.md](./领域工具清单.md)（工具的 requiredPermission 声明）

## 1. 设计约定

- **查询类操作无权限点**：登录即可（未登录统一 401）。
  - 例外：盘点（`inventory:count`）与调拨（`inventory:transfer`）的查询接口也要求对应权限点（控制器类级 `@PreAuthorize`）——因为盘点/调拨整体属于受控动作，非公开台账。
  - 例外（采购线 M3-T05/T06/T07）：采购订单（`purchase:order`）、采购入库单（`purchase:receipt`）、采购发票（`purchase:invoice`）的查询接口同样要求对应权限点（控制器类级 `@PreAuthorize`，受控动作）；唯独 GET /api/payables 应付列表查询登录即可（只读台账，无权限点）。
  - 例外（销售线 M3-T08/T09/T10）：销售订单（`sales:order`）、销售出库（`sales:delivery`）、销售发票与应收（`sales:invoice`）的查询接口同样要求对应权限点（受控动作，非公开台账；含 GET /api/receivables/**）。
- **双层同一矩阵**：Agent 工具与 REST 写接口共用 `RolePermissions`，口径绝不分叉。
  - 工具层：AgentLoop 执行前按 `ToolContext.userId` 实时查库取角色 → 矩阵判定；
    权限不足时工具**不执行**，"权限不足"错误回灌给模型，由模型向用户礼貌说明（不中断对话）。
  - REST 层：`@PreAuthorize` 判定失败统一 403 `{"error":"无权限执行该操作"}`。
- **宁拒勿放**：未知权限点 code、用户不存在/停用、userId 非法、查库异常——一律拒绝。
- **用户管理不走权限点**：UserAdminController 整体 `hasRole('ADMIN')`（M2-T05 既有约定）。
- **角色映射代码内静态定义**（小企业从简）：不落库、不可运行时配置；改矩阵 = 改代码 + 本文档 + `RolePermissionsTest`。

| `partner:create_customer` | 创建客户：工具 create_customer；REST POST /api/partner/customers | ✓ | ✓ | | ✓ | | |
| `partner:create_supplier` | 创建供应商：工具 create_supplier；REST POST /api/partner/suppliers | ✓ | ✓ | ✓ | | | |

| `catalog:write` | 商品域维护：商品更新/启停、类目与计量单位全部写操作 | ✓ | ✓ | | | | |
| `partner:write` | 往来域维护：客户/供应商的更新与启停 | ✓ | ✓ | | | | |
| `warehouse:write` | 仓库域维护：仓库的更新与启停 | ✓ | ✓ | | | ✓ | |
| `inventory:adjust` | 库存调整（期初建账 OPENING / 成本调整 COST_ADJUST）：工具 adjust_inventory；REST POST /api/inventory/adjustments（M3-T01c；库存余额/流水查询照例登录即可） | ✓ | ✓ | | | ✓ | |
| `inventory:count` | 库存盘点（创建/录入/审核/过账/查询）：工具 create_stock_count、query_stock_count；REST /api/inventory/stock-counts/**（M3-T03） | ✓ | ✓ | | | ✓ | |
| `inventory:transfer` | 库存调拨（建单/审核/过账/查询）：工具 create_transfer、query_transfer；REST /api/inventory/transfers/**（M3-T04） | ✓ | ✓ | | | ✓ | |
| `purchase:order` | 采购订单（下单/审核/关闭/查询）：工具 create_purchase_order、query_purchase_order；REST /api/purchase/orders/**（M3-T05） | ✓ | ✓ | ✓ | | | |
| `purchase:receipt` | 采购入库（收货/审核/过账/查询）：REST /api/purchase/receipts/**（M3-T06，过账产生 PURCHASE_IN 流水并回写 PO 到货量） | ✓ | ✓ | ✓ | | ✓ | |
| `purchase:invoice` | 采购发票（登记/审核/过账/查询）：REST /api/purchase/invoices/**（M3-T07，过账生成应付；GET /api/payables 登录即可，无权限点） | ✓ | ✓ | ✓ | | | ✓ |
| `sales:order` | 销售订单（建/审/作废/查）：工具 create_sales_order、query_sales_order；REST /api/sales/orders/**（M3-T08） | ✓ | ✓ | | ✓ | | |
| `sales:delivery` | 销售出库（建/审/过账/作废/查）：REST /api/sales/deliveries/**（M3-T09，过账产生 SALES_OUT 流水+结转 COGS） | ✓ | ✓ | | ✓ | ✓ | |
| `sales:invoice` | 销售发票与应收（发票建/审/过账/作废/查、查应收）：REST /api/sales/invoices/**、GET /api/receivables/**（M3-T10，过账生成应收 OPEN） | ✓ | ✓ | | ✓ | | ✓ |
| `gap:triage` | 缺口状态流转：REST POST /api/gaps/{id}/status | ✓ | ✓ | | | | |
| `demo:post_document` | 演示高风险工具（仅 dev/local 注册，生产不可达） | ✓ | | | | | |

角色口径（小企业从简）：

- **ADMIN**：全部权限点 + 用户管理（角色直接限定）。
- **BOSS**：全部业务权限点（不含用户管理、不含演示工具；含采购线 `purchase:*` 与销售线 `sales:*`）。
- **PURCHASER**：创建供应商 + 采购全程（`purchase:order`/`purchase:receipt`/`purchase:invoice`）；商品/档案查询登录即可。
- **SALES**：创建客户 + 销售全线（`sales:order`/`sales:delivery`/`sales:invoice`）。
- **WAREHOUSE**：仓库域全部（`warehouse:*`）+ 库存调整（`inventory:adjust`，M3-T01c）+ 库存盘点（`inventory:count`，M3-T03）+ 库存调拨（`inventory:transfer`，M3-T04）+ 采购收货（`purchase:receipt`，参与实物入库）+ 销售发货（`sales:delivery`，参与实物出库）。
- **ACCOUNTANT**：采购发票/应付（`purchase:invoice`）+ 销售发票/应收（`sales:invoice`，开票挂应收、查应收）；其余财务权限点（`finance:*`，过账/结账/付款核销等）留 M4 财务模块落地时补充，届时在 `Permission`/`RolePermissions` 与本表一并扩展。

## 3. REST 写接口 → 权限点对照

| 接口 | 权限点 |
|---|---|
| POST /api/catalog/products | catalog:create_product |
| PUT /api/catalog/products/{id}、POST .../enable\|disable | catalog:write |
| POST/PUT/DELETE /api/catalog/categories/** | catalog:write |
| POST/PUT/DELETE /api/catalog/units/** | catalog:write |
| POST /api/partner/customers | partner:create_customer |
| PUT /api/partner/customers/{id}、POST .../enable\|disable | partner:write |
| POST /api/partner/suppliers | partner:create_supplier |
| PUT /api/partner/suppliers/{id}、POST .../enable\|disable | partner:write |
| POST /api/warehouse/warehouses | warehouse:create_warehouse |
| PUT /api/warehouse/warehouses/{id}、POST .../enable\|disable | warehouse:write |
| POST /api/inventory/adjustments | inventory:adjust |
| POST /api/inventory/stock-counts、.../{docNo}/lines/count、.../approve、.../post、GET .../{docNo}、GET /api/inventory/stock-counts | inventory:count |
| POST /api/inventory/transfers、POST .../{docNo}/approve\|post、GET .../{docNo}、GET /api/inventory/transfers | inventory:transfer |
| POST /api/purchase/orders、.../{docNo}/approve\|close、GET .../{docNo}、GET /api/purchase/orders | purchase:order |
| POST /api/purchase/receipts、.../{docNo}/approve\|post、GET .../{docNo}、GET /api/purchase/receipts | purchase:receipt |
| POST /api/purchase/invoices、.../{docNo}/approve\|post、GET .../{docNo}、GET /api/purchase/invoices | purchase:invoice |
| GET /api/payables | 登录即可（只读台账，无权限点） |
| POST /api/sales/orders、.../{docNo}/approve\|cancel、GET .../{docNo}、GET /api/sales/orders | sales:order |
| POST /api/sales/deliveries、.../{docNo}/approve\|post\|cancel、GET .../{docNo}、GET /api/sales/deliveries | sales:delivery |
| POST /api/sales/invoices、.../{docNo}/approve\|post\|cancel、GET .../{docNo}、GET /api/sales/invoices、GET /api/receivables、GET /api/receivables/{id} | sales:invoice |
| POST /api/gaps/{id}/status | gap:triage |
| /api/identity/users/**（用户管理） | hasRole('ADMIN')（不走权限点） |
| 其余 GET 查询接口、聊天与会话接口 | 登录即可 |

> 设计取舍：单项创建权限点与 Agent 工具完全同名（同一动作聊天和界面同权）；
> 更新/启停等维护操作归各域一个 `*:write`（本期仅 ADMIN/BOSS、仓库域含 WAREHOUSE），
> 后续业务角色需要自助维护档案时再细分。
