# 权限矩阵（M2-T06）

> 状态：v1.0（2026-06，M2-T06 交付）
> 代码（单一真源，本文档与之同步维护）：
> `server/sjherp-domain/.../identity/Permission.java`（权限点定义）、
> `server/sjherp-domain/.../identity/RolePermissions.java`（角色→权限静态映射，EnumMap，不落库）
> 接线：工具层 `app/security/RolePermissionToolChecker`（实现 agent 的 `ToolPermissionChecker`，AgentInfraConfig 装配进 AgentLoop）；
> REST 层 `app/security/PermissionGuard`（bean 名 `perm`，`@PreAuthorize("@perm.has('...')")`）
> 关联：[领域工具清单.md](./领域工具清单.md)（工具的 requiredPermission 声明）

## 1. 设计约定

认证 API 的 `POST /api/auth/login` 与 `GET /api/auth/me` 均返回 `permissions` 字段。该字段由后端 `RolePermissions.permissionCodesOf(...)` 按当前角色实时求并集并排序；前端只消费权限码集合渲染菜单和执行体验层路由守卫，不复制角色矩阵。未知、缺失或过期缓存权限一律按无权限处理，后端 REST/Agent 校验仍是最终授权边界。

- **查询类操作无权限点**：登录即可（未登录统一 401）。
  - 例外：盘点（`inventory:count`）与调拨（`inventory:transfer`）的查询接口也要求对应权限点（控制器类级 `@PreAuthorize`）——因为盘点/调拨整体属于受控动作，非公开台账。
  - 例外（采购线 M3-T05/T06/T07）：采购订单（`purchase:order`）、采购入库单（`purchase:receipt`）、采购发票（`purchase:invoice`）的查询接口同样要求对应权限点（控制器类级 `@PreAuthorize`，受控动作）；唯独 GET /api/payables 应付列表查询登录即可（只读台账，无权限点）。
  - 例外（销售线 M3-T08/T09/T10）：销售订单（`sales:order`）、销售出库（`sales:delivery`）、销售发票与应收（`sales:invoice`）的查询接口同样要求对应权限点（受控动作，非公开台账；含 GET /api/receivables/**）。
  - 进销存报表（M3-T12，只读）：库存余额表 / 收发存汇总（`/api/reports/inventory-balance`、`/api/reports/stock-movement-summary`）登录即可（与库存查询 `/api/inventory/*` 一致）；采购入库明细沿用 `purchase:order`、销售出库明细沿用 `sales:order`，零新增权限点。
    > 已知取舍：销售明细的毛利/COGS 与库存余额表的库存总值是比单据更敏感的经营指标，当前随 `sales:order`/登录暴露；若后续出现"能录单但不该看利润/库存总值"的细分角色诉求，再引入独立报表读权限点（如 `report:profit`），现不过度设计。
  - 财务总账（M4-T01）：科目表/账期的**查询**登录即可（参考数据，照档案查询通则）；科目建/停启用须 `finance:account`、账期开启/关账须 `finance:period`、重开已关账期须 `finance:period_reopen`（高敏 CLOSED→OPEN）；凭证（建/过账/查询）与试算平衡/科目余额**全程受控**须 `finance:voucher`（含查询——凭证是敏感账务数据，类级 @PreAuthorize 全覆盖）。
  - 检查 Agent（M6-T05～T07）：即时预览、管理端显式运行、报告列表与详情仅 `ADMIN/BOSS`；`run_consistency_check` 和 `query_consistency_report` 工具均保持登录即可，后者只读召回历史报告并解释，不赋予报告管理 API 权限。个人通知列表、未读数和标记已读对所有已登录用户开放，但服务端按当前用户强制限定接收人，不能查看或更新他人通知；实际一致性异常和 P0 会话主动提醒只投递给启用中的 `ADMIN/BOSS`。
- **双层同一矩阵**：Agent 工具与 REST 写接口共用 `RolePermissions`，口径绝不分叉。
  - 工具层：AgentLoop 执行前按 `ToolContext.userId` 实时查库取角色 → 矩阵判定；
    权限不足时工具**不执行**，"权限不足"错误回灌给模型，由模型向用户礼貌说明（不中断对话）。
  - REST 层：`@PreAuthorize` 判定失败统一 403 `{"error":"无权限执行该操作"}`。
- **宁拒勿放**：未知权限点 code、用户不存在/停用、userId 非法、查库异常——一律拒绝。
- **用户管理不走权限点**：UserAdminController 整体 `hasRole('ADMIN')`（M2-T05 既有约定）。
- **角色映射代码内静态定义**（小企业从简）：不落库、不可运行时配置；改矩阵 = 改代码 + 本文档 + `RolePermissionsTest`。

角色口径（小企业从简）：

- **ADMIN**：全部权限点 + 用户管理（角色直接限定）。
- **BOSS**：全部业务权限点（不含用户管理、不含演示工具；含采购线 `purchase:*`、销售线 `sales:*` 与财务总账 `finance:*`，含高敏 `finance:period_reopen`）。
- **PURCHASER**：创建供应商 + 采购全程（`purchase:order`/`purchase:receipt`/`purchase:invoice`）；商品/档案查询登录即可。
- **SALES**：创建客户 + 销售全线（`sales:order`/`sales:delivery`/`sales:invoice`）。
- **WAREHOUSE**：仓库域全部（`warehouse:*`）+ 库存调整（`inventory:adjust`，M3-T01c）+ 库存盘点（`inventory:count`，M3-T03）+ 库存调拨（`inventory:transfer`，M3-T04）+ 采购收货（`purchase:receipt`，参与实物入库）+ 销售发货（`sales:delivery`，参与实物出库）。
- **ACCOUNTANT**：采购发票/应付（`purchase:invoice`）+ 销售发票/应收（`sales:invoice`，开票挂应收、查应收）；总账财务 `finance:account`/`finance:period`/`finance:voucher`（M4-T01 科目/账期/凭证，**不含** `finance:period_reopen` 重开高敏权限）；应收应付核销与账龄 `finance:settlement`（M4-T03，本批只读账龄/核销历史，核销写入口随 M4-T04 收付款单落地复用）；资金账户档案 `finance:payment_account`（M4-T04a）；月末结转关账 `finance:period`（M4-T05 复用）；会计报表 `finance:report`（M4-T06 资产负债表/利润表只读）；其余 `finance:*` 留后续任务补充。
