# 选项返回协议（AgentReply）

- 版本：**v0.1（定稿）**。本协议是前后端核心契约，保持版本化；任何字段变更必须升版本并同步修订三处实现：本文档、`server/sjherp-agent/.../reply/`、`web/src/types/agent.ts`。
- 关联：CLAUDE.md「选项返回协议」「Human-in-the-loop」

## AgentReply 结构

Agent 的每条回复都是一个结构化 JSON 消息：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `version` | string | 是 | 协议版本，当前 `"0.1"`。每条回复必带 |
| `text` | string | 是 | markdown 文本，前端渲染为消息正文 |
| `options` | array | 否 | 选项数组，前端渲染为可点击卡片，结构见下 |
| `form` | object | 否 | 需要用户补充结构化输入时返回，结构见下 |
| `requiresConfirmation` | boolean | 否 | **Human-in-the-loop 标记（回复级）**，默认 `false`。涉及资金、过账、期间关账等高风险操作必须为 `true`：Agent 只准备动作，由人点击确认后才执行 |

约定：`options` 与 `form` 可同时缺省（纯文本回复）；`requiresConfirmation=true` 时 `options` 必须非空，且必须含明确的"确认执行"（`risk="high"`）与"取消"两项。

### Option（选项卡片）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 选项唯一标识（一条回复内不重复），**点击后回传给后端的就是它** |
| `label` | string | 是 | 卡片标题（短，中文） |
| `description` | string | 否 | 卡片副文案（如供应商报价、交期、风险提示） |
| `risk` | string | 否 | **选项级风险标记**：`"normal"`（默认）/ `"high"`。`high` 表示该选项触发高风险动作，前端用醒目（danger）样式渲染 |
| `action` | object | 否 | 后端声明的"点中该选项后要执行的动作"：`{ "type": "...", "params": {...} }`。缺省表示该选项只是语义化回答（继续对话，不触发动作） |

### Form（表单）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `form.id` | string | 是 | 表单唯一标识，提交时随表单值一并回传，便于 Agent 关联上下文 |
| `form.title` | string | 否 | 表单标题（中文） |
| `form.submitLabel` | string | 否 | 提交按钮文案，缺省时前端显示「提交」 |
| `form.fields[]` | array | 是 | 字段定义，结构见下 |
| `form.submitAction` | object | 是 | 表单提交后的动作，结构同 `options[].action` |

### FormField（表单字段）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | 字段名（英文标识符，回传键名） |
| `label` | string | 是 | 展示标签（中文） |
| `type` | string | 是 | 字段类型枚举，见下文「字段类型与映射规则」 |
| `required` | boolean | 否 | 是否必填，默认 `false` |
| `placeholder` | string | 否 | 输入提示文案 |
| `defaultValue` | string | 否 | 默认值，**一律字符串形式** |
| `options` | array | 否 | `type="select"` 时**必填**：候选项 `[{ "value": "...", "label": "..." }]` |

## 回传机制（前端 → 后端）

1. **点击选项**：前端只回传选项 id —— `{ "optionId": "<id>" }`，不回传 label/action。后端必须能凭会话中最近一条 Agent 回复的 `options` 按 id 还原该选项的语义与 `action`（防止前端伪造动作参数）。用户消息气泡显示该选项的 `label`。
2. **提交表单**：前端回传 `{ "formId": "<form.id>", "values": { "<name>": "<字符串值>", ... } }`。**所有值均为字符串**；金额/数量等精度敏感值由后端以 `BigDecimal` 解析，禁止 float/double（CLAUDE.md 原则 5）。
3. `action.params` 中的金额/数量同样以字符串传输。

## Human-in-the-loop：两级标记的职责划分

- **回复级 `requiresConfirmation`**：声明"这条回复整体是一次高风险确认请求"。为 `true` 时后端只准备动作不执行，且 `options` 必含「确认执行」与「取消」两项；用户点击确认选项后后端才执行对应 `action`。
- **选项级 `risk`**：声明"单个选项是高风险动作"，仅决定前端渲染样式（`high` → 醒目警示样式）。约束：`risk="high"` 的选项只允许出现在 `requiresConfirmation=true` 的回复中，且确认回复中的「确认执行」选项必须为 `risk="high"`。

## 框架级工具确认选项（固定 id 约定，M1-T03 新增）

Agent 执行循环在框架层拦截高风险工具（`riskLevel=HIGH`）后，后端会生成一条
`requiresConfirmation=true` 的确认回复，其中「确认执行」「取消」两个选项使用**固定 id**：

| 固定 id | 选项 | risk | 语义 |
|---|---|---|---|
| `__tool_confirm__` | 确认执行 | `high` | 后端凭此 id 恢复被拦截的高风险工具调用（`AgentLoop.resume(confirmed=true)`） |
| `__tool_cancel__` | 取消 | （省略） | 后端清除待确认现场，工具不执行，告知模型由其向用户致意 |

约定：

1. **双下划线前后缀为框架保留命名空间**：业务/模型生成的选项 id 不得使用 `__...__` 形式（后端常量与判定见 `sjherp-agent` 的 `ToolConfirmation`）；
2. 前端无需特殊处理：这两个选项走正常的 `{ "optionId": "<id>" }` 回传机制，确认项因 `risk="high"` 自然渲染为醒目警示样式；
3. 待确认状态持久化在会话上（`agent_session.pending_tool_call` 列），杀进程/重启后点击确认仍可恢复执行；
4. 存在待确认调用期间，用户发来的**任何非确认输入**（点取消、改发自由文本、提交表单）一律按取消语义处理（工具不执行）；
5. 本节是行为约定而非协议字段变更，协议版本保持 v0.1。执行循环与拦截机制详见 [Agent执行循环.md](./Agent执行循环.md)。

## 字段类型与映射规则

协议层（JSON）字段类型一律**小写**：

| JSON 值 | 含义 | 后端枚举 `FieldType` | 前端控件 |
|---|---|---|---|
| `text` | 单行文本 | `TEXT` | text input |
| `decimal` | 金额/数量等精确小数。**字符串传输，后端 BigDecimal 解析** | `DECIMAL` | number input（step=any） |
| `integer` | 整数 | `INTEGER` | number input（step=1） |
| `date` | 日期（`yyyy-MM-dd`） | `DATE` | date picker |
| `select` | 下拉单选（须带 `options`） | `SELECT` | select |

映射规则：**JSON 值 = 后端枚举名的小写**（`Option.risk` 同理：JSON `"normal"/"high"` ↔ 后端 `RiskLevel.NORMAL/HIGH`）。后端序列化时输出小写、反序列化时大小写不敏感。协议中**不存在** `number` 类型——金额/数量必须用 `decimal`，避免前端浮点参与运算。

## 示例 1：采购下单时返回供应商选项（含确认标记）

```json
{
  "version": "0.1",
  "text": "物料 **M-0042 不锈钢板 2mm** 需补货 500kg，找到 2 家合格供应商，请选择：",
  "requiresConfirmation": true,
  "options": [
    { "id": "opt-sup-a", "label": "供应商A（华东金属）", "risk": "high",
      "description": "单价 ¥18.50/kg，交期 3 天，近 90 天准交率 98%",
      "action": { "type": "CREATE_PURCHASE_ORDER", "params": { "supplierId": "SUP-001", "materialId": "M-0042", "qty": "500" } } },
    { "id": "opt-sup-b", "label": "供应商B（南方钢业）", "risk": "high",
      "description": "单价 ¥17.90/kg，交期 7 天，近 90 天准交率 91%",
      "action": { "type": "CREATE_PURCHASE_ORDER", "params": { "supplierId": "SUP-002", "materialId": "M-0042", "qty": "500" } } },
    { "id": "opt-cancel", "label": "暂不下单" }
  ]
}
```

用户点击供应商A 后，前端回传：`{ "optionId": "opt-sup-a" }`。

> 注：点击供应商卡片后仅生成**草稿**采购订单，过账仍需走单据状态机审核。金额/数量在协议中用字符串传输，后端以 BigDecimal 解析。

## 示例 2：信息不足时返回表单

```json
{
  "version": "0.1",
  "text": "好的，为 **M-0042** 创建采购订单前，请补充以下信息：",
  "form": {
    "id": "form-po-m0042",
    "title": "采购订单",
    "submitLabel": "创建草稿",
    "fields": [
      { "name": "qty", "label": "采购数量(kg)", "type": "decimal", "required": true, "defaultValue": "500" },
      { "name": "expectedDate", "label": "期望到货日期", "type": "date", "required": true },
      { "name": "warehouseId", "label": "收货仓库", "type": "select", "required": true,
        "options": [ { "value": "WH-01", "label": "原料一仓" }, { "value": "WH-02", "label": "原料二仓" } ] }
    ],
    "submitAction": { "type": "PREPARE_PURCHASE_ORDER", "params": { "materialId": "M-0042" } }
  }
}
```

用户提交后，前端回传：`{ "formId": "form-po-m0042", "values": { "qty": "500", "expectedDate": "2026-06-15", "warehouseId": "WH-01" } }`。
