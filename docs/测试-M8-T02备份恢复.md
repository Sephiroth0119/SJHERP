# M8-T02 备份与恢复测试与验收记录

## 当前状态

T02 已完成实现（2026-10-21），分支 `cursor/m8-t02-backup-restore-ea78`。在 M8-T01 生产 compose 上增加 MySQL 定时备份、Qdrant 全库快照、恢复脚本与可重复演练。**未改 `web-dist/`**，未改业务领域逻辑 / Flyway。

## 验收范围

- `./deploy/backup.sh`：对运行中的 mysql 做 `--single-transaction` dump（gzip），对 qdrant `POST /snapshots` 后归档到宿主机；保留天数 `SJHERP_BACKUP_KEEP_DAYS`（默认 14）。
- 落盘：`deploy/backups/mysql/`、`deploy/backups/qdrant/`；compose 把 `./backups/qdrant/live` bind 到 `/qdrant/snapshots`。
- 定时：宿主机 cron（`deploy/crontab.example`），不在容器内再引入调度镜像。
- `./deploy/restore.sh`：停 nginx/app，灌 SQL 进**现有** mysql volume；可选 `--storage-snapshot` 恢复 qdrant。拒绝 `down -v` 当恢复。
- `./deploy/restore-smoke.sh`：备份 → 金丝雀表 → 恢复 → 表消失 + flyway/sys_user 行数一致 + `smoke.sh --login`。
- 文档：`docs/部署-备份恢复.md`，一键安装文档与路线图已链接。

## 自动化覆盖

- `./deploy/install.sh --check`：连同 backup/restore/restore-smoke 的 `bash -n` 与 `--check`
- CI job「部署资产」：dry-run → `install.sh --skip-docker-install` → `restore-smoke.sh`
- CI 末尾 `down -v` 仅回收 GitHub runner 临时磁盘，注释写明不是生产恢复路径
